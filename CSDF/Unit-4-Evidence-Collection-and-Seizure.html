4.8 Computer evidence processing steps

Q1What are general computer evidence processing steps? Explain in detail. / Enlist and explain different computer evidence processing steps.

9 marks★★★★★ 5×

Asked in: 2022 May Q4(b) [9] · 2022 Nov Q4(b) [9] · 2023 May Q3(b) [9] · 2024 May Q3(b) [9, essential steps from the crime scene] · 2025 Nov Q3(b) [9]

In simple words: Processing evidence is a fixed routine, not a single clever click.
First protect and copy the machine, then search the copy, then write down everything you did.
The book lists sixteen steps; they group into five easy phases.

Why we do this

A computer changes every time it is used. The routine freezes the scene, keeps the original safe, and produces a record that another expert can repeat and a court can trust.

Words you need first

  • Processing — the full set of steps from seizing a computer to reporting the findings.
  • Bit-stream backup — an exact copy of every sector on a disk, including deleted and empty areas.
  • Mathematical verification — using a hash to prove the copy matches the original.
  • Hash — a fingerprint of data; a single changed bit gives a completely different value.
  • Swap file — disk space used as extra memory; it can hold fragments of documents and passwords.
  • File slack — the unused tail of a file's last storage block, which can contain older data.
  • Unallocated space — disk space not assigned to any live file; deleted data often survives there.
  • Keyword list — the names, e-mail addresses and terms the examiner will search for.
  • Timestamp — the date and time recorded for a file event.
  • Volatile data — data that disappears when the power goes off, such as RAM contents.

Step-by-step

  1. Preserve. Capture volatile data if needed, shut down correctly, transport safely, and make a verified bit-stream copy. Why: the original must not change.
  2. Document the scene. Photograph the hardware, label the cables, note the system clock, and record file names and dates. Why: a later reader must be able to rebuild the setup.
  3. Search. Build a keyword list, then search files, the swap file, slack and unallocated space. Why: evidence hides outside normal files.
  4. Examine. Study irregular, binary, compressed and encrypted files, and test how the software behaves. Why: a text search cannot explain every file.
  5. Report. Record every tool, version and step, and keep copies of the software used. Why: another expert must be able to repeat the work.
Real-life analogy: Processing a computer is like processing a physical crime scene. Photograph everything, bag each item, copy what cannot be kept, test the copy in the lab, and write a report that another officer could follow.
Common confusion: Step 1 says “turn the computer off”, which sounds like the first thing to do. In modern practice you capture RAM and network state first, because they vanish on shutdown. Write both ideas: volatile data first, then the traditional shutdown step.

1. The sixteen steps (book §4.13.2)

  1. Turn the computer off — disconnect or shut down the network computer using the correct procedure; shut down as soon as feasible when time is of the essence.
  2. Describe the system's hardware setup in writing — photograph it from all sides, document the components and their connections, and label each wire so it can be reconnected.
  3. Transport the computer to a secure location — unattended confiscated computers are vulnerable; lock it up and never leave it alone.
  4. Create hard-disk and floppy-disk bit-stream backups — all processing is done on a recovered copy, not the original; the bit-stream backup is an insurance cover.
  5. Mathematically verify all storage devices' data — demonstrate that you did not change any evidence; law enforcement has used 32-bit mathematical authentication since 1989.
  6. Record the system's time and date — a wrong clock (e.g. daylight-saving error) changes file timestamps; document the setting to account for discrepancies.
  7. Create a list of key search words — gather keywords from people who know the case; automated software can then search the drives.
  8. Examine the Windows swap file — it may contain useful information and leads; it is deleted on shutdown but easy to record and assess.
  9. Determine the file slack — raw memory dumps that occur when files are closed; a key security-leakage source. Keywords should be searched here too.
  10. Examine unallocated space (erased files) — search for pertinent keywords that were not found earlier.
  11. Search files, file slack and unallocated space for keywords — search all relevant drives and diskettes with the keyword list; review and record the results.
  12. Document file names, dates and times — these may be crucial evidence; record them in a word-processing file.
  13. Detect irregularities in files, programs and storage — data may be binary, graphic, compressed or encrypted, so a text search cannot find it; manual assessment is necessary.
  14. Examine the operation of the software — execute applications to determine their function and demonstrate wilfulness when harmful processes are linked to evidence.
  15. Document your findings — record every piece of software used, its version number, the procedure followed and screenshots of the operating system.
  16. Retain copies of the software used — provide a copy with the report; if the software was upgraded and the old version was not kept, duplicating findings may be impossible.

What this means: every step protects one of two things — the evidence, or the record of what was done. Lose either one and the strongest finding can be challenged.

2. Compressed version for 9 marks

If you cannot write all sixteen, group them into five phases — this still earns most of the marks:

Write both: “Capture volatile data first where it is relevant; then shut down as step 1 of the traditional procedure.” That single sentence shows you understand the order of volatility.

4.6 Methods of collection & collection steps

Q1What are various methods of collecting digital evidence? Enlist the various digital collection steps. / What are the typical steps involved in the collection of digital evidences?

8–9 marks★★★★ 4×

Asked in: 2023 May Q4(b) [9] · 2023 Nov Q3(b) [8] · 2024 May Q4(b) [9] · 2025 Nov Q4(a) [9, any four steps]

In simple words: There are two main ways to collect digital evidence: bait the attacker and watch, or freeze the scene and copy it.
In practice you also choose live, dead, remote, logical, physical or mobile collection.
The six collection steps then keep the copy accurate and documented.

Why we do this

You cannot collect everything at once. The method decides what you save, what you lose, and whether the evidence is strong enough for court.

Words you need first

  • Honeypotting — setting up a decoy system to attract an attacker and record what they do.
  • Freezing the scene — capturing a snapshot of the system at the moment of the attack, then copying the key data.
  • Live acquisition — collecting data while the computer is still running, such as RAM and network connections.
  • Dead acquisition — collecting a disk image after the computer has been shut down.
  • Remote acquisition — copying data over a network from another location.
  • Logical acquisition — copying selected files or folders rather than the whole disk.
  • Physical acquisition — copying every sector, including deleted data, slack and unallocated space.
  • Artifact — a trace left by an attacker, such as a log entry, file or running process.
  • Rootkit — malware that hides itself and other files from the operating system.
  • Cryptographic message digest — a hash used to prove a copy has not changed.
  • Order of volatility — the rule that the fastest-changing data is collected first.

Step-by-step

  1. Find the evidence. Why: a checklist stops you missing a device or a data source.
  2. Decide what is relevant. Why: copying everything can bury the useful facts and waste time.
  3. Choose the method. Why: live, dead, remote or logical collection each save different data.
  4. Establish the order of volatility. Why: RAM disappears in seconds; a disk survives for years.
  5. Remove outside change. Why: a write blocker or isolated network stops evidence being altered.
  6. Gather and verify. Why: a hash proves the copy matches what was collected.
  7. Document everything. Why: the method itself may be challenged in court.
Real-life analogy: Honeypotting is a bait car: police leave it parked and watch what a thief does. Freezing the scene is a security camera snapshot: it captures the room exactly as it was at the moment of the crime.
Common confusion: Honeypotting is not “hacking back”. The investigator watches and records activity on their own decoy system. Attacking the intruder's machine would be a separate, usually illegal, act.

1. Two fundamental methods (book §4.9)

(a) Honeypotting. The investigator inserts deceptive information and observes the attacker's response. It is an effective way of finding out the attacker's motivation. A replica system is set up to entice the attacker into more monitoring. The attacker's actions are recorded, and the evidence shows intent and method.

(b) Freezing the scene. The investigator captures a picture of the system at the moment it is hacked. Crucial data is then copied onto removable non-volatile media in a predetermined manner. A cryptographic message digest is generated for each piece of data, and the digests are cross-checked against the originals to ensure accuracy.

2. Other collection methods in practice

MethodWhat is collectedTool / example

3. Artifacts (book §4.10)

  • Whether they are code snippets, malicious software, active processes or sniffer log files, the attacker nearly always leaves something behind. These traces are called artifacts.
  • Never try to study a piece of evidence on a hacked machine — the attacker may have left a trap or a rootkit that hides or alters what you see.
  • The examiner must ensure that the impact of artifacts is within our control, because they are unpredictable.

What this means: an artifact is only useful if you can explain where it came from. Never study it on the hacked machine, because the attacker may have hidden or changed it.

4. The six collection steps (book §4.11)

  1. Find the evidence — use a checklist. It helps in gathering evidence and confirms that all the information you want is present.
  2. Find the relevant data — after locating the evidence, decide what information is pertinent to the case.
  3. Establish an order of volatility — reduces the loss of uncorrupted evidence and is a useful guide.
  4. Eliminate external sources of change — refrain from making changes to the original data.
  5. Gather evidence — use the right resources for the task.
  6. Document everything — the validity of the collection method may be questioned later. Digital signatures, timestamps and signed statements are all significant.

5. “Explain any four steps” (2025 Nov)

Write steps 1, 3, 4 and 6 with two lines each: checklist and relevance; volatility order (RAM first, disk last); no changes to the original; documentation with hash, time, signature and photographs.

Memory hook — F-F-E-E-G-D: Find evidence, Find relevant data, Establish volatility order, Eliminate external change, Gather, Document. Six steps, six marks plus examples.

4.7 Controlling contamination — the chain of custody

Q1What is chain of custody? Explain the process of chain of custody. / How can we control the contamination of digital evidence?

9 marks★★★★ 4×

Asked in: 2022 May Q3(b) [9] · 2022 Nov Q3(b) [9] · 2023 May Q4(a) [9, with contamination] · 2025 Nov Q4(b) [9, with contamination methods]

In simple words: Chain of custody is the signed story of who had the evidence, when, and what they did with it.
It starts at seizure and ends in court.
If the story has a gap, the other side can say the evidence was changed.

Why we do this

Digital evidence is easy to copy and easy to alter. The chain is how you prove that the file in court is the same file that was taken from the suspect's computer.

Words you need first

  • Chain of custody — the written record of every transfer, access and storage location of evidence.
  • Contamination — any outside influence that changes or adds to the evidence.
  • Custody — who currently controls and protects the evidence.
  • Tamper-evident — packaging that shows clearly if someone opened it.
  • Exhibit number — the unique label given to each item in a case.
  • Evidence custodian — the named person responsible for the evidence store.
  • Faraday bag — a signal-blocking bag that stops a phone from connecting to a network.
  • Hash — a fingerprint used to prove the data has not changed.
  • Write blocker — a tool that allows reading but blocks writing to a disk.
  • Working clone — a verified copy used for analysis while the original stays sealed.

Step-by-step

  1. Save the original files. Why: the first copy is the reference for everything later.
  2. Photograph the physical evidence. Why: a picture proves the item's condition at seizure.
  3. Take screenshots of the digital evidence. Why: the screen may show live data that disappears on shutdown.
  4. Record the date, time and receiver. Why: the chain needs an exact starting point.
  5. Clone the data bit for bit. Why: analysis must happen on a copy, not the original.
  6. Hash the clone. Why: a matching hash proves the working copy is authentic.
  7. Log every later transfer and access. Why: one unrecorded handover is enough to raise doubt.
Real-life analogy: Chain of custody is a relay baton that must never be dropped. Each runner signs for the baton, runs their leg, and hands it on. If the baton appears with no signature at one stage, nobody can prove it was not swapped.
Common confusion: The chain is not just a form at the front of the file. It is a process plus a record. You must actually control access and storage, then write down what you did. A perfect form with a broken process is worthless.

1. Definition

Chain of custody is the documentation that identifies all changes in the control, handling, custody and ownership of a piece of evidence. It lets you trace the evidence from the instant it was collected to the instant it was presented in a judicial court.

2. Why it matters

  • Proves the evidence is the same item that was seized.
  • Proves it was not tampered with or contaminated.
  • Makes the evidence admissible; a break in the chain can make it unreliable and excluded.
  • Answers the defence's challenge: “How do we know this file came from that computer?”

3. The chain-of-custody process (book §4.12)

Data collection → Examination → Analysis → Reporting (media) (data) (information) (evidence)
  1. Data collection — identification, labelling, recording and acquisition of data from all relevant sources while maintaining integrity.
  2. Examination — document the chain-of-custody information and the forensic procedure followed; take screenshots throughout to show what was done and what was found.
  3. Analysis — use legally justifiable methods and techniques to gather information that answers the questions in the case.
  4. Reporting — include a statement of the chain of custody, the tools used, how the data sources were analysed, the issues identified, the vulnerabilities discovered and any further forensic measures suggested.

4. Procedure for establishing the chain (book §4.12)

  1. Save the original files.
  2. Photograph the physical evidence.
  3. Take screenshots of the digital evidence.
  4. Document date, time and any other information about receipt of the evidence.
  5. Inject forensic computers with a bit-for-bit clone of the digital evidence content.
  6. Authenticate the working clone by performing a hash test analysis.

What this means: the first four actions preserve what the evidence looked like; the last two create a safe copy. Together they turn a seized disk into something a court can examine without touching the original.

5. What the record must contain

  • Exhibit number, description and serial number.
  • Date and time of seizure; place; name of the person who seized it.
  • Every transfer: from whom, to whom, date, time, purpose, signature.
  • Every access: who opened the evidence, when, and what was done.
  • Storage location and security (safe, evidence room, locked cabinet).

6. Controlling contamination

  1. Limit access — only authorised persons enter the scene; keep an access log.
  2. Use tamper-evident packaging — anti-static bags and seals with the officer's signature.
  3. Wear gloves and avoid touching the disk surface or the gold contacts.
  4. Use a write blocker — never boot the suspect disk in a normal PC.
  5. Image first, analyse later — all work on a verified copy.
  6. Hash before and after — MD5/SHA-1 at seizure, at imaging and before analysis.
  7. Faraday bag for phones — stops remote wipe and network traffic.
  8. Keep evidence away from heat, magnets, moisture and static.
  9. Document every action — if it is not written down, it did not happen.
  10. Store in an evidence safe accessible only to the evidence custodian.

What this means: every control blocks one route for contamination — people, packaging, power, network, heat or paperwork. Name the route, then name the control, and the list becomes easy to remember.

For 2023 May / 2025 Nov: the question joins chain of custody with contamination. Answer in two parts: definition + process (5 marks), then the ten contamination controls (4 marks). Explicitly say “chain of custody is both a document and a process”.

4.1 Why collect evidence?

Q1What are evidences? What are the simple reasons to collect evidences? What are different options for collecting evidences?

8 marks★★ 2×

Asked in: 2022 May Q3(a) [8] · 2022 Nov Q3(a) [8]

In simple words: Evidence is information that helps prove something relevant to the case.
We collect it to stop the attacker repeating the act, to fix responsibility, and to support legal or disciplinary action.
At the scene you have two main choices: pull the system offline, or leave it online and watch.

Why we do this

Without evidence, a company cannot prove a crime, defend a dismissal, or claim insurance. Without a plan, the act of collecting can destroy the very data that matters.

Words you need first

  • Evidence — information that proves or helps prove something relevant to a case.
  • Relevant — connected to the incident being investigated.
  • Authentic — shown to be what it claims to be, not a fake.
  • Lawfully obtained — collected with the correct authority, such as a warrant or a company policy.
  • Isolate — disconnect a system from the network without necessarily switching it off.
  • Image — an exact copy of a disk for analysis.
  • Volatile data — data that disappears when power is lost.
  • Dead man switch — a hidden program that wipes evidence when it loses a connection or is disturbed.
  • Intruder — the person or program that has broken into the system.

Step-by-step

  1. Confirm there is an incident. Why: a system fault or user mistake is not an attack.
  2. Decide what matters more: preservation or observation. Why: you usually cannot do both perfectly.
  3. If the attacker has gone, isolate and image. Why: this stops further change and secures a stable copy.
  4. If the attacker is active, monitor first. Why: you can learn the method and identify the person.
  5. Capture volatile data before shutdown. Why: RAM and network state vanish forever when power is cut.
  6. Record the choice and the reason. Why: the defence will ask why you acted as you did.
Real-life analogy: A fire alarm goes off in a shop. You can cut the power and save the building, or leave the lights on and watch the arsonist on camera. Each choice saves something and risks something else.
Common confusion: “Collect more evidence” is not always better. Evidence must be relevant and lawfully obtained. A huge pile of unrelated personal files can create a privacy problem without proving anything.

1. What is evidence?

Evidence is any information of supporting value — information that proves something or helps to prove something relevant to the case. In digital forensics it can be a file, an e-mail, a log entry, a screenshot, a disk image or a network packet.

Evidence must be relevant to the incident, authentic (shown to be what it claims), and obtained lawfully.

2. Simple reasons to collect evidence (book §4.1)

  1. Prevention in the future — you have little chance of stopping someone from repeating the act unless you know what happened.
  2. Responsibility — the attacker is to blame for the damage, and the only way to bring him to justice is to have sufficient proof to substantiate his acts.
  3. Social obligation of the victim — information obtained after a hack can be evaluated and used to avoid future attacks.
  4. To support disciplinary or legal action — proof is needed for dismissal, a civil suit or a criminal prosecution.
  5. To reconstruct the incident — evidence shows how the attacker entered and what was done.
  6. To recover losses — insurance claims and asset recovery need documented proof.

3. Options for collecting evidence (book §4.2)

When a compromise is discovered, there are two choices:

OptionHow it worksAdvantageRisk
Remove the system from the network and begin gathering evidenceIsolate the machine, image the disk, then analyse.The attacker can no longer change or delete data; a stable image is obtained.You may not have enough proof; the attacker may have planted a “dead man switch” that wipes evidence when the machine goes offline.
Leave it online and try to track the intruderMonitor the live system and network, record the attacker's actions.You can identify the attacker and the method in real time.You may inadvertently alert the intruder, who then cleans his tracks and deletes evidence.

What this means: the two options are a trade-off, not a right answer. Pulling the plug protects the disk but loses live data; staying online keeps the live data but gives the attacker time to erase it.

A third practical option — often used in business — is to capture volatile data first, then isolate and image. That is “live acquisition then shutdown”, covered in Unit 5.

8-mark answer: definition (2) + five reasons (3) + two options in a small table (3). The two-option table is exactly what the book gives, so use it.

Q2What is the primary purpose of collecting evidence in digital forensics? Explain in detail.

9 marks★ 1×

Asked in: 2023 Nov Q3(a) [9]

In simple words: The main purpose is to turn digital data into proof a court or employer can rely on.
That means proving an incident happened, showing what was done, and linking it to a person.
Good evidence can also clear an innocent suspect.

Why we do this

Data by itself is not evidence. It becomes evidence only when someone can show it is relevant, genuine and lawfully collected. That is the whole purpose of the process.

Words you need first

  • Primary purpose — the main reason the activity is done.
  • Admissible — allowed to be used in court.
  • Relevant — connected to the incident.
  • Authentic — proven to be what it claims to be.
  • Perpetrator — the person who carried out the act.
  • Chain of custody — the signed record of who handled the evidence.
  • Volatile data — data that disappears when power is lost.
  • Timeline — a dated sequence of events.
  • Cross-examination — the other side's questioning of a witness in court.

Step-by-step

  1. Prove an incident occurred. Why: an attack must be separated from a fault or a mistake.
  2. Establish the facts. Why: the court needs to know what was accessed, changed, copied or deleted.
  3. Identify the person. Why: an account, device or IP address must be linked to human action.
  4. Preserve the truth. Why: volatile data vanishes and originals can be altered.
  5. Build a timeline. Why: the order of events shows how the attack worked.
  6. Present it so it survives challenge. Why: evidence that cannot be defended under cross-examination proves nothing.
Real-life analogy: Evidence is a bridge between the incident and the courtroom. Each plank is a fact: what happened, when, how, and who. If one plank is missing or rotten, the bridge collapses under cross-examination.
Common confusion: The purpose is not “to prove the suspect guilty”. It is to establish the facts. The same evidence may exclude a suspect, which is just as important as convicting the guilty.

The primary purpose is to obtain proof that is relevant, authentic and legally admissible, so that the incident can be explained and the responsible person can be identified and held accountable.

  1. Prove that an incident occurred — distinguish a real attack from a system fault or user error.
  2. Establish the facts — what was accessed, changed, copied or deleted, and when.
  3. Identify the perpetrator — link an account, device, IP address or physical location to the act.
  4. Preserve the truth — capture volatile data before it disappears and keep the original unchanged.
  5. Support legal or disciplinary proceedings — provide evidence that survives cross-examination.
  6. Enable reconstruction — build a timeline and show the attack path.
  7. Prevent future incidents — use the findings to close the weakness.
  8. Protect the innocent — evidence can also exclude a suspect or disprove an allegation.

What this means: the first three points prove the act and the actor. The next three protect the proof. The last two use the result to prevent harm and to be fair.

One-line definition to open with: “The primary purpose is to convert digital data into admissible evidence — proof that a court or employer can rely on.”

4.5 General procedure for evidence collection

Q1What is the general procedure for evidence collection?

8 marks★★ 2×

Asked in: 2022 May Q4(a) [8] · 2022 Nov Q4(a) [8]

In simple words: The general procedure has four stages: identify the evidence, preserve it, analyse it, and present it.
Each stage answers one question: what is evidence, how do we keep it safe, what does it mean, and how do we explain it?
The copy is always made before the analysis.

Why we do this

A single missed stage breaks the case. If you analyse before preserving, you may destroy the evidence. If you never present it clearly, the court cannot use it.

Words you need first

  • Identification — deciding which devices, files and logs are evidence.
  • Preservation — keeping evidence unchanged and protected.
  • Analysis — studying the data to work out what it proves.
  • Presentation — explaining the findings in a report or in court.
  • Bit-stream image — an exact copy of every sector on a disk.
  • Hash — a fingerprint used to prove a copy matches the original.
  • Write blocker — a tool that allows reading but blocks writing to a disk.
  • Anti-static bag — packaging that protects electronics from static damage.
  • Faraday bag — a signal-blocking bag used for phones and wireless devices.

Step-by-step

  1. Identify. Why: you cannot preserve what you have not recognised as evidence.
  2. Preserve. Why: the original must stay unchanged from seizure to court.
  3. Analyse. Why: the examiner must find and interpret the relevant data.
  4. Present. Why: the judge, jury or employer must be able to follow the conclusion.
Real-life analogy: A museum receives a fragile old manuscript. Staff first identify it, then place it in a climate-controlled case, then study it under glass, and finally write a label for visitors. The order protects the object at every stage.
Common confusion: Preservation is not analysis. Preservation keeps the evidence safe; analysis studies a copy. If you start “looking around” on the original, you have skipped preservation.

Q2Describe the general procedure for collecting and archiving digital evidence in computer forensics.

9 marks★ 1×

Asked in: 2025 May Q4(a) [9]

In simple words: Collecting gets the evidence out of the scene safely; archiving keeps it safe until the trial.
Collecting means photograph, copy and verify. Archiving means log it, lock it up, control access and keep it long enough.
The original stays sealed; the working copy is analysed.

Why we do this

A case can take months or years to reach court. Without controlled storage and a record of access, the evidence may change, disappear, or be impossible to defend.

Words you need first

  • Collection — finding and taking the digital evidence into custody.
  • Archiving — storing evidence in a controlled, logged place for long-term safekeeping.
  • Evidence safe — a locked room or cupboard accessible only to named custodians.
  • Access log — a record of who entered the store, when, and why.
  • Retention — how long evidence must be kept before it can be destroyed.
  • Tamper-evident bag — packaging that shows if it has been opened.
  • CD-R / DVD-R — write-once optical media used for a permanent copy.
  • SSD — solid-state drive, a fast storage device with no moving parts.
  • LTO — Linear Tape-Open, a high-capacity tape format used for long-term archives.
  • Faraday bag — a signal-blocking bag that stops a phone being wiped remotely.

Step-by-step

  1. Identify and document the devices. Why: the record must show exactly what was taken.
  2. Capture volatile data. Why: RAM and network state disappear on shutdown.
  3. Isolate the system. Why: it stops remote changes during collection.
  4. Image and hash. Why: the copy must be proven identical to the original.
  5. Label and seal the original. Why: the seal shows whether anyone opened it.
  6. Store it in the evidence safe. Why: controlled access prevents contamination and theft.
  7. Log every access. Why: the chain of custody needs a complete history.
  8. Keep it until the appeal period ends. Why: early destruction can be treated as obstruction.
Real-life analogy: A library's rare-book room has a locked door, a sign-in sheet and a climate-controlled shelf. You can study a copy, but the original never leaves the room. Evidence archiving follows the same rules.
Common confusion: Archiving is not just “putting it in a drawer”. It means controlled access, a log, a stable environment and a retention date. A drawer with no log is not an archive.

1. Collection

  1. Identify the devices and data that may contain evidence.
  2. Document the scene: photographs, serial numbers, cable positions, screen contents.
  3. Capture volatile data before shutdown.
  4. Isolate the system from the network so it cannot be changed remotely.
  5. Image the storage with a write blocker; compute MD5/SHA-1 for source and image.
  6. Label and seal the original in a tamper-evident bag with an exhibit number.

2. Archiving (book §4.8)

Archiving means keeping the collected evidence in a controlled store so that it remains unchanged and available for the trial.

  • Logs and logging — run a system logging function; safeguard and regularly back up the logs. The harm caused by an attacker can be seen in messages and program logs.
  • Monitoring — compile data, watch for anomalies and determine where and how an attacker is coming from. Unusual activity or the sudden arrival of unidentified users is a clear signal that something needs examination.
  • Disclaimer — when users log in, a disclaimer should state that monitoring takes place.
  • Evidence safe — store the original in a safe room or cupboard accessible only to the appointed evidence custodian.
  • Access log — record every entry and exit; evidence should never be left in an unattended location.
  • Retention — keep the evidence until the case is finally closed and the appeal period has expired.
  • Two copies — keep the original and a verified working copy; store them in separate places where possible.

4.10 Computer image verification & authentication

Q1What methods & techniques are commonly used to verify & authenticate computer images? Explain any two in detail.

9 marks★★ 2×

Asked in: 2023 Nov Q4(b) [9] · 2025 May Q3(b) [9]

In simple words: A computer image is a copy of a disk. Verification checks that the copy is exact; authentication checks that it came from the right place.
The main tool is a hash, which works like a fingerprint for a file.
If the original and the copy have the same hash, the copy is accepted.

Why we do this

The defence has the right to ask, “Is this really the data from that computer?” A verified image answers that question without letting anyone touch the original.

Words you need first

  • Image — an exact copy of every sector on a disk.
  • Verification — checking that the copy matches the original.
  • Authentication — proving the evidence is genuine and came from the stated source.
  • Hash — a short fingerprint produced from data by a mathematical function.
  • Avalanche effect — a tiny change in the input produces a completely different hash.
  • Known-good hash set — a list of fingerprints of safe, standard files.
  • Known-bad hash set — a list of fingerprints of malware or contraband.
  • Re-imaging — making a second image, often with a different tool, to compare results.
  • Digital signature — a cryptographic stamp that proves who signed the data and that it has not changed.
  • Certificate authority (CA) — a trusted body that confirms a public key belongs to a person or organisation.
  • Hex editor — a tool that shows the raw bytes of a file.

Step-by-step

  1. Hash the original at seizure. Why: this is the reference value before anything is copied.
  2. Image the disk through a write blocker. Why: the copy must be made without changing the source.
  3. Hash the image. Why: the two values must be compared.
  4. Compare the hashes. Why: equal values prove the copy is bit-for-bit identical.
  5. Record the algorithm and value. Why: the court needs to know exactly what was checked.
  6. Re-verify before analysis and at every transfer. Why: this catches any later change.
Real-life analogy: A hash is a fingerprint for a file. If the original document and the photocopy have the same fingerprint, you know the copy is exact. But the fingerprint does not tell you whether the original document told the truth.
Common confusion: A matching hash does not prove the content is true or that the suspect is guilty. It proves only that the copy equals the original. The examiner still has to interpret what the data means.

1. Why authentication is needed (book §4.15.1)

  • Evidence may be stored on a computer system; confiscating the whole system can breach the concept of innocence until proven guilty by denying an innocent person access to his system.
  • The court has the right to ask that the duplicated evidence be secured against accidental or purposeful change.
  • The investigating authority must show that the copy was made at the time and on the machine in question.
  • What is protected is the integrity of the material, not the content itself.

2. Method 1 — Cryptographic hashing (MD5 / SHA-1 / SHA-256)

A hash is a one-way mathematical function that converts a file or a whole disk image into a fixed-length hexadecimal value. If even one bit changes, the hash changes completely (avalanche effect).

Original disk  ──►  MD5  ──►  5d41402abc4b2a76b9719d911017c592
Image of disk  ──►  MD5  ──►  5d41402abc4b2a76b9719d911017c592
                               ^ identical ⇒ image verified
  • Compute the hash at seizure, after imaging and before analysis.
  • Record the value in the chain-of-custody form and in the report.
  • MD5 is fast and still widely used; SHA-1/SHA-256 are stronger. For court, quote the algorithm and the exact value.
  • Limitation: a hash proves the copy equals the original, not that the original was true.

3. Method 2 — Known good hash sets and hash databases

The examiner compares the hash of each file on the image with a database of known-good files (operating-system files, standard applications) and known-bad files (child-abuse material, malware).

  • Known-good set — eliminates thousands of standard files so the examiner can focus on the unknown ones (NSRL is a common source).
  • Known-bad set — instantly flags contraband or malware without opening every file.
  • This is also a validation technique: it shows that the tool produces the expected hash for a known file.

What this means: hashing checks one copy against one original. Known-good and known-bad sets check thousands of files at once, so the examiner can ignore the ordinary and focus on the suspicious.

4. Method 3 — Re-imaging and comparison

Take a second image from the original with a different tool, or re-image the working copy, then compare the two hashes. If they match, the copying procedure is repeatable. If they differ, the original changed or the tool is faulty.

5. Method 4 — Digital signatures and certificates

A digital signature uses public-key cryptography: the sender hashes the data and encrypts the hash with his private key; the receiver decrypts it with the public key and compares. A certificate authority (CA) such as VeriSign binds the public key to an identity. This is used for Authenticode, signed reports and signed evidence packages.

6. Method 5 — Hex editors and manual verification

A hexadecimal editor shows the raw bytes. The examiner can compare specific sectors, check the file header, and detect hidden or altered data that a normal tool may miss. ProDiscover's Auto Image Checksum Verification performs this comparison automatically when an image is loaded.

7. Practical considerations (book §4.15.2–4.15.3)

  • Complete, non-software-specific data gathering — prevents software traps and hidden partitions.
  • Rapid, straightforward operation — avoids mistakes and delay.
  • No training needed to operate the gathering system.
  • Only necessary expenses and resources.
  • Digital integrity verification and authentication adapted to the case.
  • Only investigators with a valid digital signature may finalise copies.
  • Minimal dependence on the operator's knowledge; processes must trap hardware faults and map exceptions.
“Explain any two” model: choose hashing and known hash sets. Both are easy to draw and both directly answer “verify and authenticate”. Add a one-line example with a real MD5 value (verified above with Python).

Q2Explain duplication & preservation of digital evidence.

8 marks★ 1×

Asked in: 2025 May Q4(b) [8]

In simple words: Duplication means making an exact bit-for-bit copy of the storage media.
Preservation means keeping the original unchanged and protected after that copy is made.
Together they let everyone analyse the same data without touching the only original.

Why we do this

Digital evidence is fragile: one accidental write can destroy it. A verified duplicate plus controlled storage protects the original and gives the defence the same data to inspect.

Words you need first

  • Duplication — making an exact copy of all data on the storage media.
  • Bit-for-bit copy — a copy that matches every single bit of the original.
  • Preservation — keeping the original unchanged and protected.
  • Write blocker — a tool that allows reading but blocks writing to the evidence disk.
  • Bit-stream image — an image of every sector, including deleted data, slack and unallocated space.
  • Hash — a fingerprint used to prove the image matches the original.
  • Working copy — the verified duplicate used for analysis.
  • Tamper-evident bag — packaging that shows if it has been opened.
  • Evidence safe — a locked store with restricted access and an access log.
  • Faraday bag — a signal-blocking bag that prevents remote wiping of a phone.
  • Chain of custody — the signed record of every handover and access.

Step-by-step

  1. Connect the original through a write blocker. Why: this prevents any accidental write during copying.
  2. Create a bit-stream image. Why: a normal copy misses deleted files, slack and unallocated space.
  3. Hash the original and the image. Why: matching hashes prove the copy is exact.
  4. Make a second copy for working. Why: the original and one copy can be stored separately.
  5. Label both copies. Why: the case number, exhibit number, date and hash must travel with the media.
  6. Seal and store the original. Why: preservation starts the moment the copy is verified.
  7. Re-verify at every transfer. Why: this catches accidental change or tampering.
Real-life analogy: You photocopy an important contract, check that the photocopy is perfect, then lock the original in a vault. You do all your reading and marking on the photocopy. If anyone questions the copy, you compare it with the vault original.
Common confusion: Duplication is not “copy and paste” a folder. A folder copy misses deleted data, file slack and unallocated space, and it does not prove the copy is exact. A forensic duplicate copies every sector and is hash-verified.

1. Duplication

Duplication is making an exact, bit-for-bit copy of the storage media. The copy must include every sector: allocated files, deleted files, file slack and unallocated space.

  1. Connect the original through a write blocker.
  2. Create a bit-stream image with a forensic tool (FTK Imager, dd, SafeBack, SnapBack).
  3. Compute a hash (MD5/SHA-1) of the original and of the image.
  4. Compare the hashes; if equal, the image is verified.
  5. Make a second copy for working purposes; store the original and one copy separately.
  6. Label both with the case number, exhibit number, date, examiner and hash value.

2. Preservation

Preservation means keeping the original evidence unchanged and protected from the moment of seizure until it is produced in court.

  • Seal the original in a tamper-evident bag and sign the seal.
  • Store in a secure evidence safe with restricted access and an access log.
  • Keep away from heat, moisture, magnetic fields and static electricity.
  • Never analyse, boot or repair the original.
  • Re-verify the hash at every transfer and before analysis.
  • Keep a complete chain-of-custody record.
  • For phones, use a faraday bag to prevent remote wipe.

What this means: duplication creates the safe copy; preservation keeps it safe. Duplication without preservation is just a copy lying in an unlocked drawer.

3. The three essential qualities of a trustworthy copy

  1. The procedure must be reliable and up to industry requirements.
  2. The copies must be tamper-proof.
  3. The copies must be able to be independently verified.

4. Why it matters

Digital evidence is weak and vulnerable to change or deletion. If the defence can show that the evidence was accessed by an uninvited party, it may be ruled inadmissible. Duplication and preservation protect the original, allow repeated analysis, and give the defence the same data to examine — which is the strongest answer to any allegation of tampering.

4.2 Types of evidence

Q1What kind of digital evidences can be collected in computer forensics? / Explain the different types of digital evidence that can be collected in computer forensics.

8–9 marks★★ 2×

Asked in: 2023 Nov Q2(a) [9] · 2023 Nov Q4(a) [8]

In simple words: Digital evidence comes in several forms: the device itself, documents stored on it, a witness's explanation, and a diagram that helps explain the rest.
It can also be grouped by source, such as e-mail, files, network traffic, browser history or a phone.
The type decides how you prove it is genuine.

Why we do this

Courts treat each type differently. A seized hard disk, a server log and an expert's opinion each need a different proof of authenticity, so the examiner must know which type they are handling.

Words you need first

  • Real evidence — a physical object shown to the court, such as the seized disk.
  • Documentary evidence — written or recorded material, such as logs, e-mail or contracts.
  • Testimonial evidence — a witness's statement under oath.
  • Demonstrative evidence — a chart, diagram or animation that explains other evidence.
  • Computer-generated record — data created by a system without a person typing it, such as an audit log.
  • Computer-stored record — data a person created and saved, such as a document or e-mail.
  • Hearsay — an out-of-court statement offered to prove its content; it is usually restricted in court.
  • Metadata — data about data, such as author, timestamps and GPS coordinates.
  • File slack — the unused tail of a file's last storage block.
  • Unallocated space — disk space not assigned to a live file.
  • Volatile evidence — data that disappears when power is lost.

Step-by-step

  1. Ask what the item is. Why: an object, a document, a statement and a diagram are treated differently.
  2. Ask who created it. Why: a machine log and a human-written e-mail need different authentication.
  3. Ask what it proves. Why: relevance decides whether the court will even consider it.
  4. Ask how you will prove it is genuine. Why: each type has its own authenticity test.
  5. Ask how you will present it. Why: a log may need a summary, and a disk may need an expert.
Real-life analogy: In a courtroom you may show the knife, read the letter, call the witness, and point to a diagram of the scene. Each is evidence, but each works in a different way. Digital evidence follows the same four roles.
Common confusion: A screenshot is usually demonstrative evidence, not the original record. The underlying log or file is stronger because it can be hashed and examined. Use the screenshot to explain, not to replace, the source.

1. The four classical types of evidence (book §4.4)

TypeMeaningDigital example
Real evidenceSomething that can be carried into court and shown to the jury; it “speaks for itself”. The most powerful type.The seized hard disk, USB drive, mobile phone, printed circuit board.
Documentary evidenceEvidence in written form. Must be authenticated; produce the original, not a copy.Server logs, e-mail, database records, contracts, chat transcripts.
Testimonial evidenceThe statement of a witness under oath, in court or by deposition.Expert examiner's testimony; statement of the system administrator.

What this means: the four types answer “what role does this play in court?” The device, the document, the witness and the diagram each have a different job. Do not call everything “real evidence”.

2. Types of digital evidence by source

  1. Computer-generated records — created by the system without human input: audit logs, event logs, firewall logs, IDS alerts, CPU and login records.
  2. Computer-stored records — created by a person and stored on the system: Word documents, spreadsheets, e-mail bodies, images, databases.
  3. E-mail evidence — the message, full header, attachments and server logs.
  4. File-system evidence — deleted files, file slack, unallocated space, alternate data streams, hidden and encrypted files.
  5. Network evidence — packet captures, router and firewall logs, NetFlow, proxy logs, DHCP and DNS logs.
  6. Internet evidence — browser history, cache, cookies, downloads, bookmarks, web-mail.
  7. Mobile and embedded evidence — call logs, SMS, WhatsApp, GPS tracks, photos with EXIF, smart-device data.
  8. Metadata — timestamps (created, modified, accessed), author, GPS coordinates, camera model, e-mail routing.
  9. Volatile evidence — RAM, running processes, open ports, ARP cache, routing table, swap file.

3. How digital evidence is treated by the court

  • US courts accept digital evidence as physical evidence; digital data is treated as a tangible object.
  • Computer-generated records are usually considered an exception to the hearsay rule if the program that created the output was functioning correctly.
  • Computer-stored records must be shown to be authentic and trustworthy before admission.

4. Rules of evidence (syllabus context — no direct PYQ)

The book lists five rules that every item of evidence must satisfy. No end-sem paper has asked this as a standalone question, but the five rules are part of the Unit-4 syllabus and can be used inside any “legal aspects” answer.

RuleMeaning
1. AdmissibleEvidence must be admissible; if it does not hold up in court, you have lost your time and may have allowed a guilty person to go free.
2. AuthenticEvidence must be genuine; you must be able to show that it relates to the incident in a meaningful way.
3. CompleteIt should be complete, not one-sided. Approach the case without assuming guilt or innocence and exclude other suspects only after an unequivocal judgment.

What this means: the five rules are a checklist for every item. Admissible gets it into court, authentic proves it is real, complete stops a one-sided story, reliable proves the method, and believable makes it understandable.

4.4 Volatile evidence

Q1What is volatile evidence in the context of computer forensics, and why is it important to collect it quickly? / What is the volatile evidence?

8–9 marks★★ 2×

Asked in: 2024 May Q4(a) [8] · 2025 Nov Q8(a) [9]

In simple words: Volatile evidence is data that disappears when the power goes off.
RAM, running processes and network connections are the clearest examples.
Collect it first, because a shutdown destroys it in seconds.

Why we do this

The most useful proof of live activity often exists only in memory. If you pull the plug first, you may lose the malware, the open connection and the logged-in user.

Words you need first

  • Volatile data — data that changes constantly and is lost when power is removed.
  • RAM — the computer's working memory, where running programs and open files live.
  • Register — a tiny, very fast storage location inside the processor.
  • Cache — fast memory that holds recently used data.
  • Virtual memory — disk space used as if it were extra RAM.
  • ARP cache — a table that maps local IP addresses to hardware addresses.
  • Process table — the operating system's list of running programs.
  • Swap file — the disk file that holds data moved out of RAM.
  • Order of volatility — the rule for collecting the fastest-changing data first.
  • Memory dump — a saved copy of RAM for analysis.
  • DLL — a shared code file that a running program can load.

Step-by-step

  1. Stop new activity. Why: every new program or login overwrites part of the memory.
  2. Record the system time and logged-in users. Why: these details disappear with the session.
  3. Capture the fastest-changing data first. Why: registers, cache and network tables change in seconds.
  4. Dump RAM with a trusted tool. Why: memory holds malware, keys and open documents.
  5. Record network connections and processes. Why: they show what the machine was doing at that moment.
  6. Hash the memory image. Why: the copy must be provably unchanged.
  7. Only then shut down and image the disk. Why: the disk is less volatile and can wait.
Real-life analogy: Volatile evidence is like ice on a warm day. If you wait, it melts and the shape is gone forever. You photograph it, measure it and bag it first; the solid furniture in the room can wait.
Common confusion: “Volatile” does not mean “unimportant” or “unreliable”. It often holds the strongest proof of live activity, such as running malware or an open connection to the attacker.

1. Definition

Volatile data is data that is in a state of change — data that will be lost when the power is switched off. Volatile evidence is present in physical memory, registers, virtual memory, the file-system cache and peripheral device memory.

2. Order of volatility (book §4.6)

Collect the most volatile first. A standard order is:

  1. Registers and cache
  2. Routing tables
  3. ARP cache
  4. Process table
  5. Kernel statistics and modules
  6. Main memory (RAM)
  7. Temporary file systems
  8. Secondary memory (disk)
  9. Router configuration
  10. Network topology

What this means: the list runs from “gone in milliseconds” to “survives a power cut”. You do not memorise it as ten random items; you read it as a countdown from most fragile to most stable.

3. Why collect quickly?

  • It disappears on shutdown — pulling the plug destroys RAM, cache and process information forever.
  • It changes continuously — every new process, login or network connection overwrites part of it.
  • It proves live activity — running malware, open sockets and injected DLLs are visible only in memory.
  • It defeats disk encryption — if the disk is encrypted, the decryption keys may exist only in RAM while the machine is running.
  • It links the user to the act — logged-in user, open documents and mapped drives.
  • It may be the only evidence — a diskless or cloud-only workstation leaves nothing on disk.

4. What to capture

  • RAM image (full physical memory)
  • Running processes and loaded DLLs
  • Open network connections and listening ports
  • Logged-on users
  • ARP cache and routing table
  • Clipboard contents
  • Mapped drives and shares
  • Command history
  • Swap/page file
  • System time and time zone
Order matters: capture RAM and network state before running any program that writes to disk. Use a trusted, forensically sound tool from a USB drive and record the hash of the memory image.

4.9 Legal aspects of collecting & preserving evidence

Q1Discuss the various legal aspects of collecting and storing digital evidence.

9 marks★★ 2×

Asked in: 2023 May Q3(a) [9] · 2025 Nov Q3(a) [9]

In simple words: Digital evidence must be collected and stored according to the law, not just the textbook.
You need lawful authority, a strict chain of custody, secure storage and respect for privacy.
A perfect technical copy can still be rejected if the seizure was illegal.

Why we do this

Courts exclude evidence obtained illegally, even when it proves the crime. Following the legal rules protects the case and the rights of everyone involved.

Words you need first

  • Legal standard — the rule a court requires before evidence can be used.
  • Chain of custody — the signed record of who handled the evidence and what they did.
  • Tamper-proof — stored so that unauthorised access or change is prevented or detected.
  • Search warrant — a judge's written permission to search or seize.
  • Scope — the limit of what a warrant or policy allows you to search.
  • Privacy — a person's right to control personal information.
  • Best evidence rule — use the original record, or a verified duplicate, rather than a casual copy.
  • Hearsay — an out-of-court statement used to prove its content; usually restricted.
  • Business-record exception — a rule that lets routine computer records be used despite the hearsay rule.
  • Retention — how long evidence must be kept.
  • Obstruction — deliberately interfering with an investigation or destroying evidence.

Step-by-step

  1. Get lawful authority. Why: a warrant, consent or written policy is the legal basis for the search.
  2. Stay inside the scope. Why: searching beyond the warrant can make the extra evidence inadmissible.
  3. Document every handover. Why: the chain of custody proves the evidence was not swapped.
  4. Store it securely. Why: tamper-proof storage protects both the evidence and the case.
  5. Respect privacy. Why: personal data on a work device may still be protected.
  6. Keep the original or a verified duplicate. Why: the best evidence rule prefers the original.
  7. Retain until the appeal period ends. Why: destroying evidence early can be obstruction.
Real-life analogy: Airport security can search your bag, but only within the law and with a record of what was done. If an officer searches a locked case without authority, the find may not count. Digital evidence follows the same rule.
Common confusion: A technically perfect image is not automatically admissible. If the device was seized without lawful authority, or the chain has a gap, the court may reject the image no matter how good the hash is.

1. Legal standards are not optional

When gathering evidence, specific legal standards must be followed. These requirements are extensive, intricate and differ from nation to nation. Evidence obtained illegally may be excluded even if it proves the crime.

2. Chain of custody as a legal requirement (book §4.14.1)

  • Documentation must identify every change in control, handling, custody and ownership.
  • Evidence must be stored in a tamper-proof manner so that unauthorised persons cannot access it.
  • A complete chain-of-custody record is kept for each item.
  • Many police departments and federal agencies have a property department that stores evidence securely.
  • Whenever experts or officers review the evidence, they check it out and check it in on every return to storage.
  • The best evidence is kept in a safe room or cupboard — an “evidence safe” — accessible only to appointed custodians.

3. Proving integrity for electronic evidence

To maintain a chain of custody, it must be demonstrated that:

  1. No information has been added or modified.
  2. A full copy was created.
  3. A trustworthy copying procedure was applied.
  4. All media were protected.

What this means: the four statements are the legal version of “prove the copy is good”. No addition, a full copy, a trustworthy method, and protected media. If any one is missing, the chain is weak.

4. Legal requirements for workplace monitoring (CERT Advisory CA-1992-19)

The advisory suggests wording that should be customised to the corporation's requirements and overseen by legal counsel:

  • The system is only for authorised users.
  • All activity by users who lack authority, or who use it in excess of their authority, is subject to monitoring and recording by system staff.
  • The actions of authorised users may also be watched while monitoring abusers or doing system maintenance.
  • Anyone using the system expressly agrees to such monitoring and is informed that system staff may give the evidence to law enforcement if it indicates suspected criminal conduct.

Two factors decide whether workplace monitoring is lawful:

  1. The existence of employment policies that permit monitoring.
  2. The extent to which those policies have been made known to employees.

Employees should sign a declaration that they have read, understood and agreed to abide by company policy and consent to system monitoring.

5. Other legal points to mention

  • Search warrant / authorization — seizing a device without lawful authority can make the evidence inadmissible.
  • Scope — search only what the warrant or policy allows; a broader search needs a broader warrant.
  • Privacy — personal data on a company device still attracts privacy protection in many jurisdictions.
  • Best evidence rule — produce the original recording or a verified duplicate.
  • Hearsay and business-record exception — computer-generated records are usually admissible as business records.
  • Retention — keep evidence until the appeal period ends; destroying it early can amount to obstruction.
9-mark structure: legal standards (1) + chain of custody (3) + four integrity statements (2) + workplace monitoring/CERT (2) + two other legal points (1).

4.3 Collection options & obstacles

Q1What are the various options available for collecting digital evidences? Explain in detail.

8 marks★ 1×

Asked in: 2024 May Q3(a) [8]

In simple words: At the scene you must choose how to collect: pull the plug, watch the intruder, capture live data, or copy over the network.
Each option saves some evidence and risks losing something else.
The right choice depends on whether the attacker is active, how critical the system is, and where it is.

Why we do this

There is no single safe method. A choice that saves a business-critical server may lose the attacker's live connection; a choice that catches the attacker may let evidence be deleted.

Words you need first

  • Collection option — the strategy chosen for taking evidence at the scene.
  • Live acquisition — collecting data while the system is running.
  • Dead acquisition — collecting a disk image after shutdown.
  • Remote acquisition — copying data over a network from another site.
  • Isolate — disconnect from the network while keeping the machine running.
  • Attribution — identifying who carried out the attack.
  • Business continuity — keeping essential services running during the investigation.
  • Dead man switch — a hidden program that wipes data when the machine is disturbed or disconnected.
  • Warrant — a judge's permission to search or seize.

Step-by-step

  1. Is the attacker still active? Why: if yes, watching may identify them; if no, preservation matters more.
  2. Is the system business-critical? Why: a production server may not be allowed to go offline.
  3. Is the site far away? Why: remote acquisition may be the only practical route.
  4. What legal authority do you have? Why: a warrant may require seizure; policy may allow only a copy.
  5. What will you lose? Why: shutdown loses RAM; staying online risks deletion.
  6. Record the choice and the reason. Why: the defence will question every undocumented action.
Real-life analogy: A fire is spreading in a building. You can cut the power and save the building, or keep the cameras running to catch the arsonist. Each choice saves something and gives up something else.
Common confusion: Pulling the plug is not always the safest option. It destroys RAM and can trigger a hidden wipe program. On a live server, capturing memory first is often the better choice.

“Options” means the strategic choice made at the moment of detection. The book gives two; in practice there are four.

OptionWhen to useMethodRisk
1. Pull the plug / remove from network and seizeThe attacker is gone; the priority is preservation.Photograph the screen, note connections, power down or isolate, image the disk.Loses RAM and running-process evidence; possible dead-man switch.
2. Leave online and track the intruderThe attacker is still active and attribution matters.Monitor traffic, log keystrokes, capture packets, watch new files.Attacker may detect the monitoring and destroy evidence.
3. Live acquisition, then isolateBusiness-critical server that cannot be switched off.Capture RAM, network state and selected files, then isolate and image.Every action changes the system; must be documented and hashed.
4. Remote acquisition over the networkThe system is at a distant site.Use a remote acquisition tool (DiskExplorer, HDHOST) to pull an image.Bandwidth, encryption and rootkits can corrupt or hide data.

What this means: the four options are not ranked. Option 1 is safest for the disk, option 2 is best for attribution, option 3 is best for a live server, and option 4 is best for distance. Match the option to the situation, then justify it.

Decision factors

  • Volatility — if RAM evidence matters, capture it first.
  • Business continuity — a production server may have to stay online.
  • Legal authority — a warrant may require seizure; company policy may allow only a copy.
  • Attacker awareness — if the intruder is still inside, pulling the plug warns him.
  • Data volume and distance — remote acquisition may be the only practical route.
Never forget: whichever option you choose, document the time, the person, the action and the reason. The defence will attack any undocumented change.

Q2What are some common obstacles faced when collecting digital evidence? Explain in detail.

8 marks★ 1×

Asked in: 2025 May Q3(a) [8]

In simple words: Digital evidence is hard to collect because it is fast, invisible, easy to change and often encrypted.
It may sit on a server in another country, or vanish before you arrive.
The obstacles are technical, legal and organisational, not just “the disk is locked”.

Why we do this

Knowing the obstacles in advance tells you what to capture first, what tools to bring and when to involve a lawyer. It also explains why a simple “copy the disk” plan often fails.

Words you need first

  • Obstacle — anything that makes collection slower, harder or less reliable.
  • Ephemeral — lasting only a very short time.
  • Audit trail — the recorded history of system activity.
  • Encryption — scrambling data so only a key can read it.
  • Steganography — hiding data inside an ordinary-looking file.
  • Anti-forensics — methods used to hide, alter or destroy evidence.
  • Timestomping — changing a file's timestamps to mislead an investigator.
  • Rootkit — malware that hides files and processes from the operating system.
  • Jurisdiction — the legal area a court or police force controls.
  • Warrant scope — the limit of what a warrant allows you to search.
  • Volatility — how quickly data disappears without power.

Step-by-step

  1. Identify the obstacle. Why: a legal problem needs a lawyer, while encryption needs a technical tool.
  2. Capture the volatile data first. Why: it disappears while you are still arguing about access.
  3. Isolate the system. Why: it stops remote deletion and further attack.
  4. Image before you investigate. Why: a verified copy lets you experiment without risk.
  5. Document what you could not get. Why: a known gap is easier to explain than a hidden one.
  6. Get legal help early. Why: jurisdiction and warrant limits can stop a case after the technical work is done.
Real-life analogy: You are chasing a thief who can erase footprints, lock doors from the inside and move to another country. You save the footprints you can see, photograph the doors, and call a lawyer before forcing entry.
Common confusion: Encryption is not the only obstacle, and often it is not the biggest one. Distance, jurisdiction, cost, business downtime and a gap in the chain of custody can stop an investigation just as effectively.

1. Obstacles listed in the book (§4.3)

  1. Speed and distance — computer transactions are quick, can be done from anywhere, and may be encrypted or anonymous.
  2. No identifying traits — digital acts lack handwriting, signatures, fingerprints or DNA that can identify a person.
  3. Ephemeral audit trail — any paper trail of computer records can be quickly altered or removed, and may exist only briefly.
  4. Automatic erasure — when transactions are completed, auditing tools may automatically erase the records left behind.
  5. Ease of alteration — data can be changed without leaving an obvious mark; transactions can be conducted anonymously.
  6. Investigative limits — investigators can only follow the norms of evidence collection and be as diligent as is feasible.

What this means: the book's six obstacles all point to one problem: digital evidence leaves no stable physical scene. The examiner must race the system, not just search it.

2. Technical obstacles

  • Encryption — full-disk encryption, encrypted containers and encrypted e-mail.
  • Steganography — evidence hidden inside images, audio or video.
  • Anti-forensics — wiping tools, timestomping, log deletion, rootkits.
  • Cloud and remote data — data may be outside the jurisdiction and controlled by a third party.
  • Volume — terabytes of data; the examiner must find the relevant fraction.
  • Volatility — RAM and network state disappear within seconds or minutes.

3. Legal and organisational obstacles

  • Jurisdiction — the server may be in another country.
  • Privacy law — employee monitoring needs a written policy and consent.
  • Warrant scope — evidence outside the warrant may be inadmissible.
  • Chain of custody — a single gap can make the evidence unreliable.
  • Cost and time — imaging and review are expensive; business downtime is costly.
