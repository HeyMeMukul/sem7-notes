6.1 Evaluating computer forensic tool needs

Q1What factors should be considered when evaluating computer forensics tool needs for an investigation? Explain any two in detail.

9 marks★★ 2×

Asked in: 2023 Nov Q7(b) [9] · 2025 May Q7(a) [9]

In simple words: Choose a forensic tool based on the case: the file system, the amount of data, encryption, the analysis you need, the budget and whether the tool will survive court. The cheapest or most popular tool is not automatically the right one.

Why we do this

A tool that cannot read the file system, handle the volume or prove its results may miss evidence or produce findings the court rejects. Matching the tool to the case saves time and protects the investigation.

Words you need first

  • File system — the way a disk organises files, such as FAT, NTFS, ext4, HFS+ or APFS.
  • RAID — a group of disks combined for speed, size or redundancy.
  • SSD — a solid-state drive with no moving parts, which may erase deleted data automatically.
  • TRIM — an SSD command that marks deleted blocks for erasure, sometimes destroying recoverable data.
  • Encryption — scrambling data so it cannot be read without a key.
  • Anti-forensics — techniques used to hide, destroy or fake evidence.
  • Acquisition — making a copy of the evidence without changing the source.
  • CFTT — the NIST Computer Forensics Tool Testing programme.
  • Licensing — the legal terms and cost of using a tool, such as per-seat or dongle licences.
  • Audit trail — a record of every action taken with the tool.
  • Dongle — a physical USB key that must be plugged in for licensed software to run.
  • Indexing — building a searchable list of file contents so keyword searches run quickly.

Step-by-step

  1. List the case facts. Note whether it is criminal, civil, HR or incident response, because each has different legal and reporting needs.
  2. Match the media and file system. Confirm the tool supports FAT, NTFS, ext4, HFS+, APFS, RAID, SSD and mobile devices as needed.
  3. Estimate the volume. A single laptop and 50 TB of server storage need different hardware, indexing time and licences.
  4. Check encryption and anti-forensics. Ask whether the tool can detect encrypted containers, hidden partitions and rootkits.
  5. Check the analysis features. You may need deleted-file recovery, keyword search, timelines, hash filtering, e-mail parsing and registry or browser artefacts.
  6. Check reporting and validation. The tool must produce a court-ready report, an audit trail and results that have been tested (for example by NIST CFTT).
  7. Check cost, training and support. A powerful tool nobody on the team can use is not a good purchase.
  8. Test it on a sample first. Run a small known case before trusting the tool with the real evidence.
Real-life analogy: It is like choosing a vehicle. A van moves furniture, a motorbike beats traffic and a truck carries heavy loads. The job decides the vehicle, not the other way round.
Common confusion: A tool that works on one file system may fail on another. NTFS support does not mean ext4, HFS+, APFS or RAID support. Check the exact formats in the case instead of assuming.

Full exam answer

1. The factors

  1. Nature of the case — criminal, civil, HR or incident response. A criminal case needs court-accepted tools and full documentation; an HR case may need only e-mail review.
  2. Type of media and file system — FAT, NTFS, ext2/3/4, HFS+, APFS, RAID, SSD or mobile. The tool must support the file system it will meet.
  3. Volume of data — a single laptop or 50 TB of server storage; this decides the hardware, indexing time and licence.
  4. Encryption and anti-forensics — can the tool detect and handle encrypted containers, hidden partitions and rootkits?
  5. Acquisition capability — physical, logical, live, remote or mobile. Does it image without changing the source?
  6. Analysis features — deleted-file recovery, keyword search, timeline, hash filtering, e-mail parsing, registry and browser artefacts.
  7. Reporting — court-ready reports, export formats and an audit trail of every action.
  8. Validation and court acceptance — has the tool been tested (NIST CFTT)? Has it been accepted in court before?
  9. Cost and licensing — open-source versus commercial; per-seat, dongle or enterprise licence.
  10. Training and support — can the team use it? Is vendor support available at short notice?
  11. Hardware requirements — CPU, RAM, disk, write blockers and forensic workstation.
  12. Speed and reliability — indexing time, stability on large images and the ability to resume.

What this means: the twelve factors are not a wish list. They are checks: if the tool fails the media, volume, validation or reporting check, it is the wrong tool for this case.

2. Factor in detail — validation and court acceptance

A tool is only useful if its output survives cross-examination. Before selecting it, check:

  • Whether the tool has been tested under the NIST Computer Forensics Tool Testing (CFTT) programme.
  • Whether the vendor publishes test reports, version history and known limitations.
  • Whether other examiners have used it and whether it has been accepted in court in your jurisdiction.
  • Whether the tool produces a hash and an audit log that can be independently verified.
  • Whether you can reproduce the result with a second tool.

3. Factor in detail — type of media and file system

A tool that handles NTFS may fail on ext4, HFS+, APFS or a RAID array. Mobile phones need a separate acquisition kit. SSDs need TRIM-aware handling because deleted data may already be gone. The examiner must match the tool to the evidence, not the other way round.

What this means: ask “what exactly am I reading?” before “which tool do I like?” The evidence format is the first technical constraint.

9-mark answer: list 8 factors in one line each (5 marks) + explain any two (4 marks). The two easiest to explain are validation/court acceptance and media/file-system support.

6.2 Computer forensics software tools

Q2State the features of any five computer forensics software tools. / Explain any software tool used in computer forensics investigation and its purpose.

9 marks★★★★★ 5×

Asked in: 2022 May Q7(b) [9] · 2022 Nov Q7(b) [9] · 2023 May Q7(a) [9] · 2024 May Q7(b) [9] · 2025 May Q8(c) [9, short note]

In simple words: Forensic software tools do different jobs. Some boot a ready-made forensic system, some analyse a disk image, some capture memory and some rebuild network traffic. In the exam, name five tools from five different categories, not five versions of the same tool.

Why we do this

No single program can acquire, repair, search, reconstruct and report everything. Knowing which tool does which job shows that you understand the forensic workflow, and it stops you using an imaging tool where an analysis tool is needed.

Words you need first

  • Live CD — a bootable disc or USB stick with forensic tools, used so the suspect operating system never starts.
  • Forensic suite — a package that combines imaging, searching, analysis and reporting.
  • GUI — a graphical user interface: menus and windows instead of typed commands.
  • E01 — the Expert Witness Format, a common forensic image file that stores metadata and checksums.
  • AFF — the Advanced Forensic Format, an open image format.
  • RAW — a plain byte-for-byte image with no extra container structure.
  • Memory dump — a copy of the contents of RAM.
  • Carving — rebuilding files from raw disk space by recognising file signatures.
  • Hash filtering — removing known safe files or flagging known bad files by their hash.
  • Timeline — a time-ordered view of file and system events.
  • Open-source — software whose source code is available, usually free to use and modify.
  • Commercial — paid software supplied and supported by a company.
  • Network forensic tool — software that rebuilds application data from captured network traffic.
  • SMTP / POP3 / IMAP — the protocols used to send mail and to collect it from a mailbox.
  • Registry hive — a file that stores part of the Windows registry.
  • Process ID — the unique number the operating system gives to a running process.

Step-by-step

The steps below show where each tool sits in a real case.

  1. Boot a live CD such as SANS SIFT. It gives you a trusted forensic environment without starting the suspect's operating system.
  2. Image the drive with FTK Imager. It creates a verified copy in E01 or RAW format and records MD5 or SHA-1 hashes.
  3. Analyse the image with The Sleuth Kit and Autopsy. They read the file system, recover deleted files, build timelines and run keyword searches.
  4. Capture and examine RAM with Volatility. Memory holds running processes, network sockets and keys that are missing from the disk.
  5. Rebuild network traffic with Xplico. It extracts e-mail and web content from a packet capture when the case involves network communication.
  6. Verify every hash and write the report. A tool result is only useful if another examiner can reproduce it and see that the evidence stayed unchanged.
Real-life analogy: A forensic toolkit is like a carpenter's toolbox: a saw, a drill and a screwdriver each do one job well. You would not try to build a cupboard with five screwdrivers.
Common confusion: “Five software tools” does not mean five disk suites. Choose five different categories — a live CD, a suite, an imager, a memory tool and a network tool. Also, do not claim a preview tool performs full analysis; FTK Imager acquires and previews, while Autopsy analyses.

Full exam answer

2. Alternative five (if you prefer)

  • ExifTool — reads, writes and edits metadata; fast; supports a large range of file formats; useful for static analysis of suspicious files.
  • HxD — user-friendly hex editor; low-level editing of raw disk or RAM; search and replace, checksums, file shredder, concatenation and splitting.
  • Bulk Extractor — scans a disk image for credit-card numbers, domains, e-mail addresses, URLs and ZIP files; writes results to text files.
  • DEFT — Linux Live CD with mobile, network, data-recovery and hashing tools.
  • HELIX3 — Linux Live CD for incident response, forensics and e-discovery; hex editors, data carving and password cracking.
  • Paladin — Ubuntu Live CD with 80+ tools in 25 categories (imaging, malware analysis, social media and hashing).
  • USB Historian — parses USB information from the Windows registry: drive name, serial number, mount time and user account.
  • Last Activity View — shows user actions and machine events; exports to CSV/XML/HTML.

3. “Explain one tool and its purpose” (2024 May)

FTK Imager. It is a data-preview and imaging tool. The examiner connects the suspect drive through a write blocker, previews the folders, then creates a bit-stream image in E01 or RAW format. The tool computes MD5/SHA-1 for the source and the image, so integrity can be verified. It can also capture RAM, mount an image as a read-only drive, export files and recover deleted items from the Recycle Bin. Its purpose is to acquire and verify evidence before full analysis in FTK or another suite.

“Any five” rule: choose tools from five different categories — one Live CD, one suite, one imager, one memory tool, one network tool. That shows breadth and prevents the answer from looking like five variations of the same thing.

Q1Explain types of digital forensics tools. Also explain the task performed by these tools.

8–9 marks★★★ 3×

Asked in: 2022 May Q7(a) [8] · 2022 Nov Q7(a) [8] · 2023 May Q7(b)(i) [9, short note]

In simple words: Forensic tools can be grouped by physical form, interface, function, scope and licence. Whatever the label, they perform five tasks: acquire the data, validate it, extract useful content, reconstruct events and report the findings.

Why we do this

Grouping tools helps you choose the right one for each stage and explain the workflow in an exam. It also stops you expecting one program to do everything from copying a drive to writing a court report.

Words you need first

  • Acquisition — making a copy of the original data without changing it.
  • Validation and discrimination — checking that the copy is accurate and separating relevant data from noise.
  • Extraction — pulling useful data out of the image, such as deleted files or keywords.
  • Reconstruction — rebuilding the sequence of events or the file system.
  • Reporting — presenting the findings in a form a court can follow.
  • Command-line interface (CLI) — a tool controlled by typed commands rather than menus.
  • GUI — a graphical user interface with windows and menus.
  • All-in-one suite — one product that covers several forensic stages.
  • Open-source — software whose code is available, usually free.
  • Commercial — paid software with vendor support.
  • Bit-stream copy — an exact copy of every byte on the drive.
  • Carving — rebuilding a file from raw data by recognising its file signature.
  • Timeline — a time-ordered list of events.
  • PST / MBOX — mailbox files used by Outlook and by Unix mail tools.
  • Allocated space — disk space currently assigned to files.
  • Slack space — the unused tail of a file's last cluster.

Step-by-step

The five steps below are the book's five task categories.

  1. Acquire. Make a physical or logical copy, verify it, and use command-line, GUI or remote acquisition as the situation requires. Without a clean copy, later analysis has no trustworthy source.
  2. Validate and discriminate. Check that the copy matches the original, then filter the data and hash known files. This stops the examiner wasting time on system files and proves the copy is sound.
  3. Extract. View, search, decompress, carve, decrypt and bookmark relevant items. This is where the useful evidence comes out of the image.
  4. Reconstruct. Rebuild deleted partitions, file-system structures and the order of events. A timeline turns isolated files into a story.
  5. Report. Present the findings with tools, versions, hashes and an audit trail. A result that cannot be explained to a court is not a finished result.
Real-life analogy: It is like cooking a meal. You buy the ingredients (acquire), check they are fresh (validate), chop and prepare them (extract), cook them in the right order (reconstruct), and plate the dish (report).
Common confusion: Acquisition and extraction are not the same. Acquisition copies the whole drive; extraction pulls specific useful data out of that copy. If you mix them up, your answer describes the wrong stage of the workflow.

2. The five task categories (book §6, Fig.)

The five categories are the five steps above. The book's sub-functions are:

  1. Acquisition — physical and logical copies, format for acquiring data, verification, command-line acquisition, GUI acquisition and remote acquisition.
  2. Validation and discrimination — filtering, hashing and investigating file headers.
  3. Extraction — data viewing, keyword search, decompression, carving, decryption and bookmarking.
  4. Reconstruction — rebuilding the sequence of events, the file system and deleted partitions; timeline analysis.
  5. Reporting — presenting the findings in court-ready form with the tools, versions, hashes and audit trail.

3. Task performed — one line each

  • Acquisition tool — makes a bit-stream copy without altering the source.
  • Write blocker — prevents any write command from reaching the evidence disk.
  • Hash tool — computes MD5/SHA-1 to verify integrity.
  • Carving tool — reconstructs files from raw clusters using file signatures.
  • Keyword search — finds text across allocated, slack and unallocated space.
  • Timeline tool — orders file-system events by time.
  • E-mail parser — extracts headers, bodies and attachments from PST/MBOX.
  • Report tool — produces a documented, reproducible report.
Book reference: the five categories are printed at the start of Unit 6 (book page 6-2) as “Computer Forensics Tools' Responsibilities/tasks”. Use these exact five names — acquisition, validation and discrimination, extraction, reconstruction, reporting.

6.3 Computer forensics hardware tools

Q1State the features of any five computer forensic hardware tools. / What is the role of hardware tools and how do they differ from software tools?

9 marks★★★★ 4×

Asked in: 2023 May Q8(a) [9] · 2024 May Q8(a) [9, short note] · 2025 May Q7(b) [9, role + difference] · 2025 Nov Q7(b) [9]

In simple words: Hardware tools are the physical side of forensics: a forensic workstation, a write blocker, a duplicator, a phone kit and a crime-scene kit. They acquire and protect evidence. Software then analyses the verified copy.

Why we do this

Simply connecting a suspect drive to a normal computer can change it. Hardware tools provide a safe physical path — read without writing, copy without altering and carry without damage — so the evidence arrives at the software exactly as it was found.

Words you need first

  • Forensic workstation — a powerful, dedicated computer used to examine images and run forensic software.
  • Write blocker — a hardware device that allows reads but blocks every write to a suspect drive.
  • Duplicator — a device that copies one drive to another without a full computer.
  • Bit-stream clone — an exact copy of every byte on the source drive.
  • Mobile acquisition kit — cables, adapters and software for extracting data from phones and GPS units.
  • Crime-scene kit — a pre-packed set of bags, labels, gloves, camera and storage media for field work.
  • IDE / SATA / SCSI — older and newer standards for connecting internal drives.
  • Hash authentication — using a hash to prove that a clone matches its source.
  • eSATA — an external version of the SATA drive connection.
  • PDA — a small handheld computer used before modern smartphones.
  • Audit trail — a record of every action performed during acquisition or analysis.

Step-by-step

  1. Photograph and document the device. Record the make, model, serial number and connections before anything is unplugged.
  2. Connect the drive through a write blocker. The blocker is the one-way valve that stops your workstation from writing to the evidence.
  3. Clone or image the drive. Use a duplicator for speed or an imaging tool for a file-based image, depending on the case.
  4. Verify the hash. Compare the source and the copy; a matching hash proves the clone is faithful.
  5. Label and seal the original. The original goes into safe storage; the copy goes to the analysis bench.
  6. Analyse the copy with software. Keep the original untouched, so the analysis can be repeated if needed.
Real-life analogy: A write blocker is a one-way valve. Data can flow out of the suspect drive to the examiner, but nothing can flow back in to change the evidence.
Common confusion: Hardware tools do not analyse the data. They acquire, protect and connect. The analysis — deleted-file recovery, keyword search and timeline building — is done by software on the verified copy.

Full exam answer

1. Role of hardware tools

Hardware tools provide the physical capability to acquire, preserve and examine digital evidence. They do not analyse data by themselves; they make sure the data reaches the software in an unaltered state. They are used for imaging, write protection, cloning, mobile acquisition and scene documentation.

2. Five hardware tools with features

2Hardware write blockerConnects a suspect drive (IDE/SATA/SCSI/USB) to the workstation and blocks every write command; examples: ACARD AEC-7720WP Ultra-Wide SCSI-to-IDE bridge. It protects the original from accidental change.

What this means: the workstation is the bench, the write blocker is the safety guard, the duplicator makes the copy, and the kits let you work at a phone or a crime scene. Each one removes a different physical risk.

6.4 Validating & testing forensics software

Q1Explain the process for validating and testing forensics software. / Write a short note on computer forensics tools testing and validation.

9 marks★★★★★ 5×

Asked in: 2022 May Q8(b) [9] · 2022 Nov Q8(b) [9] · 2024 May Q8(b) [9, short note] · 2025 May Q8(a) [9, short note] · 2025 Nov Q7(a)(i) [9, short note]

In simple words: Before trusting a forensic tool, test it on data whose answer you already know. Run it on a known file, a known drive and a deleted file, then compare the result with what should happen. NIST CFTT gives a six-step method; ISO 17025 checks that the lab can produce reliable, repeatable results.

Why we do this

A tool that misses deleted files, changes timestamps or produces a wrong hash can destroy a case. Validation proves, with records, that the tool does what it claims and that your lab can repeat the result under cross-examination.

Words you need first

  • Validation — proving that a tool or procedure produces correct, reliable results for its intended use.
  • Testing — running the tool against known data and comparing the output with the expected answer.
  • NIST — the US National Institute of Standards and Technology, which publishes forensic test methods and reports.
  • CFTT — the Computer Forensics Tool Testing programme run by NIST.
  • ISO 17025 — the international standard for the competence of testing and calibration laboratories.
  • Repeatability — the same lab, equipment and operator produce the same result.
  • Reproducibility — a different lab or operator produces the same result.
  • Test claim — a statement that a test will prove or disprove a tool's ability to meet a requirement.
  • Test case — a specific sample and procedure used to check one requirement.
  • Known-file test — hashing a file with a published value and checking that the tool gives the same value.
  • False positive — a tool reporting evidence that is not actually there.
  • Audit log — a record of every action the tool performed.
  • ISO 5725 — a standard that defines accuracy and precision for measurement methods.
  • Known-drive test — imaging a drive with known contents and checking that every file and hash matches.

Step-by-step

The six steps below are the NIST CFTT method.

  1. Create classifications for computer forensic tools. Put tools into categories such as e-mail retrieval or disk imaging, so each tool is tested against the right requirements.
  2. Identify the requirements for the category. State what a tool in that category must be able to do, in plain technical terms.
  3. Create test claims. Write tests that show whether the tool meets each requirement. A claim must be something the test can actually prove or disprove.
  4. Determine test cases. Choose sample data and a procedure; test a new tool against a closed case made with a reliable tool.
  5. Develop a test strategy. Decide how to run the test, taking the tool's function and design into account.
  6. Report the findings. Write the result to the ISO 17025 standard: accurate, transparent, unambiguous and impartial.
Real-life analogy: It is like testing a new thermometer in ice water and boiling water before using it on patients. You already know the correct temperatures, so a wrong reading proves the thermometer is faulty.
Common confusion: Testing a tool once does not validate it forever. A new version, a new operating system or a new file system can change the result, so the tool must be re-tested after a significant change.

Full exam answer

1. Why validate a tool?

Once you have decided which tools to use, you must confirm that the material you gather and examine may be used as evidence in court. A tool that produces a wrong hash, misses deleted files or changes timestamps will destroy the case. Validation proves that the tool does what it claims, reliably and repeatably.

2. NIST CFTT — the standard route

The National Institute of Standards and Technology (NIST) publishes papers, offers tools and develops methods for evaluating and verifying computer forensics software. To oversee research, NIST sponsored the Computer Forensics Tool Testing (CFTT) initiative. The six steps are listed above; together they turn “the tool seems fine” into a documented, repeatable test.

3. ISO 17025 — repeatability and reproducibility

  • Repeatable — if you operate in the same lab on the same equipment, you will produce the same results.
  • Reproducible — another examiner, in a different lab or on a different computer, will still obtain the same data.
  • ISO 5725 requires precision for all parts of the testing procedure.
  • The report must state the tool, version, settings, sample, expected result and actual result.

What this means: repeatability is “I can do it again”; reproducibility is “someone else can do it again.” A court is much more comfortable when both are true.

4. Practical validation tests you can run

  1. Known-file test — hash a known file and compare with the published MD5/SHA-1.
  2. Known-drive test — image a test drive with known contents; confirm every file is recovered and the hash matches.
  3. Deleted-file test — delete known files, image the drive and check that the tool recovers them.
  4. Slack/unallocated test — plant a keyword in slack space; check that the search finds it.
  5. Cross-tool test — run two tools on the same image; the findings must agree.
  6. Negative test — confirm that the tool does not report files that are not there (false positives).
  7. Audit-log test — confirm that every action is logged and the log cannot be edited silently.

5. Documentation of validation

  • Tool name, version, licence and patch level.
  • Test date, examiner, hardware and operating system.
  • Test data (known image or sample), expected result and actual result.
  • Hash values before and after.
  • Limitations found and the workaround used.
Short-note structure: why (2) + NIST CFTT six steps (4) + ISO 17025 repeatable/reproducible (2) + one practical test (1). That is a complete 9-mark note.

6.5 E-mail investigations

Q2Write a short note on e-mail investigation / techniques for e-mail forensic investigation.

9–18 marks★★★ 3×

Asked in: 2023 May Q7(b)(iii) [9] · 2024 May Q8(c) [9, any two] · 2025 May Q8(b) [9, any two]

In simple words: E-mail investigation means preserving the message, reading its full header, checking the attachments, and tracing the sender through IP addresses and server logs. The From line alone proves nothing, because anyone can type a false name. The header and the server records show the real route.

Why we do this

E-mail is easy to fake and easy to delete. A careful investigation preserves the original message, proves it has not changed and connects it to a real account, device or IP address. Without that chain, the message is just an anonymous claim.

Words you need first

  • E-mail header — the hidden delivery information at the top of a message, including the route and time.
  • Received chain — the list of mail servers the message passed through, one line per hop.
  • X-Originating-IP — a header added by some web-mail providers showing the sender's IP address.
  • Message-ID — a unique code created by the sending server, used to match the message to server logs.
  • Return-Path — the address where bounced mail is sent; it often reveals the real envelope sender.
  • ARIN / whois — services that show which organisation owns an IP address or domain.
  • Server log — a record kept by a mail server of logins, senders, recipients and times.
  • PST / OST / MBOX — files in which Outlook, Exchange and Thunderbird store mailboxes.
  • Sandbox — an isolated environment where a suspicious attachment can be opened safely.
  • Subpoena — a legal order requiring a person or company to provide evidence or testimony.
  • Hash — a digital fingerprint used to prove that the message file has not changed.
  • Whois — a service that shows who owns a domain name or IP address.
  • Reverse DNS — a lookup that turns an IP address back into a host name.

Step-by-step

  1. Examine the message on the victim's computer. Take an image of the machine, obtain the password if lawful, print the message with its header, and examine the sender's server IP. The local copy may contain attachments and deleted items that the server no longer has.
  2. Copy the message to a USB key. Keep a working copy so the original can stay preserved.
  3. Print the message with the mail program's print option. The printout should include the full header, not just the visible message.
  4. View the full header. Open the mail, right-click and choose “view full header”, or use the equivalent option in the client.
  5. Read the header carefully. The message header and subject body contain the origin information; look for X-Originating-IP, the return path and the receiver mail ID.
  6. Examine the attachments. Copy and print them, hash them and open them only in a sandbox. An attachment can carry malware or hidden metadata.
  7. Trace the message. Use the originating IP and domain tools (ARIN, freeality.com) to find the owner, then validate the evidence because the address may be fake.
Real-life analogy: The header is the envelope, and the mail servers are the post offices along the route. Each post office stamps the envelope, so the final recipient can see where the letter actually travelled — even if the return address is false.
Common confusion: The From: line is not proof of the sender. It is trivially spoofed. Read the Received chain from the bottom up and match the Message-ID with server logs before you name a suspect.

Full exam answer

1. The seven-step e-mail investigation (book §6.5.3)

The seven steps above are the exam list. The key order is preserve → read the header → trace → verify.

2. Techniques

  • Header analysis — reconstruct the route from the Received lines.
  • Server-log correlation — match Message-ID and timestamps with SMTP, POP and IMAP logs.
  • Hash comparison — hash the message file and compare it with the copy; any change is detected.
  • Attachment analysis — file type, metadata, malware scan and hash lookup.
  • Database recovery — Outlook PST/OST, Thunderbird MBOX, Exchange EDB and Lotus NSF.
  • Deleted-mail recovery — recover mail files from unallocated space and the recycle bin.

  • Timeline analysis — order messages and events.
  • Legal process — subpoena or warrant to the mail provider for account and login records.

What this means: the message content is only the starting point. The real proof comes from combining the header, the attachment hash, the provider's records and the server logs.

3. A short worked example

A company receives a threatening e-mail. The examiner images the recipient's PC, exports the message with full headers, and notes X-Originating-IP: 209.85.213.54 and a Gmail Message-ID. ARIN/whois shows the IP belongs to Google, so the sender used Gmail web-mail. A subpoena to Google yields the account creation IP and login times; the office firewall logs then match one of those logins to an employee's workstation. Why we do this

A message can prove intent, show a threat, reveal a data leak or place a person at a computer at a certain time. The header and server records turn an anonymous message into evidence that can be tested in court.

Words you need first

  • Header field — one labelled line in the hidden part of an e-mail, such as From: or Received:.
  • From — the sender address shown to the reader; easy to forge.
  • Return-Path — the address where bounced mail goes; often the real envelope sender.
  • Received — a line added by each mail server the message passed through, with time and IP.
  • X-Originating-IP — the sender's IP address, added by some web-mail providers.
  • Message-ID — a unique identifier created by the sending server.
  • Date — the date and time the message was sent, including the time zone.
  • Reply-To — the address that will receive replies, which may differ from From.
  • SPF — Sender Policy Framework, a check that a server is allowed to send mail for a domain.
  • DKIM — DomainKeys Identified Mail, a cryptographic signature on a message.
  • DMARC — a policy that tells receivers what to do when SPF or DKIM fails.
  • MIME — the standard that describes a message's format and attachments.
  • X-Mailer — the mail program that created the message.
  • Whois — a service that shows who owns a domain name or IP address.
  • Reverse DNS — a lookup that turns an IP address back into a host name.

Step-by-step

  1. Open the full header. The normal view hides the delivery information; the full header is where the evidence sits.
  2. Read the Received lines from the bottom up. The bottom line is the first server that handled the message, so the route makes sense in that direction.
  3. Write down every IP, server name and timestamp. These are the anchors for the timeline.
  4. Check the authentication results. SPF, DKIM and DMARC show whether the sending server was authorised; a failure is a warning sign, not automatic proof of guilt.
  5. Look up the IP owner. Use whois, ARIN or reverse DNS to identify the provider or organisation.
  6. Correlate with server logs. Match the Message-ID and times with SMTP, POP and IMAP records to link the message to an account.
  7. Preserve the message with its header. Export it, hash it and record the hash, so the court can see it was not edited.

Common confusion: Do not read the Received lines from top to bottom. The top is the last hop (closest to you); the bottom is where the message started. Reading in the wrong direction reverses the route and can point to the wrong server.

6.6 Role of the client and server in e-mail

Q1Explain the role of client and server in e-mail. / Write a short note on the role of client and server in e-mail.

8–9 marks★★★★ 4×

Asked in: 2022 May Q8(a) [8] · 2022 Nov Q8(a) [8] · 2023 May Q8(b)(i) [9] · 2025 Nov Q8(b)(i) [9]

In simple words: The e-mail client is the app you use — Gmail, Outlook or Thunderbird. The e-mail server is the computer that stores and forwards mail. The client writes and reads; the server transports and keeps the authoritative copy. Investigators need evidence from both.

Why we do this

The client shows what the user saw and saved, while the server shows the real route, time and account. A message can be deleted from the client but still exist on the server, so examining only one side gives an incomplete picture.

Words you need first

  • E-mail client — the program or web page a user opens to compose, send and read mail.
  • E-mail server — a computer that receives, stores, forwards and delivers mail for a domain.
  • SMTP — Simple Mail Transfer Protocol, used to send mail between clients and servers.
  • POP3 — Post Office Protocol 3, used to download mail from a server, often deleting it afterwards.
  • IMAP — Internet Message Access Protocol, used to keep mail on the server and synchronise it with the client.
  • MAPI — the Microsoft Exchange protocol that works like IMAP.
  • Mailbox — the storage area on the server that holds one user's messages.
  • Relay — passing a message from one mail server to the next.
  • MX record — a DNS entry that tells a sender which server receives mail for a domain.
  • Header — the hidden envelope information at the top of a message, showing route, time and IDs.
  • PST / OST / MBOX — common files in which mail clients store local mailboxes.
  • Webmail — mail read and sent through a browser rather than a desktop client.
  • Port — a numbered channel that identifies which service a connection is for.
  • DNS — the system that translates domain names into IP addresses.

Step-by-step

Follow one message from the sender's client to the recipient's mailbox.

  1. The sender composes the message in the client. The client adds the recipients, subject, body and attachments.
  2. The client sends it to the outgoing SMTP server. SMTP is the protocol for handing mail to the mail system.
  3. The server finds the recipient's domain through DNS. It looks up the MX record, which says which server accepts mail for that domain.
  4. The message travels server to server. Each hop adds a Received header, so the route is recorded.
  5. The recipient's server stores the message in the mailbox. This copy may survive even if the user later deletes it locally.
  6. The recipient's client retrieves it. POP3 downloads it and often deletes it from the server; IMAP synchronises it and keeps it on the server.
Real-life analogy: The client is the person writing and reading a letter. The server is the post office that receives the letter, sorts it, forwards it and keeps a record of delivery. The header is the envelope with the postmarks.
Common confusion: POP3 and IMAP are not interchangeable. POP3 usually downloads mail and removes it from the server; IMAP keeps the mailbox on the server and synchronises every device. This difference decides whether a server copy exists for the investigator.

Full exam answer

1. The client

The e-mail client is the application the user runs: Outlook, Thunderbird, Apple Mail, Yahoo Mail or the Gmail web interface. It composes, sends, receives and stores mail.

  • Compose — create the message, add recipients, subject, body and attachments.
  • Send — hand the message to the outgoing SMTP server.
  • Retrieve — connect to the mailbox with POP3 or IMAP and download or synchronise messages.
  • Display — list the mailbox, header, sender, date and size.
  • Manage — view, compose, delete, move to folders and search.
  • Store — keep a local copy (PST, OST, MBOX) that can become evidence.

2. The server

The e-mail server is a computer (Unix, Windows or another OS) running mail-server software. It stores and forwards messages and manages the accounts.

  • Receive — accept mail from the client or another server via SMTP.
  • Store — keep the message in the recipient's mailbox until it is collected.
  • Forward / relay — pass the message to the next server on the route.
  • Authenticate — verify the user name and password.
  • Manage accounts — one text file or database record per account.
  • Log — record the sender, recipient, time, IP and message ID.

Phishing is the usual “explain one” choice: a fake message pretends to be a bank or service, then steals passwords or installs malware. Why we do this

Different crimes leave different traces. Knowing the type tells you whether to look at the header, the attachment, the link, the mailbox or the money trail. It also helps you explain the harm in court.

Words you need first

  • Spam — unsolicited bulk e-mail, often carrying scams or malware.
  • Phishing — a fake message that impersonates a trusted organisation to steal credentials or deliver malware.
  • Spoofing — forging the sender address so the message appears to come from someone else.
  • 419 / Nigerian scam — a fraud that asks the victim to pay a small fee to release a large sum.
  • Harassment — repeated abusive or threatening messages.
  • Cyber stalking — persistent unwanted contact that frightens the victim.
  • Mail bomb — a huge volume of mail or oversized attachments designed to crash a mailbox or server.
  • Malware — software designed to damage, spy or take control, often spread by attachments or links.
  • Social engineering — manipulating a person into revealing information or performing an unsafe action.
  • SPF / DKIM / DMARC — three e-mail authentication checks that help detect forged senders.
  • Multi-factor authentication (MFA) — a login that needs more than a password, such as a code from a phone.
  • Ransomware — malware that encrypts files and demands payment to unlock them.
  • Trojan — malware disguised as a legitimate program.

Step-by-step

The steps below show how a phishing attack works and how it is investigated.

  1. The attacker registers a look-alike domain. For example, paypa1.com uses the digit one instead of the letter l, so a quick glance misses it.
  2. The attacker sends an urgent message. It uses the real logo and a threat such as “your account will be suspended”, to make the victim act before thinking.
  3. The link opens a fake login page. The page captures the user name and password, or the attachment installs malware.
  4. The stolen credentials are used immediately. The attacker may also install malware that gives long-term access.
  5. The investigator examines the header. Compare From and Return-Path, follow the Received chain and check Authentication-Results for SPF, DKIM or DMARC failures.
  6. The investigator checks the link and attachment. Compare the visible link text with the real destination, check the domain age, hash the attachment and open it only in a sandbox.
  7. The investigator uses the server logs. Find who clicked, when and from which IP, then connect that to an account and a device.
Real-life analogy: Phishing is a thief wearing a bank uniform and standing behind a fake counter. The uniform looks right, the forms look official, and the victim hands over the password without checking whether the branch is real.
Common confusion: A professional-looking logo does not make an e-mail genuine. Phishing pages can copy a brand perfectly. Check the actual link destination, the domain name and the authentication results — not the picture.

In simple words: An e-mail server is the post office: it receives mail, checks the address, queues it if the next server is down, delivers it to the mailbox and stores it until the user collects it. Its logs and mailbox copies are strong evidence because the user cannot simply delete them.

Why we do this

The server sees every message that enters or leaves a domain, even when the user deletes the local copy. Its logs can prove who sent what, to whom and when, which is often the missing link in an e-mail case.

Words you need first

  • E-mail server — a computer that receives, stores, forwards and delivers mail for a domain.
  • SMTP — the protocol used to send and relay mail between servers.
  • Queue — a holding area for messages waiting to be delivered when the destination is unavailable.
  • Relay — passing a message from one server to another.
  • Mailbox store — the file or database that holds one user's messages.
  • EDB / NSF — database formats used by Microsoft Exchange and Lotus Notes.
  • Maildir / mbox — Unix mailbox formats: one file per message, or one file for many messages.
  • Journaling — keeping a separate copy of every message for legal or compliance purposes.
  • Circular logging — overwriting the oldest log when a size or time limit is reached.
  • Retention — how long the server keeps logs or messages.
  • Message tracking — following a message's path through the server logs.
  • Password hash — a one-way fingerprint of a password, stored instead of the password itself.
  • Quota — the maximum mailbox size a user is allowed.

Step-by-step

Follow one message through the server's eight jobs.

  1. Accept mail. The server receives the message from a client or another server over SMTP.
  2. Authenticate the user and check the recipient. It confirms the login and whether the address exists, so mail is not accepted for a non-existent account.
  3. Queue the message if the destination is unavailable. The server retries later instead of losing the mail.
  4. Deliver or relay. It places the message in a local mailbox or passes it to the next server.
  5. Store the message. The mailbox keeps it until the user retrieves it, even if the user later deletes the local copy.
  6. Provide access. POP3, IMAP, MAPI or web-mail lets the client collect or synchronise the mail.
  7. Filter spam and malware. The server applies policy before the message reaches the user.
  8. Log every transaction. The log records the sender, recipient, time, IP and message ID for audit and investigation.
Real-life analogy: The server is the post office. It receives letters, sorts them, holds them when the delivery route is closed, delivers them to the right box, and keeps a delivery book that the recipient cannot erase.
Common confusion: Deleting a message in the mail client does not always delete it from the server. Backups, journaling mailboxes and retention policies may keep a copy that the user never sees.

Full exam answer

1. Function of an e-mail server

An e-mail server is a computer running mail-server software that receives, stores, forwards and delivers e-mail for a domain. It is the central point between the sender's client and the recipient's client. The eight functions are the step-by-step list above.

2. How it stores mail

  • Mailbox store — one mailbox per account, often a database file or a directory of files.
  • Database-backed — Microsoft Exchange uses EDB; Lotus Notes uses NSF; some servers use SQL.
  • Flat-file — Unix maildir or mbox; one file per message or one file per mailbox.
  • User profile — the server keeps a text file or database record for each account: user name, password hash, quota and forwarding rules.
  • Attachments — stored inside the message or as separate objects referenced by the database.
  • Backup — server backups and journaling mailboxes keep copies for compliance.

What this means: the format decides which tool can open the mailbox. A PST tool will not read an Exchange EDB, and a Unix mbox is not a Microsoft database.

3. How it manages mail

  • Accounts and quotas — create, disable and limit mailbox size.
  • Folders — Inbox, Sent, Drafts, Deleted Items and custom folders.
  • Rules — forwarding, auto-reply, filtering and retention.
  • Journaling — a copy of every message for legal hold.
  • Logs — SMTP, POP, IMAP and system logs. The administrator can turn logging off or use circular logging, which overwrites the oldest log when a size or time limit is reached.
  • Retention — the server may keep logs for one day plus six days (Mon.log … Sun.log), or longer under policy.

What this means: logging is not automatic or permanent. Ask the administrator how long logs are kept and whether circular logging has already overwritten the period you need.

4. Forensic value of the server

  • Message tracking — who sent what to whom, when and from which IP.
  • Mailbox contents — messages the user deleted locally may still be on the server.
  • Logs — prove delivery, login and relay; Use.log and a.db are examples from the book.
  • Journal archive — an independent copy that the user cannot delete.
  • Authentication records — link a message to an account and a device.
Book example: the administrator keeps the.db files for the e-mail server. A third-party program such as Use.log may search a.db; at least two logs linked to e-mail are likely present — one listing logged events for accounts accessing e-mail, another listing messages and other files. Text editors and forensic suites (FTK, EnCase) can read them.

6.8 Specialised e-mail forensic tools

Q1Write a short note on e-mail forensics tools. / List and explain specialized e-mail forensic tools.

9 marks★★★ 3×

Asked in: 2023 May Q7(b)(ii) [9] · 2023 Nov Q8(b)(i) [9, any one] · 2025 Nov Q8(b)(ii) [9]

In simple words: E-mail forensic tools open mailbox files, recover deleted messages, show full headers, search many mailboxes and export court-ready reports. Examples are FTK, Paraben E-Mail Examiner, FINALeMAIL, R-Mail and Xplico. A specialised tool often recovers more than a general forensic suite.

Why we do this

Mail is stored in many formats — PST, OST, MBOX, EDB, NSF and DBX — and each has its own structure. A tool built for e-mail understands those formats, finds deleted items and preserves the header and attachments that make the message usable as evidence.

Words you need first

  • PST / OST — Outlook mailbox files; PST is a local store, OST is an offline Exchange cache.
  • MBOX — a Unix mailbox format that stores many messages in one file.
  • EDB — the Microsoft Exchange mailbox database format.
  • NSF — the Lotus Notes database format.
  • DBX — the Outlook Express mailbox format.
  • Deleted-mail recovery — finding messages that the user removed but that still exist in the file or unallocated space.
  • Header extraction — pulling the full delivery information out of a message.
  • Hash — a fingerprint used to prove that the exported message has not changed.
  • Audit log — a record of what the tool did, so the result can be checked.
  • E-discovery — the legal process of identifying and exchanging electronic evidence.
  • Mailbox file — a file that stores one or more e-mail messages in a particular format.
  • Corrupted file — a file whose internal structure is damaged and may not open normally.

Step-by-step

  1. Identify the mail store. Find out whether the case involves PST, OST, MBOX, EDB, NSF or DBX; the format decides which tool can open it.
  2. Acquire the evidence. Image the disk or copy the mailbox file through a write blocker, and hash the source.
  3. Open the file in the tool. Load the mailbox without modifying the original, and work on a copy.
  4. Recover deleted messages. Search the file structure and unallocated space for items the user tried to remove.
  5. Extract headers and attachments. The header proves the route; the attachment may carry the payload or the stolen data.
  6. Search across mailboxes. Use sender, recipient, subject, date, keyword and attachment type to narrow the review.
  7. Export with a hash and audit log. The export must be reproducible and visibly unchanged.
  8. Verify and document. Another examiner should be able to open the export and get the same result.
Real-life analogy: An e-mail forensic tool is a specialist locksmith. A general carpenter can open some doors, but a locksmith knows every lock type and can open a damaged lock without breaking the door.
Common confusion: An e-mail tool is not just a viewer. It must preserve metadata, recover deleted items and produce a verifiable export. If it only displays the message, it is not enough for court.

  • Is the report accepted in court?
  • Can it handle large mailboxes without crashing?
