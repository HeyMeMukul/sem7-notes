6.1 Evaluating computer forensic tool needs

Q1What factors should be considered when evaluating computer forensics tool needs for an investigation? Explain any two in detail.

9 marks★★ 2×

Asked in: 2023 Nov Q7(b) [9] · 2025 May Q7(a) [9]

1. The factors

  1. Nature of the case — criminal, civil, HR or incident response. A criminal case needs court-accepted tools and full documentation; an HR case may need only e-mail review.
  2. Type of media and file system — FAT, NTFS, ext2/3/4, HFS+, APFS, RAID, SSD, mobile. The tool must support the file system it will meet.
  3. Volume of data — a single laptop or 50 TB of server storage; this decides the hardware, the indexing time and the licence.
  4. Encryption and anti-forensics — can the tool detect and handle encrypted containers, hidden partitions and rootkits?
  5. Acquisition capability — physical, logical, live, remote, mobile. Does it image without changing the source?
  6. Analysis features — deleted-file recovery, keyword search, timeline, hash filtering, e-mail parsing, registry and browser artefacts.
  7. Reporting — court-ready reports, export formats, audit trail of every action.
  8. Validation and court acceptance — has the tool been tested (NIST CFTT)? Has it been accepted in court before?
  9. Cost and licensing — open-source vs commercial; per-seat, dongle or enterprise licence.
  10. Training and support — can the team use it? Is vendor support available at short notice?
  11. Hardware requirements — CPU, RAM, disk, write blockers, forensic workstation.
  12. Speed and reliability — indexing time, stability on large images, ability to resume.

2. Factor in detail — validation and court acceptance

A tool is only useful if its output survives cross-examination. Before selecting it, check:

  • Whether the tool has been tested under the NIST Computer Forensics Tool Testing (CFTT) programme.
  • Whether the vendor publishes test reports, version history and known limitations.
  • Whether other examiners have used it and whether it has been accepted in court in your jurisdiction.
  • Whether the tool produces a hash and an audit log that can be independently verified.
  • Whether you can reproduce the result with a second tool.

3. Factor in detail — type of media and file system

A tool that handles NTFS may fail on ext4, HFS+, APFS or a RAID array. Mobile phones need a separate acquisition kit. SSDs need TRIM-aware handling because deleted data may already be gone. The examiner must match the tool to the evidence, not the other way round.

9-mark answer: list 8 factors in one line each (5 marks) + explain any two (4 marks). The two easiest to explain are validation/court acceptance and media/file-system support.

6.2 Computer forensics software tools

Q1Explain types of digital forensics tools. Also explain the task performed by these tools.

8–9 marks★★★ 3×

Asked in: 2022 May Q7(a) [8] · 2022 Nov Q7(a) [8] · 2023 May Q7(b)(i) [9, short note]

1. Types of tools

BasisTypesExamples
Physical formHardware tools, software toolsWrite blocker, duplicator vs FTK, EnCase, Autopsy
InterfaceCommand-line, GUIdd, dcfldd vs FTK, ProDiscover
FunctionAcquisition, validation, extraction, reconstruction, reportingFTK Imager, hash tool, carving tool, timeline tool, report generator
ScopeSingle-purpose, all-in-one suiteExifTool vs EnCase
LicenceOpen-source, commercialSIFT, Sleuth Kit vs EnCase, FTK

2. The five task categories (book §6, Fig.)

  1. Acquisition — create a replica of the original drive. Sub-functions: physical and logical copies, format for acquiring data, verification, command-line acquisition, GUI acquisition, remote acquisition.
  2. Validation and discrimination — verify the accuracy of the duplicate and sort the data. Sub-functions: filtering, hashing, investigating file headers.
  3. Extraction — recover data from the image. Sub-functions: data viewing, keyword search, decompression, carving, decryption, bookmarking.
  4. Reconstruction — rebuild the sequence of events, file system and deleted partitions; timeline analysis.
  5. Reporting — present the findings in a court-ready form, with the tools, versions, hashes and audit trail.

3. Task performed — one line each

  • Acquisition tool — makes a bit-stream copy without altering the source.
  • Write blocker — prevents any write command from reaching the evidence disk.
  • Hash tool — computes MD5/SHA-1 to verify integrity.
  • Carving tool — reconstructs files from raw clusters using file signatures.
  • Keyword search — finds text across allocated, slack and unallocated space.
  • Timeline tool — orders file-system events by time.
  • E-mail parser — extracts headers, bodies and attachments from PST/MBOX.
  • Report tool — produces a documented, reproducible report.
Book reference: the five categories are printed at the start of Unit 6 (book page 6-2) as “Computer Forensics Tools' Responsibilities/tasks”. Use these exact five names — acquisition, validation and discrimination, extraction, reconstruction, reporting.

6.3 Computer forensics hardware tools

Q1State the features of any five computer forensic hardware tools. / What is the role of hardware tools and how do they differ from software tools?

1. Role of hardware tools

Hardware tools provide the physical capability to acquire, preserve and examine digital evidence. They do not analyse data by themselves; they make sure the data reaches the software in an unaltered state. They are used for imaging, write protection, cloning, mobile acquisition and scene documentation.

2. Five hardware tools with features

2Hardware write blockerConnects a suspect drive (IDE/SATA/SCSI/USB) to the workstation and blocks every write command; examples: ACARD AEC-7720WP Ultra-Wide SCSI-to-IDE bridge. It protects the original from accidental change.

One-line answer for “role”: hardware tools guarantee that the evidence is acquired and preserved without alteration; software tools then analyse the verified copy. Neither replaces the other.

6.4 Validating & testing forensics software

Q1Explain the process for validating and testing forensics software. / Write a short note on computer forensics tools testing and validation.

9 marks★★★★★ 5×

Asked in: 2022 May Q8(b) [9] · 2022 Nov Q8(b) [9] · 2024 May Q8(b) [9, short note] · 2025 May Q8(a) [9, short note] · 2025 Nov Q7(a)(i) [9, short note]

1. Why validate a tool?

Once you have decided which tools to use, you must confirm that the material you gather and examine may be used as evidence in court. A tool that produces a wrong hash, misses deleted files or changes timestamps will destroy the case. Validation proves that the tool does what it claims, reliably and repeatably.

2. NIST CFTT — the standard route

The National Institute of Standards and Technology (NIST) publishes papers, offers tools and develops methods for evaluating and verifying computer forensics software. To oversee research, NIST sponsored the Computer Forensics Tool Testing (CFTT) initiative.

  1. Create classifications for computer forensic tools — software for forensics should be categorised, such as forensic tools for e-mail retrieval and tracking.
  2. Identify the requirements for the category — describe the technological requirements that a tool must meet.
  3. Create test claims — tests that demonstrate or refute the tool's capacity to satisfy the requirements.
  4. Determine test cases — find or design categories to look into using the tool, and decide what data should be extracted from a sample drive. Test a new tool in the same category against a closed case file made with a reliable tool.
  5. Develop a test strategy — decide how to test the tool, taking into account its function and design.
  6. Report test findings — state the results in a report in accordance with ISO 17025, which calls for accurate, transparent, unambiguous and impartial test reports.

3. ISO 17025 — repeatability and reproducibility

  • Repeatable — if you operate in the same lab on the same equipment, you will produce the same results.
  • Reproducible — another examiner, in a different lab or on a different computer, will still obtain the same data.
  • ISO 5725 requires precision for all parts of the testing procedure.
  • The report must state the tool, version, settings, sample, expected result and actual result.

4. Practical validation tests you can run

  1. Known-file test — hash a known file and compare with the published MD5/SHA-1.
  2. Known-drive test — image a test drive with known contents; confirm every file is recovered and the hash matches.
  3. Deleted-file test — delete known files, image the drive, and check that the tool recovers them.
  4. Slack/unallocated test — plant a keyword in slack space; check that the search finds it.
  5. Cross-tool test — run two tools on the same image; the findings must agree.
  6. Negative test — confirm that the tool does not report files that are not there (false positives).
  7. Audit-log test — confirm that every action is logged and the log cannot be edited silently.

5. Documentation of validation

  • Tool name, version, licence and patch level.
  • Test date, examiner, hardware and operating system.
  • Test data (known image or sample), expected result and actual result.
  • Hash values before and after.
  • Limitations found and the workaround used.
Short-note structure: why (2) + NIST CFTT six steps (4) + ISO 17025 repeatable/reproducible (2) + one practical test (1). That is a complete 9-mark note.

Q2Write a short note on NIST standards for forensic technologies.

9 marks★ 1×

Asked in: 2023 May Q8(b)(iii) [9]

1. Who NIST is and why it matters

The National Institute of Standards and Technology (NIST) is a US government laboratory that develops standards and test methods. In digital forensics it provides the independent, published testing that courts and laboratories rely on to show that a tool is fit for purpose.

2. Key NIST activities

Programme / documentWhat it provides
CFTT — Computer Forensics Tool TestingTest specifications, test procedures, test reports and tool categories for imaging, write blockers, mobile, e-mail and file recovery.
NIST SP 800-86Guide to Integrating Forensic Techniques into Incident Response — the four-phase process: collection, examination, analysis, reporting.
NIST SP 800-101Guidelines on mobile-device forensics.
NSRL — National Software Reference LibraryA database of known file hashes used to filter out operating-system and application files.
CFReDSComputer Forensic Reference Data Sets — sample images with known answers for testing tools.

3. The CFTT testing model

  1. Define the tool category (e.g. disk imaging, write blocker, mobile acquisition).
  2. Write the requirements the tool must meet.
  3. Write test assertions / test claims.
  4. Define the test cases and the test data.
  5. Run the tests in a controlled laboratory.
  6. Publish a test report with pass/fail results and limitations.

4. How a lab uses NIST standards

  • Select a tool that has a current CFTT report for the required category.
  • Repeat the relevant test in-house and keep the record.
  • State the tool, version and NIST test reference in the forensic report.
  • Use ISO/IEC 17025 for the laboratory quality system and NIST CFTT for the tool.
  • Use SWGDE and ENFSI guidance where the jurisdiction requires it.
Exam-safe line: “NIST does not certify tools; it publishes test reports. The laboratory must still validate the tool in its own environment.” This distinction earns marks and is technically correct.

6.5 E-mail investigations

Q1How does e-mail play a significant role in digital investigations? What types of information can be obtained from an e-mail header that may be relevant in investigations?

9 marks★ 1×

Asked in: 2023 Nov Q7(a) [9]

1. Role of e-mail in investigations

  • Primary business record — e-mail has largely replaced memos and letters; it contains decisions, approvals and instructions.
  • Evidence of intent — people write things in e-mail that they would never put in a formal document.
  • Fraud, phishing and spoofing — the message and header show the true sender and route.
  • Harassment, threats and stalking — the content, frequency and timestamps establish a pattern.
  • Data leakage — attachments show what was sent out and to whom.
  • Timeline — the Date and Received lines place the message at a specific time and place.
  • Attribution — the originating IP, Message-ID and mail-server logs link the message to an account and a device.
  • Civil and criminal proceedings — e-mail has been used effectively in both.

2. Information in an e-mail header

Header fieldWhat it tells the investigator
FromDisplayed sender address — easily forged, so treat with caution.
Return-PathThe address to which bounces go; often the real envelope sender.
ReceivedEvery mail server the message passed through, with date, time and IP. Read bottom-up to trace the route.
X-Originating-IPThe IP address of the sender's machine, inserted by some web-mail providers.
Message-IDUnique identifier created by the originating server; links the message to server logs.
DateDate and time the message was sent, including the time zone.
To / Cc / BccRecipients; Bcc may be missing from the received copy.
SubjectTopic; may contain keywords relevant to the case.
Reply-ToA different address than From — a common phishing trick.
Authentication-ResultsSPF, DKIM and DMARC results — shows whether the sender was authorised.
DKIM-SignatureCryptographic signature over selected headers and the body; a broken signature suggests tampering.
MIME-Version / Content-TypeFormat of the message and whether it has attachments.
X-MailerThe mail client that created the message.

3. Example header analysis

From: Suvarna Pansambal Tue Feb 2 12:16:14 2016
X-Originating-IP: [209.85.213.54]
Received: from 127.0.0.1 (EHLO mail-vk0-f54.google.com) (209.85.213.54)
          by mta1073.mail.gq1.yahoo.com with SMTP; Tue, 02 Feb 2016 12:16:15 -0800
Authentication-Results: mta1073.mail.gq1.yahoo.com from=gmail.com;
          domainkeys=neutral (no sig); from=gmail.com; dkim=pass (ok)
Message-ID: <...@mail.gmail.com>
Subject: Threat mail

Reading it: the message claims to come from a Gmail account, but the Received chain shows it entered through a Google server and was delivered to a Yahoo mailbox. The X-Originating-IP is a Google address, not the sender's home IP. The DKIM result is “pass”, so the message was signed by Gmail, but the display name is not proof of identity. The investigator must obtain the Gmail account details and the Yahoo server logs to identify the actual user.

Key point: the From: line is trivially spoofed. The Received chain, Message-ID and X-Originating-IP are much harder to fake, and server logs are the strongest evidence.

Q2Write a short note on e-mail investigation / techniques for e-mail forensic investigation.

9–18 marks★★★ 3×

Asked in: 2023 May Q7(b)(iii) [9] · 2024 May Q8(c) [9, any two] · 2025 May Q8(b) [9, any two]

1. The seven-step e-mail investigation (book §6.5.3)

  1. Examine the e-mail message — the evidence may be on the victim's computer. Take an image of the machine, obtain the password, print the message with its header, and examine the sender's server IP.
  2. Copy the e-mail message to a USB key.
  3. Take a printout of the message using the mail program's print option.
  4. View the mail header — open the mail, right-click, choose “view full header”.
  5. Examine the e-mail header — the message header and the subject body contain the origin information; the X-Originating-IP, return path and receiver mail ID are visible.
  6. Examine the attachments — copy and print them; hash them; open them only in a sandbox.
  7. Trace the e-mail — use the originating IP and domain tools (ARIN, freeality.com) to find the owner; validate the evidence because the address may be fake.

2. Techniques

  • Header analysis — reconstruct the route from the Received lines.
  • Server-log correlation — match Message-ID and timestamps with SMTP, POP and IMAP logs.
  • Hash comparison — hash the message file and compare with the copy; any change is detected.
  • Attachment analysis — file type, metadata, malware scan, hash lookup.
  • Database recovery — Outlook PST/OST, Thunderbird MBOX, Exchange EDB, Lotus NSF.
  • Deleted-mail recovery — recover mail files from unallocated space and the recycle bin.
  • Domain/IP lookup — whois, ARIN, reverse DNS, geolocation.
  • Timeline analysis — order messages and events.
  • Legal process — subpoena or warrant to the mail provider for account and login records.

3. A short worked example

A company receives a threatening e-mail. The examiner images the recipient's PC, exports the message with full headers, and notes X-Originating-IP: 209.85.213.54 and a Gmail Message-ID. ARIN/whois shows the IP belongs to Google, so the sender used Gmail web-mail. A subpoena to Google yields the account creation IP and login times; the office firewall logs then match one of those logins to an employee's workstation. The attachment hash matches a file found on that workstation. The case is proved by the header + provider records + firewall log + file hash, not by the From line.

Short-note answer: 7 numbered steps + 5 techniques + one line on “From is not proof”. For 18 marks, add the worked example and a small header diagram.

6.6 Role of the client and server in e-mail

Q1Explain the role of client and server in e-mail. / Write a short note on the role of client and server in e-mail.

8–9 marks★★★★ 4×

Asked in: 2022 May Q8(a) [8] · 2022 Nov Q8(a) [8] · 2023 May Q8(b)(i) [9] · 2025 Nov Q8(b)(i) [9]

1. The client

The e-mail client is the application the user runs: Outlook, Thunderbird, Apple Mail, Yahoo Mail, Gmail web interface. It composes, sends, receives and stores mail.

  • Compose — create the message, add recipients, subject, body and attachments.
  • Send — hand the message to the outgoing SMTP server.
  • Retrieve — connect to the mailbox with POP3 or IMAP and download or synchronise messages.
  • Display — list the mailbox, show the header, sender, date and size.
  • Manage — view, compose, delete, move to folders, search.
  • Store — keep a local copy (PST, OST, MBOX) that can become evidence.

2. The server

The e-mail server is a computer (Unix, Windows or other OS) running mail-server software. It stores and forwards messages and manages the accounts.

  • Receive — accept mail from the client or another server via SMTP.
  • Store — keep the message in the recipient's mailbox until it is collected.
  • Forward / relay — pass the message to the next server on the route.
  • Authenticate — verify the user name and password.
  • Manage accounts — one text file or database record per account.
  • Log — record the sender, recipient, time, IP and message ID.

3. The flow of a message

Sender's client │ SMTP (port 25 / 587) ▼ Sender's mail server ──► DNS/MX lookup ──► Receiver's mail server │ stores in mailbox ▼ Receiver's client (POP3 110 / IMAP 143) │ ▼ Local mailbox
  1. The sender composes the message in the client.
  2. The client sends it to the outgoing SMTP server.
  3. The server finds the recipient's domain through DNS (MX record).
  4. The message travels server-to-server; each hop adds a Received header.
  5. The recipient's server stores the message in the mailbox.
  6. The recipient's client retrieves it with POP3 (download and often delete) or IMAP (synchronise and keep on server).

4. Protocols to name

ProtocolPortRole
SMTP25 / 587Sending and receiving mail between servers; easy to spoof.
POP3110 / 995Downloads incoming mail to the workstation; usually deletes from server.
IMAP143 / 993Stores all messages on the server; client and server stay synchronised; copies of incoming and outgoing mail remain on the server or workstation.
MAPI—Microsoft Exchange protocol; works like IMAP.
HTTP / HTTPS80 / 443Web-based send and receive.

5. Forensic significance

  • The client holds the local mailbox, address book, attachments and deleted items — the best source on the suspect's PC.
  • The server holds the authoritative log of senders, recipients, IPs and times — the best source for attribution.
  • A POP3 client may be the only copy of the message; an IMAP account leaves a copy on the server that can be subpoenaed.
  • Web-mail (HTTP) leaves evidence in the browser cache, cookies and the provider's logs.

2. One crime in detail — phishing

Definition: phishing is a form of social engineering in which the attacker sends an e-mail that appears to come from a trusted organisation and persuades the victim to reveal credentials, card numbers or to run an attachment.

How it works:

  1. The attacker registers a look-alike domain (for example paypa1.com).
  2. The e-mail uses the real logo and a urgent message (“your account will be suspended”).
  3. The link goes to a fake login page that captures the user name and password.
  4. The credentials are used immediately, or the attachment installs malware.

What the investigator examines:

  • From and Return-Path — usually different from the real domain.
  • Received chain — the true originating server and IP.
  • URL — the link text and the actual href differ; the domain is newly registered.
  • Authentication-Results — SPF/DKIM/DMARC often fail.
  • Attachment — hash, file type and macro content.
  • Server logs — who clicked, when, from which IP.

Prevention: SPF, DKIM and DMARC; user awareness; link inspection; multi-factor authentication; mail filtering.

3. The 419 / Nigerian scam in brief

One of the most notable e-mail frauds. It started as a chain letter from Nigeria and moved to e-mail to save international postage. The message uses a standard writing style, capital letters and a few recognisable tricks: a large sum is trapped and the victim must pay a small fee or give bank details to release it. Modern variants are more sophisticated but the structure is the same. Investigators trace the header, the receiving bank account and the money-transfer records.

“Any one in detail”: choose phishing. It has a clear definition, a four-step mechanism, six investigative points and a prevention list — enough for 9 marks without padding.

Q2What is the function of an e-mail server and how does it store and manage e-mail data?

9 marks★ 1×

Asked in: 2023 Nov Q8(a) [9]

1. Function of an e-mail server

An e-mail server is a computer running mail-server software that receives, stores, forwards and delivers e-mail for a domain. It is the central point between the sender's client and the recipient's client.

  1. Accept mail from clients and other servers via SMTP.
  2. Authenticate users and check whether the recipient exists.
  3. Queue messages when the destination is unavailable and retry later.
  4. Deliver to the local mailbox or relay to another server.
  5. Store messages until the user retrieves them.
  6. Provide access through POP3, IMAP, MAPI or web-mail.
  7. Filter spam and malware, and apply business policy.
  8. Log every transaction for audit and investigation.

2. How it stores mail

  • Mailbox store — one mailbox per account, often a database file or a directory of files.
  • Database-backed — Microsoft Exchange uses EDB; Lotus Notes uses NSF; some servers use SQL.
  • Flat-file — Unix maildir or mbox; one file per message or one file per mailbox.
  • User profile — the server keeps a text file or database record for each account: user name, password hash, quota, forwarding rules.
  • Attachments — stored inside the message or as separate objects referenced by the database.
  • Backup — server backups and journaling mailboxes keep copies for compliance.

3. How it manages mail

  • Accounts and quotas — create, disable and limit mailbox size.
  • Folders — Inbox, Sent, Drafts, Deleted Items, custom folders.
  • Rules — forwarding, auto-reply, filtering and retention.
  • Journaling — a copy of every message for legal hold.
  • Logs — SMTP, POP, IMAP and system logs; the administrator can turn logging off or use circular logging, which overwrites the oldest log when a size or time limit is reached.
  • Retention — the server may keep logs for one day plus six days (Mon.log … Sun.log), or longer under policy.

4. Forensic value of the server

  • Message tracking — who sent what to whom, when, and from which IP.
  • Mailbox contents — messages the user deleted locally may still be on the server.
  • Logs — prove delivery, login and relay; Use.log and a.db are examples from the book.
  • Journal archive — an independent copy that the user cannot delete.
  • Authentication records — link a message to an account and a device.
Book example: the administrator keeps the.db files for the e-mail server. A third-party program such as Use.log may search a.db; at least two logs linked to e-mail are likely present — one listing logged events for accounts accessing e-mail, another listing messages and other files. Text editors and forensic suites (FTK, EnCase) can read them.

1. What e-mail forensic tools do

  • Locate and open mailbox files (PST, OST, MBOX, EDB, NSF, DBX).
  • Recover deleted messages and attachments.
  • Extract and display full headers.
  • Search by sender, recipient, subject, date, keyword or attachment type.
  • Export messages in a court-ready format with a hash and audit log.
  • Correlate server logs with mailbox content.

4. One tool in detail — Paraben E-Mail Examiner

Paraben E-Mail Examiner opens PST, OST, DBX, MBOX and Exchange EDB files. It recovers deleted messages, shows the full header, searches across multiple mailboxes, extracts attachments and produces a report. It is used when the investigator needs a dedicated e-mail tool rather than a full forensic suite, and when several mail formats must be handled in one case.

5. How to choose

  • Does it support the mail store in the case (PST, OST, EDB, NSF, MBOX)?
  • Can it recover deleted mail and show the header?
  • Does it hash the output and keep an audit log?
  • Is the report accepted in court?
  • Can it handle large mailboxes without crashing?
