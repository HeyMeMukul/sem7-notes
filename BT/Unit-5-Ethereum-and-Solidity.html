5.4 Smart contracts

Q4Explain the concept of a smart contract with an example. Define smart contracts with a real-world scenario and evaluate their benefits. Discuss the role of gas.

6 / 8 / 9 marks★★★★★ 6×Unit 5

Asked in: 2024 May Q6(a) [8 — concept + example] · 2025 May Q5(b) [9 — real-world example + gas] · 2025 Nov Q6(a) [8 — concept + example] · also part of 2022 Nov Q6(a) [8] and 2023 Nov Q5(c) [6]

In simple words: A smart contract is a small program that lives on a blockchain. It runs by itself when its conditions are met. No clerk, lawyer or broker has to approve the result. Once deployed, its code cannot be quietly changed.

Why we do this

Normal agreements need people to check papers, approve each step and update separate records. That is slow, costly and open to mistakes or favouritism. A smart contract puts the rule and the money in one place, so the result happens automatically and every participant sees the same outcome.

Words you need first

  • Blockchain: a shared record book copied across many computers, where past entries are very hard to change.
  • Ethereum: a blockchain designed to run programs, often called a “world computer”.
  • Smart contract: a program stored on a blockchain that runs automatically when its coded conditions are met.
  • EVM (Ethereum Virtual Machine): the engine inside every Ethereum node that runs contract code.
  • Bytecode: the low-level instruction form of a program that the EVM can execute.
  • Solidity: the main programming language used to write Ethereum contracts.
  • Gas: a unit that measures computational work and is paid for in ether.
  • Blockspace: the limited room in a block for transactions; users compete for it by paying higher fees.
  • Ether (ETH): Ethereum’s native money, used to pay gas and to stake.
  • Deploy: to publish a contract to the blockchain so that it receives its own address.
  • Immutable: cannot be changed after it has been written.
  • Deterministic: the same input always produces the same output.
  • Oracle: a trusted data feed that brings outside facts, such as a flight delay, onto the blockchain.
  • dApp: a decentralised application whose backend rules are smart contracts.
  • DAO: a decentralised autonomous organisation, run by code and votes instead of a boss.
  • Escrow: a neutral holding place for money until both sides meet the agreed condition.
  • ABI: the public menu of functions that tells an app how to call a contract.
  • Contract account: an Ethereum account that holds contract code and storage instead of a private key.
  • Validator: a computer that checks transactions and helps secure Ethereum under proof of stake.

Step-by-step

  1. Write the rule. A developer writes the agreement in Solidity: who pays, which event triggers payment, and how much is paid.
  2. Compile it. A compiler turns readable code into bytecode that the EVM can run. It also creates the ABI, the list of functions that apps may call.
  3. Deploy it. A special transaction sends the bytecode to Ethereum. The network stores it and gives it an address, like a house number.
  4. Fund and call it. A user sends ETH or calls a function. Each call costs gas because it uses computing power.
  5. Check the condition. The contract reads its own stored data and, if needed, a trusted oracle.
  6. Apply the result. If the condition is true, the contract pays or updates its records. If it is false, the contract does nothing or rejects the call.
  7. Record the outcome. Every node runs the same code and reaches the same result, so all copies of the ledger stay in sync.
Real-life analogy: A vending machine is a contract built from metal and buttons. You insert the right coins and press A3; the machine gives you the snack without asking a shopkeeper. The rule is fixed, the machine checks the payment itself, and the same action always gives the same result.
Common confusion: A smart contract is not a lawyer and does not understand intent. It only does exactly what its code says. If the code has a bug, or the oracle sends bad data, the contract will still execute the wrong result.

The full answer, piece by piece

1. Definition

A smart contract is a program stored on a blockchain that automatically executes the terms of an agreement when predefined conditions are met. The code is immutable after deployment, and every node runs the same code and reaches the same result.

The term was coined by Nick Szabo in the 1990s. In Ethereum, a smart contract is a contract account with bytecode and persistent storage.

What this means: the contract is not a piece of paper stored in a safe. It is running software whose rules and history are copied across the network.

2. Properties

  • Self-executing: no manual step is needed to enforce the outcome.
  • Immutable: the code cannot be changed; a new version must be deployed.
  • Deterministic: the same inputs produce the same output on every node.
  • Transparent: anyone can read the code and the transaction history.
  • Permissionless: anyone can call a public function if they pay gas.
  • Composable: contracts can call other contracts, like building blocks that plug together.

3. Real-world example — flight-delay insurance (2025 May Q5b)

An insurer deploys a contract with a pool of ETH. Travellers pay a premium. The contract reads a trusted flight-status oracle. If the flight is delayed by more than 3 hours, the contract automatically pays the traveller; otherwise the premium stays in the pool.

traveller ── premium ──► [ Insurance contract ]
                                  │
                                  │ reads flight oracle
                                  ▼
                    delay > 3 hours ?
                     │              │
                    yes             no
                     │              │
                     ▼              ▼
             pay traveller      keep premium
             (no claim form)    (pool grows)

What this means: the payout rule is visible before anyone buys the policy, and the money moves as soon as the trusted data confirms the delay.

Benefits in this scenario: instant payout, no claim paperwork, no adjuster, transparent rules, no selective denial, and the pool is auditable.

4. Benefits and challenges

BenefitsChallenges
Disintermediation: removes brokers and escrow agents.Immutability: a bug cannot be patched; a new contract is needed.
Near real-time settlement: payment on the trigger event.Oracle problem: bad external data gives a wrong outcome.
Transparency: rules and history are visible to all.Privacy: public code and state expose business logic.
Lower cost: less paperwork, audit and manual processing.Legal uncertainty: enforceability varies by country.
Accuracy: exact code execution, no human discretion.Bugs: the 2016 DAO hack drained ~$50M of ETH.

What this means: smart contracts are strongest when the rule is simple, the outside data is trustworthy, and the cost of a wrong result is understood before deployment.

5. Role of gas (the second half of 2025 May Q5b)

Gas is the unit that measures computational work on Ethereum. Every opcode, which is one low-level instruction, has a fixed gas cost. The sender pays:

Transaction fee = gas used × gas price
gas price = base fee + priority fee (tip)

What this means: gas is the fuel meter. A bigger or busier computation burns more fuel, and the fee is the fuel bill.

  • Prevents infinite loops: execution stops when gas runs out (out-of-gas), so a stuck program cannot freeze the chain.
  • Pays validators: the fee compensates the nodes that execute and include the transaction.
  • Allocates scarce blockspace: users bid more when many people want their transactions included.
  • Punishes spam: every computation has a real cost.
  • Refund: unused gas is returned; a reverted transaction still pays for the work done.

Worked example: a contract call uses 50,000 gas at 30 gwei. A gwei is one billionth of an ETH. Fee = 50,000 × 30 = 1,500,000 gwei = 0.0015 ETH. At $3,000 per ETH that is $4.50. The same call at 100 gwei costs 5,000,000 gwei = 0.005 ETH = $15.00.

What this means: the readable Solidity file is only the recipe. The blockchain stores the compiled bytecode, and users reach it through its address plus the ABI.

7. Important limitation

A contract cannot fetch data from the internet by itself. It needs an oracle (for example Chainlink or API3) to bring off-chain data on-chain. This is the “oracle problem”.

5.1 What is Ethereum?

Q1What is Ethereum? Explain in detail how it differs from traditional cryptocurrencies. Enlist the features of Ethereum.

8 / 6 / 9 marks★★★★★ 5×Unit 5

Asked in: 2022 Nov Q5(a) [8] · 2023 Nov Q5(a) [6 — with types] · 2024 May Q5(a) [8] · 2025 May Q5(a) [9 — features + networks] · 2025 Nov Q5(a) [8]

In simple words: Ethereum is a blockchain that can run programs, not just record payments. It is like a world computer that anyone can use by paying a small fee. Developers build apps on it, and its own money, ether, pays for the computing work.

Why we do this

Bitcoin proved that money could move without a bank. Ethereum asked a bigger question: what if the same shared ledger could also run agreements and applications? That lets many people use one trustworthy computer instead of each company building its own private server and asking everyone to trust it.

Words you need first

  • Ethereum: an open-source blockchain platform that stores data and runs smart contracts.
  • Blockchain: a shared record book copied across many computers, where past entries are very hard to change.
  • Smart contract: a program on the blockchain that runs automatically when its conditions are met.
  • EVM (Ethereum Virtual Machine): the engine that executes contract code on every Ethereum node.
  • dApp: a decentralised application whose backend logic is a smart contract.
  • Ether (ETH): Ethereum’s native cryptocurrency, used to pay fees and to stake.
  • Gas: the unit that measures computational work; the fee is paid in ETH.
  • Wei: the smallest unit of ETH; one ETH equals 1018 wei.
  • Gwei: one billion wei, a common unit for quoting gas prices.
  • Account: an entry on Ethereum that can hold ETH, and may also hold code and storage.
  • EOA (externally owned account): an account controlled by a private key, with no contract code.
  • Contract account: an account that holds code and storage and runs only when called.
  • Proof of Stake (PoS): a way to secure the chain where validators lock ETH as a deposit.
  • Validator: a computer that checks transactions and proposes or votes on blocks.
  • Staking: locking ETH to help secure the network and earn rewards.
  • Turing-complete: able to express any computation, given enough time and resources.
  • UTXO: “unspent transaction output”, Bitcoin’s way of tracking money as coins rather than balances.
  • Token: a digital asset created by a contract on top of Ethereum.
  • ERC-20 / ERC-721: common token standards for fungible coins and unique NFTs.
  • DAO: a decentralised autonomous organisation run by code and token voting.
  • Nonce: a counter that stops the same signed transaction from being replayed.
  • Layer 2: a separate network built on top of Ethereum to make transactions cheaper and faster.
  • DeFi: decentralised finance, where lending and trading run through smart contracts instead of banks.
  • NFT: a unique token that proves ownership of a specific digital or physical item.
  • ENS: a naming service that turns a long blockchain address into a readable name.

Step-by-step

  1. Someone sends a transaction. A user signs a request with a private key, for example “send 1 ETH” or “call this contract function”.
  2. The transaction goes to the network. Nodes check the signature, the balance and the fee.
  3. A validator includes it in a block. The validator orders transactions and proposes the next block.
  4. The EVM runs the code. If the transaction calls a contract, every node runs the same bytecode with the same inputs.
  5. The state changes. Balances, contract storage and account data are updated in the same way on every node.
  6. The block is added. Other validators attest to it, and the change becomes part of the shared history.
  7. Users read the result. A dApp reads the blockchain or listens for events, and shows the new state.
Real-life analogy: Ethereum is a world computer anyone can rent by the instruction. The EVM is its engine, gas is the fuel, ETH is the money in the meter, and a smart contract is an app running on that computer.
Common confusion: Ethereum is not “just another coin”. ETH is the fuel of the platform; the platform itself is the computer that runs contracts. Bitcoin is mainly digital money, while Ethereum is a programmable environment for apps.

The full answer, piece by piece

1. Definition

Ethereum is an open-source, decentralised, programmable blockchain platform. It runs smart contracts on the Ethereum Virtual Machine (EVM) and lets developers build decentralised applications (DApps). It was proposed by Vitalik Buterin in 2013; the first live version, Frontier, was released in 2015.

Its native currency is ether (ETH). Ether pays for computation (gas) and secures the network through staking.

What this means: Ethereum is both a ledger and a computer. The ledger records what happened; the computer runs the rules that decide what happens next.

2. Brief history

What this means: the project started as an idea, became a live chain in 2015, survived a major split in 2016, and cut its energy use dramatically by moving to proof of stake in 2022.

5. Ether, gas and accounts

  • 1 ETH = 1018 wei; 1 gwei = 109 wei.
  • EOA: controlled by a private key, has a balance and nonce, and no code.
  • Contract account: has code and persistent storage, no private key, and runs only when called by a transaction.
  • Transaction fee = gas used × (base fee + priority fee). A plain ETH transfer uses 21,000 gas.

6. Worked gas example

A user sends ETH with a gas price of 20 gwei. Gas used = 21,000.

Fee = 21,000 × 20 gwei = 420,000 gwei = 0.00042 ETH

If ETH = $3,000, the fee is 0.00042 × 3,000 = $1.26. A complex DeFi swap may use 150,000 gas, so the same gas price costs 150,000 × 20 = 3,000,000 gwei = 0.003 ETH = $9.00.

What this means: gas price is the price per unit of work, and gas used is the amount of work. Multiply the two to get the fee.

7. Real-world applications

  • DeFi: lending, borrowing, stablecoins and decentralised exchanges.
  • NFTs: digital art, tickets and memberships.
  • DAOs: community treasuries and voting.
  • Supply chain: provenance and tracking.
  • Identity: ENS names and verifiable credentials.
  • Voting and agreements: transparent, tamper-resistant records.
One-line answer: “Bitcoin is digital gold; Ethereum is a world computer.” Ethereum adds a Turing-complete VM, accounts, gas and tokens on top of a blockchain.

5.2 Ethereum networks

Q2Identify two types of Ethereum networks and explain the purpose of each. Compare Ethereum Mainnet, Testnet and Private networks.

9 / 6 marks★★★★ 4×Unit 5

Asked in: 2023 Nov Q5(a) [6 — types of Ethereum] · 2024 May Q5(b) [9 — two types] · 2025 May Q5(a) [9, part — Mainnet/Testnet/Private] · 2025 Nov Q5(b) [9 — two types]

In simple words: Ethereum is not one chain but a family of chains. Mainnet is the real one that handles real money, like the final exam. Testnet is a free practice chain, like a mock exam. Private networks are company-only chains, like a private exam room.

Why we do this

A developer cannot test dangerous code on the real chain, because a bug could destroy real money and a deployed contract cannot be edited. Separate networks let people practise, experiment and run private business systems without touching Mainnet funds.

Words you need first

  • Network: a set of computers running the same blockchain rules and sharing the same history.
  • Mainnet: the live production Ethereum network, where ETH has real value.
  • Testnet: a public practice network that uses free test ETH with no real value.
  • Private network: a separate Ethereum-compatible chain controlled by one organisation or a group.
  • Chain ID: a number that identifies a chain so a wallet cannot send a transaction to the wrong one.
  • Faucet: a website or service that gives free test ETH on a testnet.
  • Validator: a computer that checks transactions and helps produce blocks.
  • Permissioned: only approved organisations or users may join and validate.
  • Consortium: a group of organisations that share control of a network.
  • PoA (Proof of Authority): a consensus method where approved identities, not open competition, produce blocks.
  • PoW (Proof of Work): a consensus method where computers compete to solve a puzzle and win the right to add a block.
  • IBFT: a family of Byzantine-fault-tolerant consensus methods used in permissioned chains.
  • Raft: a consensus method that keeps copies in sync when nodes may crash but are not malicious.
  • Gas: the fee for computation; on Mainnet it costs real ETH.
  • EVM: the Ethereum Virtual Machine, the engine that runs contract code on all these chains.
  • Contract deployment: publishing a contract so it gets a permanent address on a chain.

Step-by-step

  1. Build on a local chain. The developer runs a private test chain on their own laptop for fast, free experiments.
  2. Test on a public testnet. They deploy to a testnet such as Sepolia, using free test ETH from a faucet, to check behaviour with other users and tools.
  3. Audit and fix. Testers look for bugs, and auditors review the code before real money is involved.
  4. Choose a production chain. A public app usually goes to Mainnet; an enterprise app may go to a private or consortium chain.
  5. Deploy with the right chain selected. The wallet must show the correct chain ID, because the same address can exist on several chains.
  6. Verify and monitor. The team publishes the source code and watches gas costs, errors and upgrades.
Real-life analogy: Mainnet is the real driving test on a public road. A testnet is the practice track where mistakes cost nothing. A private network is a company’s own closed test track, with its own rules and guards at the gate.
Common confusion: Testnet ETH looks like ETH and uses a similar address, but it has no money value and cannot be spent on Mainnet. Sending real ETH to a testnet address, or the reverse, usually means the funds are lost.

The full answer, piece by piece

1. Mainnet

Mainnet is the live, production Ethereum blockchain. It uses real ETH, has real economic value and is secured by hundreds of thousands of validators. Chain ID = 1. All deployed contracts on Mainnet cost real gas and are permanent.

  • Purpose: real payments, DeFi, NFTs and production DApps.
  • Risk: bugs cost real money; gas is expensive during congestion.

What this means: Mainnet is the chain you use when the app is ready for real users and real value.

2. Testnet

A testnet is a separate public Ethereum network that behaves like Mainnet but uses free test ETH with no real value. Developers deploy and test contracts there before Mainnet.

  • Purpose: testing, debugging, audits and CI pipelines.
  • Faucets: free test ETH from a faucet.
  • Examples: Sepolia (current PoS testnet), Goerli (deprecated), and historically Ropsten (PoW), Kovan and Rinkeby (PoA).
  • Chain IDs: Sepolia = 11155111; Goerli = 5.

What this means: a testnet is a full rehearsal. The code, wallets and tools are the same, but the money is fake.

3. Private network

A private Ethereum network runs the same EVM but is not connected to Mainnet. One organisation or a consortium controls the validators. It can be permissioned and can use a custom chain ID and consensus (IBFT, Clique PoA, Raft).

  • Purpose: enterprise pilots, internal ledgers, privacy and zero gas cost.
  • Examples: GoQuorum (J.P. Morgan), Hyperledger Besu private and Geth private.
  • Risk: you must secure and govern it yourself; there is no public security budget.

What this means: a private chain gives a company control and privacy, but it also gives the company all the security work.

5. “Two types” short answer (2024 / 2025 Nov)

If the paper asks for two, write Mainnet and Testnet: Mainnet is the live chain with real ETH; Testnet is an identical but valueless chain for testing. Add one line: “A third type, the private network, is used by enterprises and is permissioned.”

6. ETH vs ETC (if “types of Ethereum” means the fork)

Never send real ETH to a testnet address (or vice versa). The addresses look the same, but the funds are on different chains and are lost.

5.7 Swarm — decentralized storage

Q7Discuss Swarm, the decentralized storage platform. How does Swarm contribute to decentralized storage in the Ethereum ecosystem?

4 / 6 / 9 marks★★★★ 4×Unit 5

Asked in: 2022 Nov Q5(c) [4] · 2023 Nov Q5(b) [6] · 2024 May Q6(b) [9] · 2025 Nov Q6(b) [9]

In simple words: Swarm is Ethereum’s shared hard drive. It stores large files off the blockchain, across many computers. The blockchain keeps only a small fingerprint, called a hash, which proves the file is the right one.

Why we do this

Putting a photo, video or whole website on Ethereum would be extremely expensive, because every node would copy it forever. Swarm keeps the heavy data outside the chain but still on a peer-to-peer network, so a dApp can be complete without renting a central server that one company can switch off.

Words you need first

  • Swarm: Ethereum’s peer-to-peer storage network for large files.
  • Decentralised storage: files spread across many independent computers instead of one company’s server.
  • Off-chain: kept outside the blockchain itself, usually with only a hash on-chain.
  • Chunk: a small fixed-size piece of a file; Swarm cuts files into chunks of at most 4 KB.
  • Hash: a short digital fingerprint of data; change the data and the hash changes.
  • P2P (peer-to-peer): computers talking directly to each other without a central server.
  • Node: one computer participating in the storage network.
  • ENS (Ethereum Name Service): a naming system that maps a readable name to a blockchain address or hash.
  • Incentive layer: the payment rules that reward nodes for storing data and serving it.
  • dApp: a decentralised application whose rules run on smart contracts.
  • IPFS: another content-addressed storage network, not tied to Ethereum.
  • IPNS: IPFS’s naming system for pointing a stable name at changing content.
  • Pub/sub (publish–subscribe): a messaging pattern where a sender posts to a topic and every subscriber to that topic receives it.
  • Pinning: asking an IPFS node to keep a copy of a file so it stays available.
  • Geth: a popular Ethereum node client that Swarm can work with.
  • BZZ: the accounting token used inside the Swarm network.
  • Content integrity: proof that the file you received is exactly the file that was stored.

Step-by-step

  1. Split the file. Swarm cuts it into chunks of at most 4 KB, because small pieces are easier to distribute and verify.
  2. Hash each chunk. Each chunk gets a 32-byte fingerprint, which also acts as its address.
  3. Build a root hash. The chunk hashes are combined into one root hash that represents the whole file.
  4. Spread the chunks. Nodes take responsibility for different chunks across the network.
  5. Pay for storage. The incentive layer rewards the nodes that keep the data available.
  6. Retrieve by hash. A user asks for the root hash; the network finds the chunks and rebuilds the file.
  7. Check integrity. The received chunks are hashed again. If a chunk was changed, its hash will not match.
Real-life analogy: Swarm is a shared hard drive run by a large library. A book is split into numbered pages, each page has a unique call number, and any branch can fetch the pages. The catalogue entry is the hash; the book itself is not kept in the catalogue.
Common confusion: Swarm does not store files inside the Ethereum blockchain. The blockchain stores a hash or reference; the file lives off-chain on Swarm. The hash is not encryption either — it proves integrity, not secrecy.

The full answer, piece by piece

1. Definition

Swarm is Ethereum’s decentralised storage platform. It stores large data — DApp front-ends, images, NFT metadata and documents — off-chain across a peer-to-peer network. It is one of the three pillars of Web3: Ethereum contracts (logic), Swarm (storage) and Whisper (messaging).

What this means: contracts decide, Swarm stores, and Whisper talks. Together they cover the three basic jobs of an application.

2. Why it is needed

  • Storing large data on-chain is extremely expensive, because every node replicates it forever.
  • DApps need a place for front-end files and media.
  • Centralised servers create a single point of failure and censorship.
  • IPFS does not guarantee that content stays available unless some node keeps serving it.

What this means: Swarm solves the “where do the big files live?” problem without handing control back to one cloud provider.

3. Architecture

  1. A file is split into chunks of at most 4 KB.
  2. Each chunk is hashed; the 32-byte hash is its address.
  3. Chunks are distributed across the P2P network; nodes store the chunks they are responsible for.
  4. To retrieve a file, the user asks for the root hash; the network resolves the chunks.
  5. ENS maps a human-readable name to the hash.
  6. An incentive layer pays node operators for storage and bandwidth.

  • DApp hosting: front-end HTML, CSS and JavaScript can be served from Swarm, so the whole DApp is decentralised.

5.5 Types of smart contracts

Q5What is a smart contract? Explain / discuss its types. Discuss two types commonly used on the Ethereum platform.

8 / 6 / 9 marks★★★ 3×Unit 5

Asked in: 2022 Nov Q6(a) [8] · 2023 Nov Q5(c) [6] · 2025 May Q6(b) [9 — two types + deployment]

In simple words: Smart contracts are grouped by the job they do. A smart legal contract enforces an agreement. A DAO runs an organisation. An application logic contract connects software or devices.

Why we do this

“Smart contract” is a broad label. A supply agreement, a club treasury and an IoT payment rule all use code, but they solve different problems and need different explanations. Grouping them by purpose makes the design choice clear in an exam answer or a real project.

Words you need first

  • Smart contract: a program on a blockchain that runs automatically when its conditions are met.
  • Smart legal contract: a contract whose legal terms are written in code and can be enforced by law.
  • DAO: a decentralised autonomous organisation, run by member votes and coded rules instead of a manager.
  • Quorum: the minimum number of votes or nodes needed before a decision is valid.
  • Governance token: a token that gives its holder voting power in a DAO.
  • Treasury: the shared pool of money controlled by an organisation.
  • ALC (Application Logic Contract): a contract that carries application-specific logic and connects other contracts or devices.
  • Oracle: a trusted data feed that brings outside facts onto the blockchain.
  • IoT (Internet of Things): everyday devices, such as sensors, that connect to a network and exchange data.
  • Escrow: money held by a neutral party until an agreed condition is met.
  • On-chain: recorded on the blockchain itself.
  • Proposal: a suggested action that DAO members vote on.

Step-by-step

  1. Ask what the contract is for. Is it enforcing a legal deal, running a group, or connecting software and devices?
  2. If it enforces a legal deal, use a smart legal contract. Write the obligations, the trigger and the remedy, and keep a legal wrapper so courts can enforce it.
  3. If it runs a group, use a DAO. Give members tokens, define who may propose, define the quorum, and let the contract hold the treasury.
  4. If it connects systems, use an ALC. Define the data source, the threshold and the action, then let the contract call other contracts or devices.
  5. Test the trigger. Feed normal, missing and malicious data to see whether the contract does the right thing.
  6. Deploy and monitor. Watch the events and the money flow, because the code cannot be quietly patched later.
Real-life analogy: Think of three machines in one building. A notarised rental agreement is the legal machine, a club’s shared bank account with online voting is the DAO machine, and a factory controller that reacts to a sensor is the ALC machine. All three are automatic, but they serve different purposes.
Common confusion: “Types of contracts” is not the same as “types of accounts”. Contracts are smart legal, DAO and ALC. Accounts are externally owned accounts (EOA) and contract accounts.

The full answer, piece by piece

The book classifies self-executing contracts into three types by application. For the 2025 paper, which asks for two, write the first two and mention the third.

1. Smart legal contracts

  • Legally enforceable contracts whose terms are written in code.
  • The parties are bound to perform; failure can trigger legal action.
  • Example: a supply contract that releases payment when delivery is confirmed by a trusted oracle.
  • Use: trade finance, escrow, insurance and employment agreements.

What this means: the code automates the mechanics, while the law still provides the ultimate backup if someone refuses to comply.

2. Decentralised Autonomous Organisations (DAOs)

  • A blockchain-based organisation whose rules and governance are coded into contracts.
  • Members hold governance tokens; proposals and votes are on-chain; the treasury is controlled by the contract.
  • Example: a DAO that funds open-source projects — members vote, and the contract releases funds automatically.
  • Use: investment clubs, protocol governance and community treasuries.

What this means: the organisation’s rulebook and bank account are the same contract, so spending follows the vote instead of a manager’s private decision.

3. Application Logic Contracts (ALCs)

  • Contracts that contain application-specific logic and stay in sync with other blockchain contracts.
  • They allow communication across devices — for example, IoT devices and blockchain.
  • Example: a contract that records sensor readings and triggers a payment when a threshold is crossed.
  • Use: IoT, supply chain and automated machine-to-machine workflows.

What this means: an ALC is the “glue” contract. It listens to data, applies business logic and tells another system what to do.

5.6 Solidity — implementation and deployment

Q6Explain Solidity in detail. Discuss how smart contracts are implemented using Solidity. Elaborate the basic steps involved in deploying a smart contract on the Ethereum blockchain.

6 / 9 marks★★★ 3×Unit 5

Asked in: 2022 Nov Q5(b) [6] · 2023 Nov Q6(c) [6] · 2025 May Q6(b) [9 — deployment steps]

In simple words: Solidity is the language used to write Ethereum smart contracts. A compiler turns Solidity into bytecode, the machine language of the EVM. The contract is then deployed in a transaction and gets its own address.

Why we do this

People cannot write raw EVM bytecode by hand for every agreement. Solidity gives them readable rules, variables and functions, while the compiler handles the low-level instructions. A clear deployment process then moves the code from a laptop to a live network without losing control of versions, keys or gas.

Words you need first

  • Solidity: a high-level programming language for Ethereum smart contracts, with syntax similar to JavaScript.
  • Compiler: a program that translates readable code into machine-level instructions.
  • solc: the standard Solidity compiler.
  • Bytecode: the compiled instruction set that the EVM executes.
  • ABI (Application Binary Interface): the public menu that tells an app which functions exist and what data they expect.
  • Pragma: a line that tells the compiler which Solidity version to use.
  • State variable: data stored permanently in the contract’s storage.
  • Function: a named block of code that performs an action or returns a value.
  • Modifier: a reusable check, such as “only the owner may call this”.
  • Event: a cheap log that a contract writes so outside apps can react.
  • Mapping: a key-value table inside a contract.
  • Payable: a function that is allowed to receive ETH.
  • Constructor: code that runs once, when the contract is first deployed.
  • require: a check that stops execution and reverts the transaction if the condition is false.
  • Reentrancy: an attack where a contract calls back into itself before the first call finishes, often to drain funds.
  • Integer overflow: a bug where a number grows past its maximum size and wraps around to a small value.
  • Etherscan: a block explorer that lets anyone read transactions, addresses and verified contract source code.
  • IDE: an integrated development environment, one app that combines an editor, compiler and debugger.
  • Gas: the fee for computation, paid in ETH.
  • Testnet: a free practice network used before Mainnet.
  • Mainnet: the live Ethereum network with real money.
  • Contract address: the permanent address that the network assigns to a deployed contract.
  • MetaMask: a wallet that signs transactions and selects a network.
  • Remix: a browser IDE for writing, compiling and deploying contracts.
  • Hardhat: a development environment for testing and deploying contracts from Node.js.

Step-by-step

  1. Write the contract. Create a .sol file, set a pragma, and define the state, functions and checks.
  2. Compile it. Run solc, Remix or Hardhat. The output is bytecode plus the ABI.
  3. Test it. Run it on a local chain or a testnet with fake ETH, and try normal, edge and malicious inputs.
  4. Audit it. Look for reentrancy, overflow, weak access control and oracle risk before real money is involved.
  5. Choose the network. Use a testnet for rehearsal and Mainnet only when the contract is ready.
  6. Deploy it. Send a contract-creation transaction with the bytecode. The network returns a contract address.
  7. Verify and interact. Publish the source on Etherscan, then call functions through the ABI and address.
Real-life analogy: Solidity is the recipe language, the compiler is the translator, bytecode is the kitchen’s internal instruction sheet, the ABI is the menu, and deployment is opening the restaurant at a fixed street address.
Common confusion: the blockchain does not store your readable Solidity file; it stores the compiled bytecode. The ABI is not secret and does not hold money — it is only the calling menu. Deploying is a real transaction, so it costs gas.

The full answer, piece by piece

1. Definition

Solidity is a high-level, statically typed, contract-oriented programming language for writing Ethereum smart contracts. Its syntax is similar to JavaScript, C++ and Java. It compiles to EVM bytecode using the solc compiler. It was created by Gavin Wood and is maintained as an open-source project.

What this means: Solidity is for humans; bytecode is for the EVM. The compiler is the bridge between the two.

2. Features

  • Contracts — like classes; contain state variables and functions.
  • State variables — stored permanently in contract storage.
  • Functions — public, private, internal, external; view/pure for reads.
  • Modifiers — reusable checks such as onlyOwner.
  • Events — cheap logs for off-chain apps.
  • Mappings, arrays, structs, enums — data structures.
  • Inheritance, interfaces, libraries — code reuse.
  • Payable — functions that can receive ETH.
  • Error handling — require, revert, assert; custom errors.
  • Pragma — compiler version directive.

3. A complete contract

// SPDX-License-Identifier: MIT
pragma solidity ^0.8.0;

contract SimpleStorage {
    uint256 private value;

    event ValueChanged(uint256 newValue);

    function set(uint256 x) public {
        value = x;
        emit ValueChanged(x);
    }

    function get() public view returns (uint256) {
        return value;
    }
}

What this means: value is stored on-chain, set changes it and emits a log, and get reads it without spending gas because it is a view function.

4. A supply-chain style contract

// SPDX-License-Identifier: MIT
pragma solidity ^0.8.0;

contract Shipment {
    enum Status { Created, InTransit, Delivered }

    address public owner;
    Status public status;

    constructor() {
        owner = msg.sender;
        status = Status.Created;
    }

    modifier onlyOwner() {
        require(msg.sender == owner, "not owner");
        _;
    }

    function ship() public onlyOwner {
        require(status == Status.Created, "bad state");
        status = Status.InTransit;
    }

    function deliver() public onlyOwner {
        require(status == Status.InTransit, "bad state");
        status = Status.Delivered;
    }
}

What this means: the contract can move from Created to InTransit to Delivered, but it cannot skip a step or let a stranger move it.

5. Implementation workflow

  1. Write the contract in a .sol file with a pragma.
  2. Compile with solc, Remix or Hardhat. Output = bytecode (deployable code) + ABI (function interface).
  3. Test on a local chain (Hardhat Network, Anvil, Ganache) or a testnet.
  4. Audit for reentrancy, overflow, access control and oracle risk.
  5. Deploy to the chosen network (see below).
  6. Verify the source on Etherscan so users can read it.
  7. Interact using the ABI and contract address.

5.8 Whisper — decentralized messaging

Q8List decentralized messaging platforms. Discuss Whisper and its purpose in the Ethereum ecosystem.

6 / 9 marks★★★ 3×Unit 5

Asked in: 2022 Nov Q6(b) [6] · 2023 Nov Q6(b) [6] · 2025 May Q6(a) [9 — list + purpose]

In simple words: Whisper is Ethereum’s private post office. It lets apps send encrypted messages directly to each other without a central chat server. Messages are temporary: they expire after a set time instead of staying on the blockchain forever.

Why we do this

Not every message belongs in a permanent, paid transaction. A chat message, a price quote or a notification should be private, cheap and temporary. Whisper gives dApps a way to talk peer-to-peer, so no company can read the traffic or shut down the server.

Words you need first

  • Whisper: Ethereum’s peer-to-peer messaging protocol for encrypted, temporary messages.
  • P2P (peer-to-peer): computers talking directly to each other without a central server.
  • Encryption: scrambling a message so only the intended reader can understand it.
  • Asymmetric encryption: uses a public key to lock a message and a private key to unlock it.
  • Symmetric encryption: uses one shared secret key for both locking and unlocking.
  • Public key: a shareable key that others use to encrypt a message for you.
  • Private key: the secret key that decrypts messages and signs transactions; never share it.
  • TTL (time-to-live): how long a message may stay in the network before it expires.
  • PoW (proof of work): a small computational puzzle that makes spam expensive.
  • RLPx: the transport protocol Ethereum nodes use to exchange data.
  • Node: one computer participating in the Ethereum or Whisper network.
  • dApp: a decentralised application whose rules are smart contracts.
  • Metadata: data about a message, such as timing or size, as opposed to its content.
  • Waku: a newer, more scalable messaging protocol that is replacing Whisper in many projects.
  • Gossip: passing a message from peer to peer until it spreads across the network.
  • Latency: the delay between sending a message and the receiver getting it.
  • Ephemeral: temporary; the data disappears after a set time instead of being kept forever.
  • OTC (over-the-counter): a private trade negotiated directly between two parties instead of on a public exchange.

Step-by-step

  1. Write the message. A dApp creates a short message, such as a chat line or a trade offer.
  2. Encrypt it. For one receiver, the sender uses the receiver’s public key. For a group, the sender uses a shared symmetric key.
  3. Attach a TTL and a small proof of work. The TTL limits lifetime, and the PoW makes bulk spam costly.
  4. Send it to peers. The message travels through the Whisper network using the same transport family as Ethereum nodes.
  5. Peers pass it on. Nodes relay the message without needing to read it.
  6. The receiver decrypts it. Only the holder of the matching private key can read the content.
  7. The message expires. After the TTL, nodes drop it, which limits storage and replay risk.
Real-life analogy: Whisper is a private post office. You seal a letter in an envelope that only the receiver can open, pay a small postage stamp in computing work, and the post office passes it along without reading it. After a set date, the post office destroys any copy it still holds.
Common confusion: Whisper is not a permanent chat history and not a storage system. It is for short-lived messages, not for files or real-time video. Swarm stores data; Whisper sends messages. Waku is the modern successor.

The full answer, piece by piece

1. Definition

Whisper is Ethereum’s decentralised messaging protocol. It lets DApps and nodes send encrypted peer-to-peer messages without a central server. It is the third pillar of Web3, alongside Ethereum contracts (logic) and Swarm (storage).

What this means: Whisper is the “talk” layer. It does not store files and does not run business rules; it moves private messages between peers.

  • No central server: no single point of failure or censorship.
  • Node discovery and signalling: peers can exchange control messages.

5.3 Ethereum Virtual Machine (EVM)

Q3Explain the Ethereum Virtual Machine in detail. What is the significance of the EVM?

4 / 6 marks★★ 2×Unit 5

Asked in: 2022 Nov Q6(c) [4] · 2023 Nov Q6(a) [6 — significance]

In simple words: The EVM is the engine that runs Ethereum programs. Every full node has its own copy of this engine. It executes the same bytecode with the same inputs, so every node reaches the same result.

Why we do this

A blockchain needs every computer to agree on what happened. If one node ran a contract on a fast gaming PC and another on an old laptop, they might get different results. The EVM removes that problem: it is a fixed, sandboxed machine with a fuel meter, so execution is identical everywhere and always stops.

Words you need first

  • EVM (Ethereum Virtual Machine): the software machine that executes Ethereum contract bytecode.
  • Virtual machine: a simulated computer that runs inside real computers, with its own rules and memory.
  • Bytecode: the low-level instructions that the EVM executes.
  • Opcode: one basic instruction, such as ADD or SSTORE.
  • Stack: a last-in-first-out workspace where the EVM keeps the values it is working on.
  • 256-bit word: the standard size of an EVM number, large enough for hashes and elliptic-curve maths.
  • State root: a single hash that summarises the entire Ethereum state at one moment.
  • Elliptic-curve cryptography: the maths behind Ethereum’s public and private keys and signatures.
  • Memory: temporary workspace that disappears after the call.
  • Storage: permanent key-value data kept by a contract between calls.
  • Program counter: a pointer that tracks which instruction to run next.
  • Gas: the fuel unit that pays for each opcode.
  • Sandbox: a closed environment where code cannot touch the host computer or other contracts’ data directly.
  • Deterministic: the same input always produces the same output.
  • State: the current data of all accounts and contracts.
  • REVERT: an instruction that undoes state changes but keeps the gas fee.
  • JVM (Java Virtual Machine): a general-purpose virtual machine that runs Java programs.

Step-by-step

  1. Fetch. The EVM reads the next opcode at the program counter.
  2. Decode. It works out what the instruction means and which values it needs.
  3. Check gas. It verifies that enough gas remains, then deducts the opcode’s fixed cost.
  4. Execute. It performs the operation and writes the result to the stack, memory or storage.
  5. Advance. The program counter moves forward, and the cycle repeats.
  6. Stop or roll back. On STOP or RETURN, the state is committed. On REVERT or out-of-gas, state changes are undone but the gas already used is kept.
Real-life analogy: The EVM is a locked calculator with a fuel meter. You insert a program card, it performs one instruction at a time, and it shuts down when the fuel runs out. It cannot open the desk drawer or talk to the room outside; it can only calculate and update its own notebook.
Common confusion: the EVM is not a physical chip or a separate blockchain. It is software that every node runs. It is also not “Turing-complete with no limits”: gas puts a hard limit on every execution, which is why it is often called quasi-Turing-complete.

The full answer, piece by piece

1. Definition

The EVM is the runtime environment of Ethereum. It is a stack-based, deterministic, sandboxed virtual machine that executes smart-contract bytecode on every full node. It is the part of Ethereum that turns a transaction into a state change.

What this means: a transaction is a request; the EVM is the worker that carries it out and updates the shared record.

2. Key properties

  • Quasi-Turing-complete: it can compute anything, but every opcode costs gas, so execution always halts.
  • 256-bit word size: matches the hash and elliptic-curve arithmetic used by Ethereum.
  • Stack-based: up to 1024 items; push and pop operations.
  • Deterministic: the same code, input and state give the same output on every node.
  • Sandboxed: a failed call reverts its state changes; only gas is consumed.
  • Single-threaded: contracts execute one after another, not in parallel.
  • No system calls or hardware access: it is a pure computation machine.

3. EVM architecture

┌─────────────────────────────────────────────────────────┐

What this means: code is fixed, stack and memory are for current work, storage survives between calls, and gas is checked at every step.

4. Execution cycle

  1. Fetch the next opcode at the program counter.
  2. Decode it and read operands from the stack.
  3. Check that enough gas is available; deduct the opcode’s gas cost.
  4. Execute the operation; write the result to stack, memory or storage.
  5. Increment the program counter and repeat.
  6. On STOP or RETURN, commit state. On REVERT or out-of-gas, roll back state and keep the gas fee.

What this means: the EVM is small on purpose. It has arithmetic, data movement, storage, jumps, calls and logging — enough to build contracts, but not enough to touch the outside world directly.

6. Significance (6-mark answer)

  • Portability: one contract runs identically on every node and every EVM-compatible chain.
  • Determinism: all nodes compute the same state root, which is necessary for consensus.
  • Safety: gas bounds execution, so a malicious contract cannot loop forever.
  • Isolation: sandboxing protects the host node from the contract.
  • Programmability: it is the engine behind DeFi, NFTs, DAOs and tokens.
  • Standardisation: Solidity, Vyper and tooling target the same bytecode, creating a large ecosystem.

7. EVM vs JVM (one line)

The JVM virtualises a general-purpose computer for Java and Scala; the EVM virtualises only a deterministic calculation and storage machine for smart contracts, with gas metering and no OS or hardware interface.

What this means: the JVM is built to run many kinds of applications; the EVM is deliberately narrow so that every node can agree on the result.
