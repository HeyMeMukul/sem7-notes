5.1 Automation testing fundamentals

Syllabus: What is automation testing, automated testing process, automation frameworks, benefits, how to choose automation testing tools.

Q1What is automation testing in software testing? Explain in brief. / Explain it with an example.

6 marks★★ 2×

Asked in: 2023 May Q5(a) [6] · 2024 May Q6(a) [6]

Definition: Automation testing uses software tools and scripts to execute test cases, compare actual and expected results, and report outcomes — with little or no manual intervention. The tester designs the test; the tool runs it repeatedly.

1. How it works

  1. Select the test cases that are stable, repetitive and high-risk.
  2. Choose a tool (Selenium, JMeter, TestNG, Appium, etc.).
  3. Write or record a script with input data and assertions.
  4. Run the script manually, on a schedule, or from CI after every build.
  5. Compare actual vs expected; log pass/fail and defects.
  6. Maintain the scripts when the application changes.

2. Example — login with 100 user records

A data-driven Selenium script reads 100 username/password pairs from an Excel file, enters them on the login page, clicks Submit, and asserts the expected page title for each row. The report shows 97 pass and 3 fail in 4 minutes. Manually this would take about 2 hours.

3. What can be automated

TypeTool exampleGood candidate?
Unit testsJUnit, TestNG, PyTestYes — fast and stable
API testsRest Assured, Postman, SoapUIYes — less UI flakiness
UI / regressionSelenium WebDriver, Playwright, CypressYes — repetitive flows
PerformanceJMeter, LoadRunnerYes — needs many virtual users
MobileAppiumYes — device matrix
Exploratory / usability—No — needs human judgement

Not everything should be automated: one-off tests, rapidly changing screens and tests that need human look-and-feel judgement are better manual.

Q3Identify / list and explain different benefits of Automation testing.

6 marks★★★★ 4×

Asked in: 2022 Nov Q6(b) [6] · 2023 May Q6(a) [6] · 2024 May Q5(b) [6] · 2025 Nov Q5(a) [6]

  1. Speed: a suite that takes days manually runs in minutes or hours. This shortens the release cycle.
  2. Repeatability: the same script runs exactly the same way every time, removing human variation.
  3. Wider coverage: data-driven scripts test hundreds of input combinations, browsers and devices.
  4. Parallel execution: Selenium Grid or cloud grids run tests on many machines at once.
  5. 24×7 execution: scheduled runs at night or on every commit; no tester overtime.
  6. Regression safety: old features are checked after every change, catching side effects early.
  7. Accurate reporting: tools produce pass/fail logs, screenshots, videos and trend dashboards.
  8. Long-term cost saving: high setup cost is recovered after repeated regression cycles; rework and production defects fall.
  9. CI/CD support: automated gates decide whether a build can move to the next stage (DevOps).
  10. Better use of people: testers spend time on exploratory and usability testing instead of repeating steps.

Limitations (write one line for balance)

High initial cost, tool licensing, script maintenance, flaky UI tests and inability to judge look-and-feel. Automation does not replace manual testing; it complements it.

ROI rule of thumb: automate a test if it will run at least 5–10 times and the application is stable.

Q4Construct / explain / illustrate the different automated testing process (with neat diagram).

6 marks★★★★★ 5×

Asked in: 2022 Nov Q5(c) [6] · 2023 May Q6(b) [6] · 2023 Nov Q6(a) [6] · 2024 May Q6(b) [6] · 2025 Nov Q5(c) [6]

Definition: The automated testing process (Automated Test Life Cycle, ATLC) is the sequence of activities used to decide what to automate, build the scripts, run them and maintain them.

1. Diagram (draw this)

1 Decide scope & ROI
        │
        ▼
2 Select tool & design framework
        │
        ▼
3 Create test scripts + test data
        │
        ▼
4 Execute (manual / CI / schedule)
        │
        ▼
5 Analyse results & log defects
        │
        ▼
6 Maintain scripts & reports
        │
        └──── feedback to step 1

2. Steps in detail

  1. Decide scope and ROI: list candidate tests; choose stable, repetitive, high-risk cases. Estimate manual effort vs automation effort.
  2. Select the tool: check application technology, browser/device support, language, budget, reporting and integration (see Q6).
  3. Design the framework: choose linear, modular, data-driven, keyword-driven or hybrid; define folder structure, naming, object repository, assertions and reporting.
  4. Create scripts and data: record or code the steps; separate test data from logic; use version control. Example: Selenium + TestNG + Excel data.
  5. Execute: run locally, on a schedule, or from Jenkins/GitHub Actions after every build. Use parallel runs where possible.
  6. Analyse and report: compare actual vs expected; capture screenshots/logs; raise defects; publish pass rate and coverage.
  7. Maintain: update locators, data and scripts when the UI or requirements change; remove obsolete tests. Maintenance is the largest long-term cost.

3. Example

A retail project automates 120 regression cases. Selenium scripts run nightly on Grid (Chrome, Firefox, Edge). The report shows 116 pass, 4 fail; two are real defects, two are broken locators. The team fixes locators and logs the defects — then repeats the cycle next build.

If asked “construct”, draw the six boxes and label the feedback arrow. That alone earns 2 marks.

Q6How to choose an Automation tool / automation testing tools? Explain briefly.

6 marks★★ 2×

Asked in: 2023 Nov Q5(a) [6] · 2025 May Q6(b) [6]

Tool selection is a cost-benefit decision, not a popularity contest. Check these criteria:

CriterionQuestions to askWhy it matters
Application technologyWeb, mobile, desktop, API, mainframe?A web tool cannot test a native desktop app.
Platform supportWhich browsers, OS versions, devices?Coverage of the real user matrix.
Scripting skillDoes the team know Java/Python? Is codeless needed?Wrong skill match slows the project.
Licensing and costOpen source or paid? Per-seat or per-parallel-run?Total cost includes training and maintenance.
Object recognitionCan it identify dynamic elements, iframes, shadow DOM?Reduces flaky tests.
IntegrationJIRA, Jenkins, Git, test-management, cloud grid?Fits the existing DevOps pipeline.
Reporting and debuggingScreenshots, logs, video, dashboards, retries?Faster failure analysis.
Parallel and distributed runsCan it run on multiple machines?Cuts regression time.
Vendor support and communityDocs, training, active forum, paid support?Reduces risk and onboarding time.
Maintenance effortHow often do locators/scripts break?Long-term cost driver.

Selection method

  1. List must-have and nice-to-have criteria.
  2. Give each criterion a weight (e.g. technology 25%, cost 20%, skills 15%).
  3. Score 2–3 shortlisted tools in a table.
  4. Run a proof of concept (POC) on 10–20 real test cases.
  5. Compare effort, stability and cost; then buy/licence.

Example: a Java web team with Jenkins chooses Selenium WebDriver + TestNG (open source, strong Java support, Grid); a mobile team chooses Appium; an API team chooses Rest Assured/Postman.

Q7Illustrate Selenium tool suite in detail.

6 marks★★★ 3×

Asked in: 2022 Nov Q6(a) [6] · 2023 Nov Q5(b) [6] · 2025 May Q5(b) [6]

Selenium is a free, open-source suite for automating web browsers. It supports Chrome, Firefox, Edge, Safari and others, and languages such as Java, Python, C#, Ruby and JavaScript.

1. Components

ComponentWhat it doesBest forLimitation
Selenium IDEBrowser extension that records and replays user actions; exports code.Quick prototypes, learning, simple smoke tests.No real programming; weak reporting; not for complex suites.
Selenium RCOlder “Remote Control” server; injects JavaScript into the browser; client libraries drive it.Legacy projects; browsers without native drivers.Slow, JavaScript-dependent, deprecated.
Selenium WebDriverSpeaks directly to the browser through its driver (chromedriver, geckodriver); W3C standard.All modern web automation and regression suites.Needs programming; no built-in reporting (use TestNG).
Selenium GridHub + nodes; runs tests in parallel on many machines, browsers and OS.Large cross-browser regression and CI.Setup and infrastructure cost.

2. Architecture

Test code (Java/Python)
        │
        ▼
Selenium client library  ──►  JSON / W3C protocol
        │
        ▼
Browser driver (chromedriver / geckodriver)
        │
        ▼
Real browser (Chrome / Firefox / Edge)

For Grid, the client sends the request to the Hub, which forwards it to a matching Node.

3. Version history (one line)

  • Selenium 1 = IDE + RC.
  • Selenium 2 = WebDriver merged with RC.
  • Selenium 3 = WebDriver only; RC deprecated.
  • Selenium 4 = W3C WebDriver, relative locators, CDP, Grid 4.

4. Example

WebDriver driver = new ChromeDriver();
driver.get("https://example.com/login");
driver.findElement(By.id("user")).sendKeys("admin");
driver.findElement(By.id("pass")).sendKeys("secret");
driver.findElement(By.id("login")).click();
Assert.assertEquals(driver.getTitle(), "Dashboard");
driver.quit();

Limitation of the suite: web only. It cannot test native mobile apps (use Appium) or desktop apps (use WinAppDriver/Tosca).

Q8Illustrate Selenium's IDE and explain in detail. (Also printed as “IQE” in some papers.)

6 marks★★★★★ 5×

Asked in: 2022 Nov Q4(b) [6] · 2022 Nov Q5(a) [6] · 2023 May Q5(b) [6, printed “IQE”] · 2025 May Q3(b) [6] · 2025 Nov Q6(c) [6, printed “IQE”]

Definition: Selenium IDE (Integrated Development Environment) is a record-and-playback tool for creating Selenium test cases without programming. It runs as a browser extension (Chrome/Firefox).

1. Main features

  • Record: captures clicks, typing, selection and navigation as commands.
  • Playback: re-runs the recorded script in the browser; failures are highlighted.
  • Selenese commands: open, click, type, select, assertText, verifyTitle, waitForElementPresent.
  • Test suites: groups several test cases and runs them in order.
  • Debugging: breakpoints, step execution, speed control and log pane.
  • Export: converts the script to Java/JUnit/TestNG, Python/Pytest, C# or Ruby for WebDriver.

2. How to use it (steps)

  1. Install the IDE extension and open it from the browser toolbar.
  2. Click Record, enter a base URL and perform the business flow.
  3. Stop recording; edit commands, add assertions and test data.
  4. Run the case; fix broken locators; add waits for dynamic elements.
  5. Save the suite; export to code if it must join the CI pipeline.

3. Example

Record a login: open /login → type id=user admin → type id=pass secret → click id=login → assertTitle Dashboard. Save as “ValidLogin”. Add a second case with a wrong password and assertText for the error message.

4. Advantages and limitations

AdvantagesLimitations
No programming needed; very fast to start.Not suitable for large, complex suites.
Good for learning Selenium commands and locators.Limited looping, branching and data-driven support (older versions).
Exports to WebDriver code.Weak reporting and integration; browser-specific.
Useful for quick smoke and bug-reproduction scripts.Recorded locators break easily; maintenance is high.

Verdict: use IDE for prototyping and simple checks; move to WebDriver + TestNG for real regression.

Q9How would you explain Selenium WebDriver? Explain it.

6 marks★★★ 3×

Asked in: 2022 Nov Q6(c) [6] · 2023 May Q5(c) [6] · 2025 May Q5(c) [6]

Definition: Selenium WebDriver is a browser-automation API that sends commands directly to a real browser through its native driver. It is the core of modern Selenium and follows the W3C WebDriver standard.

1. Architecture

Test script (Java/Python/C#)
        │  findElement, click, sendKeys
        ▼
Selenium client library
        │  W3C HTTP/JSON request
        ▼
Browser driver (chromedriver, geckodriver, msedgedriver)
        │  native browser automation
        ▼
Real browser + web page

2. Key features

  • Works with real browsers — no JavaScript injection into the page.
  • Supports locators: id, name, className, tagName, linkText, partialLinkText, CSS selector, XPath.
  • Handles alerts, frames, multiple windows, cookies, dropdowns, mouse and keyboard actions.
  • Supports headless mode and parallel execution through Grid.
  • Can take screenshots and execute JavaScript when needed.

3. Example

WebDriver driver = new FirefoxDriver();
driver.get("https://example.com");
WebElement search = driver.findElement(By.name("q"));
search.sendKeys("software testing");
search.submit();
System.out.println(driver.getTitle());
driver.quit();

4. WebDriver vs Selenium RC

PointWebDriverSelenium RC
CommunicationDirect to browser driver (W3C)Via RC server; JavaScript injection
SpeedFastSlow
Same-origin policyNot an issueWorkarounds needed
APIObject-oriented, modernOlder, method-heavy
StatusCurrent standardDeprecated

Limitation: no built-in test framework or reporting — pair it with TestNG/JUnit and a reporting library (Extent, Allure).

Q10What is Selenium RC? Explain in detail.

6 marks★ 1×

Asked in: 2023 Nov Q6(b) [6]

Definition: Selenium Remote Control (RC) was the original Selenium 1 tool. A Java server (Selenium Server) receives commands from a client library and drives the browser by injecting JavaScript into the page.

1. Architecture

Test program (Java/Python/Ruby)
        │  HTTP request
        ▼
Selenium RC Server (launches browser)
        │  JavaScript injection
        ▼
Browser + AUT (application under test)

2. How it works

  1. The client sends a command such as click(element) to the RC server.
  2. The server launches the chosen browser and opens the application.
  3. It injects a JavaScript “Selenium core” into the page.
  4. The JavaScript executes the command in the browser and returns the result.
  5. The client asserts the result.

3. Advantages

  • Supported many browsers and languages through one server.
  • Could run tests on a remote machine.
  • Worked when native drivers were not available.

4. Limitations

  • Slow — every command goes through JavaScript and HTTP.
  • Same-origin policy problems; needed a proxy.
  • JavaScript injection is blocked or behaves differently on some pages.
  • Cannot handle native OS dialogs, file uploads or complex mouse actions well.
  • Deprecated in Selenium 2 and removed in Selenium 3 — use WebDriver instead.

Exam line: RC = server + JavaScript injection; WebDriver = direct native driver. RC is history, but it is still asked to test whether you know the evolution.

Q11What do you understand by Selenium Grid? Explain it.

6 marks★★ 2×

Asked in: 2023 Nov Q6(c) [6] · 2025 May Q6(c) [6]

Definition: Selenium Grid is a distributed test-execution component of Selenium. It runs the same test suite in parallel on many machines, browsers and operating systems, controlled by a central Hub.

1. Architecture

          ┌────────────┐
          │    HUB     │  receives test requests
          └──┬───┬───┬─┘
             │   │   │
      ┌──────┘   │   └──────┐
      ▼          ▼          ▼
   Node 1     Node 2     Node 3
 Chrome/    Firefox/    Edge/
 Windows    Linux       macOS
  • Hub: central server; knows which nodes are free and matches the requested browser/OS.
  • Node: a machine with a browser and driver; registers with the hub and runs tests.
  • Desired capabilities: the requested browser name, version and platform.

2. How it works

  1. Start the hub: java -jar selenium-server.jar hub.
  2. Start nodes and register them with the hub URL.
  3. The test sends DesiredCapabilities (e.g. Chrome 120 on Windows 11).
  4. The hub queues the test and forwards it to a free matching node.
  5. Results return to the client; the node becomes free for the next test.

3. Benefits

  • Speed: 100 tests on 10 nodes finish in about one-tenth of the time.
  • Cross-browser/cross-OS coverage from one suite.
  • Better utilisation of machines; central management.
  • Scales by adding nodes; integrates with CI (Jenkins).

4. Limitations

Infrastructure and maintenance cost, network latency, node version drift, and flaky tests caused by shared environments. Grid 4 simplifies setup with a single jar and Docker support.

5.3 RPA and performance testing

Q12Explain Robotic Process Automation (RPA) in detail.

6 marks★★★★★ 5×

Asked in: 2022 Nov Q5(b) [6] · 2023 May Q6(c) [6] · 2023 Nov Q5(c) [6] · 2025 May Q6(a) [6] · 2025 Nov Q6(b) [6]

Definition: Robotic Process Automation uses software bots to mimic human actions on a computer — clicking, typing, copying data, opening e-mail and reading files — to automate repetitive, rule-based business processes.

1. How RPA works

  1. Identify a high-volume, rule-based process (invoice entry, data migration, ticket triage).
  2. Record the human steps or design a workflow in an RPA tool.
  3. Add rules for decisions, exceptions and validation.
  4. Run the bot attended (human triggers) or unattended (scheduled/background).
  5. Monitor success rate, exceptions and time saved; improve the bot.

2. Types

  • Attended RPA: bot works alongside a human, triggered on demand (e.g. a call-centre agent's screen pop).
  • Unattended RPA: bot runs on a server at scheduled times without a human (e.g. nightly invoice processing).
  • Hybrid: a combination of both, often with human approval for exceptions.

3. Tools

UiPath, Automation Anywhere, Blue Prism, Microsoft Power Automate Desktop, WorkFusion.

4. Example — invoice processing

A bot reads invoices from an e-mail inbox, extracts the vendor, amount and PO number, checks the PO in the ERP, enters the invoice, and routes mismatches to a human. It processes 800 invoices per day with 99% accuracy.

5. Benefits and limitations

BenefitsLimitations
Low code; fast to deploy; works with existing UI.Brittle when the UI or document format changes.
Reduces manual effort and errors; runs 24×7.Not suitable for judgement-heavy or creative work.
Improves compliance and audit logs.Licensing and bot-maintenance cost.
Frees people for higher-value work.Security/governance risk if credentials are poorly managed.

6. RPA vs test automation

PointRPATest automation
GoalPerform a business processVerify software behaviour
AssertionsUsually none; it completes workCompares actual vs expected and fails
UsersOperations/business teamQA/test team
ExampleEnter 500 invoicesCheck that invoice entry validates amount

Q13What is Performance testing? Explain the uses of it as well.

6 marks★★★ 3×

Asked in: 2024 May Q5(c) [6] · 2025 May Q5(a) [6] · 2025 Nov Q5(b) [6]

Definition: Performance testing is a non-functional test that measures speed, responsiveness, throughput and stability of a system under a specified workload. It answers “how well”, not “does it work”.

1. Types of performance testing

TypeLoadPurpose
LoadExpected peakVerify SLA at normal busy load.
StressBeyond peak until failureFind breaking point and graceful degradation.
SpikeSudden increaseCheck recovery from a traffic burst.
Endurance / soakNormal load for hoursFind memory leaks and resource exhaustion.
VolumeLarge data setCheck DB and batch performance.
ScalabilityIncreasing users/nodesCheck whether capacity grows as expected.

2. Metrics

  • Response time — average and 95th percentile (p95).
  • Throughput — requests or transactions per second.
  • Error rate — failed requests ÷ total requests.
  • Resource use — CPU, memory, disk I/O, network, DB connections.
  • Concurrent users and think time.

3. Uses

  1. Validate SLAs/NFRs — “p95 < 2 s at 1,000 users”.
  2. Capacity planning — how many servers/users are needed for a launch.
  3. Find bottlenecks — slow query, memory leak, thread-pool limit.
  4. Compare versions/hardware — did the new release slow down?
  5. Test failover and recovery — behaviour when a node dies under load.
  6. Reduce production risk — avoid outages during sales or peak events.

4. Example

An online exam portal expects 10,000 students at 10:00 AM. JMeter ramps 0 → 10,000 users over 15 minutes, holds 60 minutes, and measures login, question load and submit. Result: p95 = 4.2 s against a 3 s target, with DB CPU at 98%. The team adds a read replica and retests.

Tools: Apache JMeter, LoadRunner, Gatling, k6, Locust.

Q14Describe Apache JMeter based on: (i) Aim/Purpose (ii) Working (iii) Advantages.

6 marks★ 1×

Asked in: 2024 May Q6(c) [6]

(i) Aim / purpose

Apache JMeter is a free, open-source, Java tool for load, stress, functional and performance testing of web applications, APIs, databases, FTP and JMS. It simulates many virtual users and reports response time and throughput.

(ii) Working

  1. Test Plan — the root container for the test.
  2. Thread Group — number of virtual users, ramp-up period and loop count.
  3. Samplers — the request type: HTTP Request, JDBC Request, SOAP, FTP.
  4. Config elements — CSV Data Set, HTTP Cookie Manager, headers, CSV of test data.
  5. Assertions — check response code, body or duration.
  6. Timers — think time between requests (constant, random, Gaussian).
  7. Listeners — view results tree, summary report, aggregate report, graphs.
Test Plan
 └── Thread Group (500 users, ramp 60 s, loop 10)
      ├── HTTP Cookie Manager
      ├── CSV Data Set (users.csv)
      ├── HTTP Request: POST /login
      ├── Response Assertion: code = 200
      └── Summary Report / Graph

(iii) Advantages

  • Free and open source; large community and plugins.
  • Cross-platform (Java) and supports many protocols.
  • GUI for test design plus CLI/non-GUI mode for heavy load.
  • Distributed testing (master + slaves) for very high load.
  • CI integration (Jenkins) and HTML dashboard reports.
  • Reusable test plans; CSV/data-driven testing.

Limitations: GUI mode is resource-heavy (use CLI), less accurate for complex browser-side JavaScript, and report customisation needs plugins.

Automation process (6 steps)

Scope/ROI → Tool → Framework → Scripts → Execute → Report/Maintain

Numbers and facts

  • JMeter: Java, open source, Thread Group = users, Sampler = request, Listener = report.
  • Grid: 100 tests / 10 nodes ≈ 10× faster.
  • RPA: attended vs unattended; UiPath, Automation Anywhere, Blue Prism.
  • ROI: automate tests that run 5–10+ times.
  • Performance metrics: p95 response, throughput, error rate, CPU/memory.

One-line differences

  • RPA vs test automation: does the work vs checks the work.
  • Load vs stress: expected peak vs beyond peak until failure.
  • Soak vs spike: long steady run vs sudden burst.
  • IDE vs WebDriver: record/playback vs programmable suite.
