5.1 Amortized analysis — the three methods

Q1Explain the methods of amortized analysis with a suitable example.

6–9 marks★★★★★ 5×

Asked in: 2022 Nov Q5(a) [10 — short notes on all three] · 2023 Nov Q5(a) [9 — aggregate] · 2024 May Q6(a) [8] · 2025 May Q6(a) [6] · 2025 Nov Q5(c) [6 — any two]

What is amortized analysis?

According to the book, amortized analysis means finding the average running time per operation over a worst-case sequence of operations. The average cost of a single operation is small when the average of the whole sequence is taken, even if one operation in that sequence is expensive. It therefore guarantees the time per operation in the worst case.

Average case vs amortized: average-case analysis averages over all possible inputs; amortized analysis averages over a sequence of operations and assumes a worst-case input. Amortized cost is not average-case cost.

The book gives three commonly used techniques, with one key formula:

Amortized cost of n operations = total cost of the n operations / n

1. Aggregate analysis

Analyse the whole sequence of n operations first. If the sequence takes worst-case time T(n), the amortized cost of each operation is:

T(n) / n
  • Stack with PUSH, POP and MULTIPOP: n operations cost at most 2n, because each object is pushed once and popped once → O(1) per operation.
  • k-bit binary counter: n INCREMENTs flip fewer than 2n bits → O(1) per increment.
  • The book points out that a sequence containing O(n) MULTIPOPs costs O(n²) in the loose worst case, but this bound is correct and not tight; the tight total is O(n).

2. Accounting method

Assign a different charge to each operation; this charge is its amortized cost. It may be more or less than the actual cost.

  • If amortized cost > actual cost, the difference is saved on a specific object as credit.
  • If amortized cost < actual cost, the stored credit is used up.
  • The total amortized cost must be an upper bound on the total actual cost, so total credit never becomes negative.
Amortized cost = actual cost + credit (deposited or used up)
Σ c′i ≥ Σ ci    and    total credit = Σ c′i − Σ ci ≥ 0

Stack example: charge PUSH 2, POP 0, MULTIPOP 0. The extra 1 from PUSH stays on the pushed object and pays for its later POP or MULTIPOP. Total for n operations is at most 2n, so the amortized cost per operation is 2.

Binary counter example: charge 2 for setting a bit to 1. Of this, 1 pays the actual set and 1 is credit on that bit; when the bit is reset to 0, the stored credit pays for the reset. Total is O(n).

3. Potential function method

This is similar to the accounting method, but the prepaid amount is potential “energy” attached to the whole data structure, not to individual objects. Let D0, D1, …, Dn be the data structure after each operation, ci the actual cost of operation i, and Φ(Di) its potential (a real number).

c′i = ci + Φ(Di) − Φ(Di−1)
Σ c′i = Σ ci + Φ(Dn) − Φ(D0)

Choose Φ(D0) = 0 and Φ(Di) ≥ 0. Then the amortized cost is an upper bound on the actual cost. A positive potential change means the operation was overcharged; a negative change means stored potential is discharged to pay for the operation.

  • Stack: Φ = number of elements. PUSH: ΔΦ = +1 → ĉ = 1 + 1 = 2. POP: ΔΦ = −1 → ĉ = 1 − 1 = 0. MULTIPOP of k′ elements: ΔΦ = −k′ → ĉ = k′ − k′ = 0.
  • Binary counter: Φ = number of 1 bits. If an INCREMENT resets t bits, actual cost = t + 1 and ΔΦ = 1 − t → ĉ = (t + 1) + (1 − t) = 2.

Comparison of the three methods

MethodIdeaBest used when
AggregateAnalyse the entire sequence first; amortized cost = total / nThe total cost of the sequence is easy to bound
AccountingAssign different charges; excess is stored as credit on objectsDifferent operations have very different actual costs
PotentialDefine a potential function Φ and prove it is a valid potentialA rigorous proof is needed; the structure has a natural “energy”
Key line for the examiner: amortized analysis averages over a sequence of operations, not over inputs — so it gives a worst-case guarantee, unlike average-case analysis.

5.2 Stack: PUSH, POP, MULTIPOP ★★★ 3×

Q1Explain amortized analysis using a stack with PUSH, POP and MULTIPOP. Find the amortized cost of each operation using all three methods.

9 marks★★★ 3×

Asked in: 2022 Nov Q6(a) [9] · 2023 Nov Q5(b) [9] · 2025 Nov Q6(a) [9]

Operations and actual costs

The book implements the stack as an array: PUSH does s[top] = item; top++; and POP does top--; item = s[top];. Both run in O(1). MULTIPOP is:

Algorithm multiple_pop(st, k)
while ((!stempty(st)) AND (k != 0))
{
    pop(st);
    k = k - 1;
}

It removes at most k elements. For a stack of size 8, removing 4 elements costs 4 pops.

OperationActionActual cost
PUSH(S, x)push x onto stack S1
POP(S)remove and return top element1
MULTIPOP(S, k)pop min(k, |S|) elementsmin(k, |S|)

MULTIPOP looks expensive: if the stack has n elements, one call can cost O(n). The book says a sequence of n operations containing O(n) such calls costs O(n²) in the loose worst case, but this is correct and not tight. The tight bound follows because each object can be popped only once: total pops = total pushes.

Method 1 — Aggregate analysis

Start with an empty stack and perform n operations. Each element is pushed at most once, so it can be popped at most once.

Total cost of n operations ≤ (number of pushes) + (number of pops) ≤ n + n = 2n
Amortized cost per operation = 2n / n = 2 = O(1)

Method 2 — Accounting method

Assign: PUSH = 2, POP = 0, MULTIPOP = 0.

  • PUSH: $1 pays for the actual push; the second $1 is stored as credit on the pushed object.
  • POP: uses the $1 credit stored on that object.
  • MULTIPOP: each popped object spends its own $1 credit.

Credits never go negative. Total amortized cost for n operations is at most 2n, so the amortized cost per operation is 2 = O(1).

Method 3 — Potential function method

Let Φ(S) = |S|, the number of objects in the stack. Φ(D0) = 0 and Φ(Di) ≥ 0. For MULTIPOP, let k′ = min(|S|, k).

OperationActual ciΔΦAmortized ĉi = ci + ΔΦ
PUSH1+11 + 1 = 2
POP1−11 − 1 = 0
MULTIPOP(k)k′ = min(k, |S|)−k′k′ − k′ = 0

The book's MULTIPOP line prints the potential change as k′; because k′ objects leave the stack, the change is actually −k′, which gives the stated amortized cost 0.

All three operations have amortized cost O(1).
Total for n operations = O(n), even though one MULTIPOP can cost O(n).
Common mistake: saying “MULTIPOP is O(n), so the sequence is O(n²)”. That is the worst-case per operation, not the amortized bound. The total is O(n) because each element is popped once.

5.3 Binary counter ★★ 2×

Q1Prove that the amortized cost per operation of a k-bit binary counter is O(1), using the aggregate method.

5–6 marks★★ 2×

Asked in: 2025 May Q5(a) [6] · 2025 Nov Q5(a) [5]

Setup

A k-bit binary counter is stored in an array B[0..k−1], with B[0] the least significant bit. INCREMENT flips a suffix of 1-bits to 0 and the next 0-bit to 1. The book's algorithm is:

Algorithm Increment(B[0..k-1])
i = 0
while ((i < length(B)) AND (B[i] = 1))
{
    B[i] = 0
    i = i + 1
}
if (i < length(B)) then
    B[i] = 1

The book's 8-bit example starts at 00000000. The costs of successive increments are 1, 2, 1, 3, 1, 2, 1, 4, 1, 2, 1, 3, 1, 2, 1, 5, giving a cumulative cost of 31 flips for 16 increments (Fig. 5.1.1).

Aggregate analysis

In n consecutive INCREMENT operations, count how often each bit flips:

Bit positionFlips everyNumber of flips in n increments
B[0] (LSB)1 operationn
B[1]2 operationsn/2
B[2]4 operationsn/4
B[3]8 operationsn/8
………
B[i]2i⌊n/2i⌋
T(n) = Σi=0k−1 ⌊n/2i⌋ < n · Σi=0∞ (1/2)i = 2n
Worst case for the sequence = O(n)
Amortized cost per INCREMENT = O(n)/n = O(1)

Potential method (alternative, for full marks)

Let Φ(Di) = bi, the number of 1-bits after the i-th increment. Suppose the i-th operation resets ti bits. Its actual cost is:

ci = ti + 1

If bi = 0, the operation resets all k bits, so bi−1 = ti = k. Otherwise bi = bi−1 − ti + 1. Hence bi ≤ bi−1 − ti + 1, and the potential change is:

Φ(Di) − Φ(Di−1) = 1 − ti
ĉi = ci + ΔΦ = (ti + 1) + (1 − ti) = 2

Since Φ ≥ 0 and Φ(D0) = 0, total amortized cost is an upper bound on total actual cost, so each operation is O(1) amortized.

Worst case vs amortized: a single INCREMENT can flip all k bits → O(k). But n increments cost O(n), so the amortized cost is O(1).

5.4 Tractable and intractable problems

Q1What are tractable and non-tractable (intractable) problems? Give examples.

6–7 marks★★★★ 4×

Asked in: 2022 Nov Q5(a) [part] · 2025 May Q5(b) [7] · 2025 Nov Q5(b) [6]

Tractable problem

The book defines a tractable problem as a problem that can be solved by a polynomial-time algorithm; its upper bound is polynomial.

Examples (book): (i) searching an unordered list, (ii) searching an ordered list, (iii) sorting a list, (iv) multiplication of integers, (v) finding a minimum spanning tree in a graph.

Intractable (non-tractable) problem

The book defines an intractable problem as a problem that cannot be solved by a polynomial-time algorithm; its lower bound is exponential.

Examples (book): (i) travelling salesman problem, (ii) knapsack problem.

PointTractableIntractable
Solvable in polynomial time?YesNo polynomial-time algorithm is known
Bound used by the bookUpper bound is polynomialLower bound is exponential
Book examplesSearching ordered/unordered list, sorting, integer multiplication, MSTTravelling salesman problem, knapsack problem

Why the difference matters

  • For a tractable problem, polynomial growth keeps the running time manageable as the input size increases.
  • For an intractable problem, the best known exact algorithms grow exponentially; even moderate n can be impossible.
  • Intractability is a worst-case asymptotic statement. Small instances of TSP or knapsack can still be solved exactly.
  • The book uses this distinction to motivate approximation algorithms in §5.5: for an NP-hard optimization problem, find a good solution quickly instead of the exact optimum.

📘 Book: §5.3 Introduction to Tractable and Non-tractable Problems, p. 5-12

Q2What are intractable problems? Does the Travelling Salesman Problem belong to this class? Justify.

6 marks★ 1×

Asked in: 2025 Nov Q5(b) [6]

Yes, TSP is intractable. The book's rule is: if the decision version of a combinatorial optimization problem is proved NP-complete, then its optimization version is NP-hard.

  • Decision TSP: “Is there a tour of length less than K?” A proposed tour can be checked in polynomial time, and Hamiltonian cycle reduces to it, so it is NP-complete.
  • Optimization TSP: “What is the shortest tour?” This is NP-hard. The book's Hamiltonian-cycle example makes the same point: the decision version (is there a cycle shorter than k?) is NP-complete, but the optimization version (what is the shortest cycle?) is NP-hard because it is not easy to decide whether the cycle obtained is the shortest.

No polynomial-time exact algorithm is known. Exhaustive search is O(n!), and the standard dynamic-programming solution (Held–Karp) is O(n²2n); both are super-polynomial.

But TSP is approximable. For Euclidean (metric) TSP, the book gives the twice-around-the-tree algorithm, a 2-approximation: compute an MST, walk around it by DFS, and remove duplicate visits. So exact TSP is intractable, but a near-optimal tour can be found in polynomial time.

📘 Book: §5.3 & §5.5.1 TSP, p. 5-12, 5-19 – 5-22

Q3Comment: "The problem of searching an ordered list or an unordered list belongs to the class of tractable problems."

4 marks★ 1×

Asked in: 2025 Nov Q6(c) [4]

The statement is true. The book lists both searching an unordered list and searching an ordered list as examples of tractable problems.

  • Unordered list: linear search scans up to n elements → O(n), which is polynomial.
  • Ordered list: binary search halves the interval each time → O(log n), which is also polynomial (and faster).

Since a polynomial-time algorithm exists for both, both belong to the tractable class. The ordered list is simply the easier of the two.

5.5 Randomized algorithms ★★★★★ 5×

Q1What are randomized algorithms? Enlist and explain the primary reasons for using randomized algorithms.

8 marks★★★★★ 5×

Asked in: 2022 Nov Q5(b) [8] · 2023 Nov Q6(c) [8] · 2024 May Q5(a) [8] · 2025 May Q6(c) [4] · 2025 Nov Q6(b) [4]

Randomized algorithm — book definition

A randomized algorithm uses a random number generator (randomizer) and takes each decision from the current random output, instead of following one fixed deterministic path. The book gives three properties:

  1. Execution time may vary from run to run.
  2. For different inputs there may be different outcomes on each execution.
  3. For the same input there may be different outcomes on each execution.

Probability background used by the book

  • An experiment has outcomes called sample points; the set of all sample points is the sample space S.
  • An event E is a subset of S; its probability is P(E) = |E| / |S|. For m sample points there are 2m possible events.
  • Two events are mutually exclusive if A ∩ B = ∅; they are independent if P(A ∩ B) = P(A) × P(B).
  • A random variable F maps sample points to real numbers; it is discrete if its set of values is finite. Example: pick 4 balls from an urn of red and white balls; F = number of red balls, so F(RRRW) = 3 and F(RWWW) = 1.
  • A probability distribution lists P[F = ai] for all values, and Σ P[F = ai] = 1. For the 4-ball example: P[0] = 1/16, P[1] = 4/16, P[2] = 6/16, P[3] = 4/16, P[4] = 1/16.

Two types of randomized algorithms (Fig. 5.4.1)

TypeBook definitionMeaningBook example
Las VegasProduces the same outcome on each execution for the same inputAlways correct; running time may varyRandomized algorithm for repeated elements
Monte CarloProduces different outcomes on each execution for the same inputMay be wrong with a small probability; usually fixed timeRandomized primality testing

In standard exam language: Las Vegas = correct answer, random time; Monte Carlo = fixed time, small probability of error. The book's defining test is the “same/different outcome” line above.

Book examples

  1. Repeated elements (Las Vegas). An array of n elements has n/2 distinct and n/2 duplicate values. A deterministic algorithm may need n/2 + 2 steps. The randomized algorithm Repeated(a,n) repeatedly picks two random indices i and j until i ≠ j and a[i] = a[j], then returns i. Each trial is O(1); the expected number of trials is O(log n), written Õ(log n).
  2. Primality testing (Monte Carlo). A composite n has a divisor ≤ ⌊√n⌋; testing all divisors from 2 to ⌊√n⌋ is the deterministic way. The randomized version uses Fermat's theorem an−1 ≡ 1 (mod n): pick a random a and test the congruence. If it fails, n is composite; if it holds, n is probably prime. It may return a wrong answer with small probability. It is used in cryptography.
  3. Randomized quicksort (Las Vegas). RANDOMIZED-PARTITION picks the pivot index uniformly at random, swaps A[r] with A[i], and then calls PARTITION. The rest of quicksort is unchanged. It avoids the fixed-pivot worst case; expected time is O(n log n).

Primary reasons for using randomized algorithms

The book lists two major advantages:

  1. Simple to implement — the random choice often removes complicated case handling. For example, RANDOMIZED-PARTITION adds only a random index and a swap to ordinary PARTITION.
  2. Many times more efficient than traditional algorithms — random sampling and random pivots often give better expected performance. The repeated-element search takes Õ(log n) instead of n/2 + 2 steps, and randomized quicksort has expected O(n log n) on any input.

Two further reasons follow directly from the book's examples:

  1. Avoiding an adversarial worst case — randomizing the pivot means no fixed input order can force quicksort's O(n²) partition pattern every time.
  2. Good solutions quickly for hard problems — for primality, random witnesses replace a long deterministic search; for duplicate detection, random sampling is much faster than scanning.

Drawbacks (book §5.4.3)

  • The small degree of error may be dangerous for some applications.
  • It is not always possible to obtain better results using a randomized algorithm.

Binomial random variable (mathematics for randomized analysis)

If X counts the number of successes in n independent trials, each with success probability p, then X is a binomial random variable, X ~ B(n,p):

P(X = k) = nCk pk (1−p)n−k,   E[X] = np,   Var(X) = np(1−p)

For a single trial, the indicator variable I is 1 on success and 0 on failure, with E[I] = p. Linearity of expectation, E[X+Y] = E[X] + E[Y], holds even when X and Y are dependent; this is the usual tool for analysing randomized algorithms. The book's 4-ball example is exactly a binomial distribution with n = 4 and p = 1/2: its probabilities 1/16, 4/16, 6/16, 4/16, 1/16 are the B(4, 1/2) values.

Q2Does the randomized algorithm for quicksort improve the average-case time complexity? Discuss.

4 marks★★ 2×

Asked in: 2025 May Q5(c) [4] · 2025 Nov Q6(b) [4]

The book's randomized quicksort

RANDOMIZED-PARTITION(A, p, r)
1  i = RANDOM(p, r)
2  exchange A[r] <-> A[i]
3  return PARTITION(A, p, r)

RANDOMIZED-QUICKSORT(A, p, r)
1  if p < r
2      q = RANDOMIZED-PARTITION(A, p, r)
3      RANDOMIZED-QUICKSORT(A, p, q - 1)
4      RANDOMIZED-QUICKSORT(A, q + 1, r)

No — it does not improve the average-case complexity, which remains O(n log n). What it improves is the dependence on the input order.

  • Deterministic quicksort with the first or last element as pivot is O(n²) on an already sorted or reverse-sorted input: every partition is completely unbalanced.
  • Randomized quicksort chooses the pivot uniformly at random, so for any fixed input the expected running time over the random choices is O(n log n).
  • The O(n²) worst case is still possible, but its probability is very small and no adversary can force it without knowing the random choices.
Expected T(n) = O(n log n)   |   Worst case = O(n²) with small probability

One-line answer: randomization turns an input-dependent worst case into a low-probability event; the average case stays O(n log n).

5.6 Approximation algorithms ★★★★ 4×

Q1What are approximation algorithms? Based on the approximation ratio, classify them. How are performance ratios useful?

7–9 marks★★★★ 4×

Asked in: 2022 Nov Q5(b) [8] · 2023 Nov Q6(b) [4] · 2024 May Q5(b) [9] · 2025 May Q6(b) [7]

NP-hard problems — the book's starting point

In complexity theory, some problems are decision problems (answer yes/no), some are search problems, and many are optimization problems. The book defines: if the decision version of a combinatorial optimization problem is proved NP-complete, then its optimization version is NP-hard.

Example (book): the Hamiltonian-cycle decision problem (“is there a Hamiltonian cycle of length less than k?”) is NP-complete, because a cycle of length less than k is easy to verify. The optimization version (“what is the shortest Hamiltonian cycle?”) is NP-hard, because it is not easy to decide whether the cycle obtained is the shortest.

What is an approximation algorithm?

The book defines approximation algorithms as algorithms used to find approximate solutions to optimization problems. They are usually associated with NP-hard problems because an efficient polynomial-time exact algorithm is very difficult to obtain.

  • They are mainly useful when an exact polynomial algorithm is known but is too expensive for the size of the data set.
  • The philosophy is: find a “good” solution fast. You will not get the exact optimum, but you will get an approximate solution quickly.
  • They start with inaccurate data, so the approximate optimization may be as good as the optimal solution.
  • They are based on heuristics — a collection of common-sense rules defined from experience (trial and error).

Book examples of heuristics: in TSP, go to the next nearest city; in knapsack, start with the item of highest value and minimum weight.

Accuracy ratio

For an approximate solution sa with objective value f(sa) and an optimal solution s* with value f(s*):

r(sa) = f(sa) / f(s*)    and generally   r(sa) ≥ 1

When r(sa) is close to 1, the approximate solution is better. For a maximization problem the ratio is written the other way round so that it is still ≥ 1.

Performance ratio and classification by ratio

The performance ratio RA is the best upper bound on the accuracy ratio taken over all instances of the problem. It is used to judge the quality of an approximation algorithm; a value nearer 1 is better.

If there exists a value c ≥ 1 such that r(sa) ≤ c for all instances, the algorithm is called a c-approximation algorithm. This is the book's classification:

Value of cClassMeaning / book example
c = 1OptimalExact algorithm; ratio 1 is the best possible
c > 1, constantc-approximationGuaranteed f(sa) ≤ c·f(s*); smaller c is better
c = 22-approximationTwice-around-the-tree TSP for Euclidean distances
No finite cUnbounded ratioNearest-neighbour TSP; ratio grows without limit
For a c-approximation:   f(sa) ≤ c · f(s*)

Why performance ratios are useful

  • They give a provable worst-case quality guarantee, unlike a heuristic with no bound.
  • They let us compare two approximation algorithms independently of the input instance: the smaller RA or c, the better.
  • They show how much accuracy is traded for speed: c = 1 means exact, c = 2 means at most twice the optimum.
  • They help decide whether the approximate algorithm is good enough or an exact (possibly exponential) algorithm is required.

Book example — nearest-neighbour TSP and its ratio

Graph: A–B = 2, B–C = 3, C–D = 2, D–A = 7, A–C = 4, B–D = 4. Start at A; the nearest unvisited city gives the tour A–B–C–D–A, with sa = 2 + 3 + 2 + 7 = 14. Exhaustive search gives the optimal A–B–D–C–A, with s* = 2 + 4 + 2 + 4 = 12. Hence

r(sa) = 14 / 12 = 1.16

The approximate tour is 16% longer than the optimum. Its drawback is the long return edge D–A: if that edge has length w, then r(sa) = (7 + w)/12, which tends to infinity as w grows.

Book example — twice-around-the-tree TSP

For Euclidean instances the distances satisfy the triangle inequality, dist[i,j] ≤ dist[i,k] + dist[k,j], and symmetry, dist[i,j] = dist[j,i]. The book's algorithm is:

  1. Compute a minimum spanning tree (MST) of the graph.
  2. Start at any city and walk around the tree by DFS, recording the nodes visited.
  3. Eliminate duplicate visits from the recorded list; the remaining order is a Hamiltonian circuit.

This is a 2-approximation (c = 2) for TSP with Euclidean distances. The book also gives the accuracy-ratio bound

r(sa) ≤ ½ (⌈log2 n⌉ + 1)

where n is the number of cities. In the book's example the MST is A–B (3), B–C (5), B–D (8), D–E (7); DFS records A–B–C–B–D–E–D–B–A; removing duplicates gives A–B–C–D–E–A. This is a valid tour but not necessarily the optimal one.

5.7 Embedded algorithms & power-optimized scheduling ★★★ 3×

Q1What is an embedded algorithm? Explain embedded system scheduling using a power-optimized scheduling algorithm.

9 marks★★★ 3×

Asked in: 2022 Nov Q6(b) [9] · related: 2023 Nov Q6(a) [6] · 2024 May Q6(b) [9]

Embedded system and embedded algorithm

The book defines an embedded system as “a computer system with a dedicated function within a larger mechanical or electrical system.” It usually does not look like a computer: there is often no keyboard, monitor or mouse, but it has a processor, memory and software. It is a permanent part of a bigger system. Examples: smart card, washing machine, microwave oven, answering machine, mobile phone, digital camera, vending machine.

An embedded algorithm is therefore an algorithm written for such a dedicated system. It must respect the system's constraints: limited memory, low power, real-time deadlines, small code size and predictable timing.

Characteristics of embedded systems (book)

  1. Single functional: designed to perform dedicated functions.
  2. Tightly constrained: tightly coupled hardware and software integration.
  3. Part of a large system: an integral part of a bigger system.
  4. Reactive and real-time: responds to events and triggers; generally time-bounded; modern systems have a user-friendly interface.
  5. Programmable: contains at least one programmable unit (microcontroller).

Embedded system scheduling (book §5.6.1)

The book defines scheduling as the method by which threads and processes access system resources at a specific time. It balances the load and shares resources effectively. In a real-time embedded system the scheduler must ensure that processes meet their deadlines. Priorities are assigned to tasks, and the OS always runs the ready task with the highest priority. Algorithms are classified as fixed priority, dynamic priority, or mixed/hybrid priority.

Fixed-priority scheduling

  • All priorities are assigned at design time and remain constant for the lifetime of the task.
  • Initially tasks reside in the sleep queue. When ready, they enter the ready queue; one ready queue is maintained for each distinct priority.
  • The highest-priority ready task is executed first.
  • Advantage: simple to execute.

Dynamic-priority scheduling

  • All scheduling decisions, including assignment of priorities, are made at run time.
  • Task deadlines are taken into consideration when deciding priorities; mutual exclusion and synchronization are enforced.
  • Tasks start in the sleep queue and move to ready queues; for the highest-priority task the scheduler checks the deadlines of the highest-priority queue and then executes the task.
  • Advantage: flexible, and used only when actual resources are claimed.

Power-optimized scheduling

A power-optimized scheduler is a deadline-aware dynamic-priority scheduler with voltage/frequency scaling. It uses the book's dynamic-priority idea — priorities decided at run time from deadlines — and adds a power rule: run each task at the lowest voltage and frequency that still finishes it before its deadline.

  1. Assign each task a priority from its deadline at run time (earlier deadline = higher priority).
  2. Compute the required execution cycles Ci and the time left until the deadline.
  3. Choose the lowest frequency fi such that Ci/fi ≤ deadlinei − current time.
  4. Run at that frequency; if a task finishes early, use the slack to lower the frequency of later tasks.
  5. If the total utilization Σ Ci/Ti ≤ 1, earliest-deadline-first (EDF) meets all deadlines.

The power saving comes from the CMOS dynamic-power relation

Pdynamic = α · C · V² · f

where V is supply voltage and f is clock frequency. Since a lower frequency allows a lower voltage, power falls roughly as the cube of the frequency. Example: a task needs 300 ms of work and has a 500 ms deadline; running at 60% frequency still meets the deadline, and dynamic energy falls to about 0.6³ ≈ 22% of the maximum.

Trade-off: lowering frequency increases execution time. Too aggressive scaling misses deadlines; too conservative scaling wastes energy. The scheduler must keep enough slack.

The book's §5.6.1 gives the fixed/dynamic priority scheduling framework; the voltage/frequency layer above is the standard power-optimized extension of the same deadline-driven rule.

5.8 Sorting algorithm for embedded systems

Q1Which sorting algorithm is best for embedded systems? Why? / Suggest a suitable sorting algorithm for a real-time medical device and justify.

6–9 marks★★ 2×

Asked in: 2023 Nov Q6(a) [6] · 2024 May Q6(b) [9 — medical device scenario]

What the book requires from an embedded sorting algorithm

  1. The sorting algorithm must be in place.
  2. The algorithm must not be recursive.
  3. The code size must be as per the need of the problem.
  4. The running time should increase linearly or logarithmically with the number of elements sorted.

The book defines an in-place algorithm as one that requires very little additional space besides the initial array; the input is overwritten by the output and no more additional space is required. It lists bubble sort, insertion sort and heap sort as methods that can be used in embedded systems, and discusses insertion sort in detail.

Insertion sort (book §5.6.2)

Insertion sort maintains a sorted zone. Each new unsorted element is compared with the elements in the sorted zone and inserted at its proper position. The process continues until the whole list is sorted.

Book example: 30 70 20 50 40 10 60 → the sorted zone grows as 30 | 30 70 | 20 30 70 | 20 30 50 70 | 20 30 40 50 70 | 10 20 30 40 50 70 | 10 20 30 40 50 60 70.

Algorithm Insert_sort(A[0..n-1])
for i = 1 to n-1 do
{
    temp = A[i]
    j = i - 1
    while (j >= 0) AND (A[j] > temp) do
    {
        A[j+1] = A[j]
        j = j - 1
    }
    A[j+1] = temp
}

The book notes that although insertion sort is naturally recursive (top-down), the bottom-up iterative version above is very efficient to implement.

The basic operation is the key comparison A[j] > temp; the book analyses it over the range 1 to n − 1.

Which is best for embedded systems?

Insertion sort is the natural choice for the small buffers typical of embedded systems, and it is the algorithm the book develops for this purpose. Reasons:

  • In place — only O(1) extra memory, no auxiliary array.
  • Non-recursive when written as the bottom-up loop above — no recursion stack.
  • Small code size — simple loops, suitable for limited ROM.
  • Adaptive — Θ(n) on nearly sorted data, which is common for sensor streams.
  • Stable — equal readings keep their original order (useful for timestamps).

For large buffers with a hard real-time deadline, heap sort is safer: the book lists it as an embedded sorting method, and it gives O(n log n) worst-case time with O(1) extra memory and no recursion. Merge sort is unsuitable because it needs O(n) extra memory; ordinary recursive quicksort is unsuitable because of its O(n²) worst case and recursion stack.

Medical-device scenario (2024 May): the device samples timestamps, temperature, heart rate and blood pressure continuously, and the buffer is small and often nearly sorted. Insertion sort is ideal: in-place, stable, Θ(n) on nearly sorted data and very small code. If the buffer becomes large, switch to heap sort to keep an O(n log n) worst-case guarantee.
