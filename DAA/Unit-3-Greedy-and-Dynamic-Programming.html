3.1 Greedy strategy

Syllabus: Principle, control abstraction, time analysis of control abstraction, knapsack problem, job scheduling, activity selection.

Q1Explain Greedy strategy: Principle, control abstraction, time analysis of control abstraction with suitable example.

8 marks★★ 2×

Asked in: 2022 Nov Q1(b) [8] · 2024 May Q1(a) [6 — control abstraction + complexity]

1. Principle (book §3.1.1)

A greedy algorithm builds the solution step by step, expanding a partially constructed solution until a complete solution is reached. At every step the choice made must be:

  • Feasible — it satisfies the problem's constraints;
  • Locally optimal — among all feasible choices, it is the best at that moment;
  • Irrevocable — once chosen, it is never changed in later steps.

In short, there must be a “greed” for the optimum solution. The book adds two correctness conditions: the greedy-choice property (a globally optimal solution can be reached by local greedy choices) and optimal substructure (an optimal solution contains optimal solutions of its subproblems).

2. Control abstraction (book §3.1.2)

Algorithm Greedy(D, n)
// D is the domain of candidates, |D| = n
{
    Solution = ∅;
    for i = 1 to n do
    {
        s = Select(D);                     // pick the best remaining candidate
        if Feasible(Solution, s) then      // check the constraints
            Solution = Union(Solution, s); // add it permanently
    }
    return Solution;
}

Select, Feasible and Union are the three problem-dependent functions. The book lists the applications as knapsack, job sequencing with deadlines, minimum spanning tree, single-source shortest path and Huffman tree.

3. Time analysis of the control abstraction

T(n) = Tsort + n × ( TSelect + TFeasible + TUnion )
  • The loop executes exactly n times — one candidate per iteration.
  • If candidates are already sorted by the greedy criterion: O(n) when Select, Feasible and Union are O(1). This is exactly what the book's Knapsack_Greedy shows — the basic operation lies inside the loop, so time = O(n).
  • If sorting is needed first: O(n log n).
  • If each feasibility check scans the current solution: O(n²).
  • Space = O(n) for the candidate array and the solution set.

4. Suitable example — fractional knapsack (book Example 3.2.2)

n = 5, capacity m = 100, profits (10, 20, 30, 40, 50), weights (20, 30, 66, 40, 60). Using the greedy rule “maximum profit/weight first”: x4 has ratio 1 and x5 has 5/6, so take x4 (w = 40) and x5 (w = 60). The capacity is exactly full.

x = (0, 0, 0, 1, 1),   weight = 100,   maximum profit = 40 + 50 = 90
For 8 marks: principle (3 conditions) + control abstraction + time analysis + one example. Add the two correctness conditions from §3.1.4 — the examiner looks for “greedy-choice property” and “optimal substructure”.

Q3Comment on the statement: "Greedy method always provides the optimal solution."

3 marks★ 1×

Asked in: 2025 Nov Q1(c) [3]

The statement is false. The book says plainly that in the greedy method there is no guarantee of getting the optimum solution (§3.5.5). A greedy algorithm is optimal only when the problem satisfies:

  • Greedy-choice property — a globally optimal solution can be reached by making locally optimal choices;
  • Optimal substructure — an optimal solution contains optimal solutions of its subproblems.

Counter-example — 0/1 knapsack: capacity 10, items (w, p) = (6, 30), (5, 25), (5, 25). All ratios are 5, so greedy takes the 6 kg item first and earns 30; the remaining capacity 4 cannot hold a 5 kg item. The optimal choice is both 5 kg items → profit 50. Greedy gives 30, so it is not optimal.

Why it fails here: the 0/1 restriction makes the choice irreversible and can leave capacity unused. The book's Example 3.2.8 shows the same limitation — after selecting by p/w ratio, object 5 cannot be taken because it does not fit, and no fraction is allowed.

Where it does work: fractional knapsack, job sequencing with deadlines, activity selection, minimum spanning tree, single-source shortest path and Huffman tree (the book's list of greedy applications).

3.2 Fractional knapsack & greedy knapsack

Q1Give a mathematical formulation for: (i) Fractional Knapsack problem (ii) 0/1 Knapsack problem.

8 marks★ 1×

Asked in: 2025 May Q1(a) [8]

Let there be n items. Item i has weight wi > 0 and profit pi > 0; the knapsack capacity is m (the book uses W); xi is the fraction of item i selected. The objective function is the total profit. A solution satisfying all constraints is a feasible solution, and the feasible solution with the best objective value is the optimal solution (book §3.1.1).

(i) Fractional knapsack (book §3.2)

Maximize  Z = Σi=1..n pi xi
Subject to  Σi=1..n wi xi ≤ m
and  0 ≤ xi ≤ 1    for i = 1, 2, …, n

Items are divisible: a fraction of an item may be placed in the knapsack. The greedy algorithm sorts by pi/wi and takes items in that order, taking a fraction of the last item if needed.

(ii) 0/1 knapsack (book §3.8)

Maximize  Z = Σi=1..n pi xi
Subject to  Σi=1..n wi xi ≤ W
and  xi = 0 or 1    for i = 1, 2, …, n

Each item is either taken completely (xi = 1) or rejected (xi = 0). The book states that the objective is the maximum profit earned; because of the 0/1 restriction the ratio rule can fail, so dynamic programming is used.

Key difference: in fractional knapsack the last item may be split (0 ≤ xi ≤ 1); in 0/1 knapsack only 0 or 1 is allowed. That single change is why fractional knapsack is greedy-solvable and 0/1 knapsack needs DP.

📘 Book: §3.2 Knapsack Problem, p. 3-4; §3.8 The 0/1 Knapsack, p. 3-62

3.3 Job sequencing with deadlines ★★★★ 4×

This is the single most repeated Unit-3 question. Learn the algorithm and the three solved instances below.

Q1What is job scheduling algorithm? How can it be solved using the greedy approach? Explain with respect to principle, control abstraction and time analysis, for the given instance.
Jobs J1–J5, Deadline 2,1,3,2,1, Profit 60,100,20,40,20

12 marks★★★ 3×

Asked in: 2023 Nov Q2(a) [12] · related: 2023 Nov Q2(b) [6 — steps] · 2023 Nov Q1(a) [9] · 2025 Nov Q1(b) [8]

Problem statement (book §3.3)

There are n jobs to be executed. Each job takes one unit of time, has deadline di and gives profit pi only if it is completed within its deadline. At any time only one job runs. We must obtain a feasible sequence that maximises the total profit.

The book's rules: a job started before or at its deadline earns profit, otherwise no profit; consider all schedules and choose the one with maximum profit. A feasible sequence is one in which every job finishes by its deadline.

Greedy strategy (book's 4 steps, §3.3)

  1. Arrange the jobs in descending order of profit.
  2. Create a job array J[1..n] and keep all slots free.
  3. For each job in that order, insert it at the slot equal to its deadline. If that slot is occupied, search an earlier free slot (< di). If no free slot exists, discard the job.
  4. Read the filled array from left to right — that is the optimal sequence.

Algorithm Job_seq (book §3.3)

Algorithm Job_seq(p, d, n)
{
    Sort jobs so that p[1] ≥ p[2] ≥ … ≥ p[n];
    for r = 1 to n do J[r] = free;
    count = 0;

    for i = 1 to n do
    {
        r = d[i];                       // try the deadline slot
        while (r ≥ 1 and J[r] ≠ free) do
            r = r − 1;                  // search an earlier slot
        if (r ≥ 1) then
        {
            J[r] = i;                   // insert job i
            count = count + 1;
        }
        // if r = 0, no slot ≤ d[i] is free → discard job i
    }
    return J, count;
}

Time: the book states O(n²), because the insertion/scan runs inside two nested loops. Sorting adds O(n log n). Space is O(n) for J.

3.4 Activity selection problem

Q1Consider seven activities with start and finish times. Using the greedy strategy, compute an execution schedule with the maximum number of non-conflicting activities.
A(1,3) B(3,4) C(2,5) D(0,7) E(5,9) F(8,10) G(11,12)

9 marks★ 1×

Asked in: 2025 May Q1(b) [9]

Definition (book §3.4)

Given a resource such as a CPU or a lecture hall and n activities, activity i has start time Si and finish time Fi. The activity-selection problem is to find a maximum-size subset of mutually compatible activities — i.e. maximise the number of lectures in the hall or tasks assigned to the CPU.

Greedy rule

Sort the activities by finish time in non-decreasing order. Select the first activity, then repeatedly select the next activity whose Si ≥ Flast. Choosing the earliest finish leaves the maximum room for the remaining activities.

Algorithm Greedy_Act_sel (book §3.4)

Algorithm Greedy_Act_sel(S, F)
{
    n = length[S];
    A = {a1};                 // select the first activity
    i = 1;                    // last selected activity

    for m = 2 to n do
    {
        if (S[m] ≥ F[i]) then // compatible with the last choice
        {
            A = A ∪ {a_m};
            i = m;
        }
    }
    return A;
}

Time: O(n) after sorting; with sorting, O(n log n). Space O(n) for the activity arrays.

3.5 Dynamic programming — principle & control abstraction

Q1Explain the dynamic programming approach. Write the control abstraction and comment on its time complexity.

8 marks★★★ 3×

Asked in: 2022 Nov Q2(b) [8] · 2024 May Q2(a) [8] · 2025 Nov Q2(a) [7]

What is dynamic programming? (book §3.5)

Dynamic programming was invented by Richard Bellman in 1950. It is a technique for solving problems that have overlapping subproblems. Each subproblem is solved only once, and its result is recorded in a table; the final solution is then obtained from that table. It is typically applied to optimization problems, where we want the minimum or maximum value among many possible solutions.

Steps of dynamic programming (book §3.5.1)

  1. Characterise the structure of an optimal solution — develop a mathematical notation that expresses any solution and its subsolution.
  2. Recursively define the value of an optimal solution.
  3. Compute the value bottom-up using a recurrence relation that relates a solution to its subsolutions.
  4. Compute an optimal solution from the stored information.

Control abstraction (bottom-up table filling)

Algorithm DynamicProgramming(n)
{
    // table[] stores the optimum value of every subproblem
    for each base subproblem do
        table[base] = base value;

    for each subproblem in increasing order of size do
    {
        table[state] = worst value;              // +∞ for min, −∞ for max
        for each choice c of that subproblem do
        {
            value = cost(c) + table[smaller state(c)];
            if value is better than table[state] then
            {
                table[state] = value;
                decision[state] = c;             // remember the choice
            }
        }
    }
    return table[full problem];
}

Elements (book §3.5.3)

  • Optimal substructure — the optimal solution contains optimal solutions of its subproblems.
  • Overlapping subproblems — the same subproblem is solved many times, so storing its result avoids repeated work.

Time analysis

T(n) = (number of distinct states) × (choices per state) × (cost per choice)
  • 0/1 knapsack: table of (n + 1) × (W + 1) entries → O(nW).
  • Matrix chain multiplication: O(n²) states × O(n) splits → O(n³).
  • Optimal BST: O(n³) (the book notes Knuth's improvement to O(n²)).
  • Binomial coefficients: A(n,k) = nk additions → Θ(nk).
  • Space equals the table size: O(nW), O(n²), etc.

The book lists the main applications as multistage graph, travelling salesman, matrix multiplication, longest common subsequence, maximum flow and all-pairs shortest path.

📘 Book: §3.5 Introduction to Dynamic Programming, p. 3-26 – 3-28

Q2With respect to dynamic programming, what is the principle of optimality? Give a mathematical representation.

7 marks★★ 2×

Asked in: 2025 May Q2(a) [7] · related: 2024 May Q1(c) [4]

Statement (book §3.5.2)

The principle of optimality states: “In an optimal sequence of decisions or choices, each subsequence must also be optimal.” In other words, whatever the first decision is, the remaining decisions must form an optimal solution for the subproblem that results from that first decision.

The book adds: a DP algorithm obtains its solution using this principle, and when the principle cannot be applied it is almost impossible to obtain the solution by dynamic programming.

Mathematical representation

Let OPT(i, j) be the optimum cost for the subproblem from i to j, and let the first decision split it at k. Then the optimum is built from optimum subsolutions:

OPT(i, j) = mini ≤ k < j { OPT(i, k) + OPT(k+1, j) + cost(i, k, j) }

For matrix chain multiplication the book writes this as:

m[i, j] = mini ≤ k < j { m[i, k] + m[k+1, j] + Pi−1 Pk Pj },    m[i, i] = 0

For a shortest path from s to t through v, the same idea gives:

d(s, t) = d(s, v) + d(v, t)

i.e. every sub-path of a shortest path is itself a shortest path — the book's example of the principle of optimality.

Book's proof for OBST (Example 3.7.1)

If the left subtree L of an optimal tree T0n were not optimal, replace it by a cheaper L′. The new tree has cost C(L′) + C(R) + W < C(L) + C(R) + W = C(T0n), contradicting the optimality of T0n. Hence L must be optimal; similarly R must be optimal. This proves that OBST follows the principle of optimality.

When it fails

Longest simple path has no optimal substructure: a longest path from A to D through B need not contain the longest path from A to B, because that sub-path may already use a vertex needed later. DP cannot be applied to such a problem.

📘 Book: §3.5.2 Principle of Optimality, p. 3-26 – 3-27; §3.7 OBST, p. 3-35

Q3Comment on the statement: "A problem which does not satisfy the principle of optimality cannot be solved by dynamic programming."

4 marks★ 1×

Asked in: 2024 May Q1(c) [4]

The statement is true in the sense used by the book. Dynamic programming builds the global optimum from optimal solutions of subproblems — it “makes use of the principle of optimality to find the optimal solution from subproblems” (book §3.5.3). If the principle does not hold, an optimal subsolution may lead to a worse or invalid global solution, so the recurrence OPT(i,j) = combine(OPT of parts) cannot guarantee the correct answer.

The book states: “When it is not possible to apply the principle of optimality it is almost impossible to obtain the solution using the dynamic programming approach.”

Example where it holds: shortest path — every sub-path of a shortest path is a shortest path, so Floyd–Warshall and the MCM recurrence work.

Example where it fails: longest simple path — the longest path from A to D through B may not contain the longest A–B path, because that sub-path can use a vertex needed later. No DP recurrence gives the correct answer; the problem is NP-hard.

Exam note: DP may still be applied and return a feasible answer, but without the principle of optimality it cannot guarantee optimality. Write this distinction for the 4th mark.

📘 Book: §3.5.2 – §3.5.3, p. 3-26 – 3-27

3.6 Matrix chain multiplication ★★ 2×

Q1Solve the matrix chain multiplication for the 6-matrix problem using dynamic programming.
Dimensions: A1 10×20, A2 20×5, A3 5×15, A4 15×50, A5 50×10, A6 10×15

10 marks★★ 2×

Asked in: 2022 Nov Q1(a) [10] · same pattern: 2024 May Q2(b) [10]

Problem (book §3.9)

Given n matrices A1, A2, …, An with dimensions P1×P2, P2×P3, …, Pn×Pn+1, compute the product A1A2…An using the minimum number of scalar multiplications. Matrix multiplication is associative, so the answer is the best parenthesisation.

Multiplying a p×q matrix by a q×r matrix costs p·q·r scalar multiplications. The book's 3-matrix example: (5×4)(4×6)(6×2) costs 180 as (A1A2)A3 but only 88 as A1(A2A3).

Recurrence (book Step 2)

m[i, i] = 0
m[i, j] = mini ≤ k < j { m[i, k] + m[k+1, j] + Pi−1 · Pk · Pj }

m[i][j] = minimum cost for Ai…Aj; s[i][j] = the split k that gives it.

Algorithm Matrix_chain (book §3.9.1)

Matrix_chain(P[0..n])
{
    for i = 1 to n do m[i, i] = 0;

    for len = 2 to n do
        for i = 1 to (n − len + 1) do
        {
            j = i + len − 1;
            m[i, j] = ∞;
            for k = i to j − 1 do
            {
                q = m[i, k] + m[k+1, j] + P[i−1]*P[k]*P[j];
                if (q < m[i, j]) then
                {
                    m[i, j] = q;
                    s[i, j] = k;
                }
            }
        }
    return m[1, n];
}

Time O(n³), space O(n²) — the book's analysis: three nested loops.

3.7 Optimal binary search tree (OBST)

Q1Write a dynamic programming algorithm for creating an optimal binary search tree for n keys, and construct the OBST for the 4 given keys.
Keys A, B, C, D with probabilities 0.1, 0.2, 0.4, 0.3

10 marks★ 1×

Asked in: 2022 Nov Q2(a) [10]

Problem (book §3.7)

When we search words in a dictionary, frequently used words should be placed near the root so that the average search time is small. Such a tree — arranged to minimise the search cost — is an optimal binary search tree (OBST).

Given identifiers a1 < a2 < … < an, let p(i) be the probability of a successful search for ai and q(i) the probability of an unsuccessful search between ai and ai+1. We want a tree with minimum cost Σp(i) + Σq(i).

Notation and recurrence (book Steps 1–3)

  • Tij = OBST for keys ai+1 … aj; Cij = its cost; Wij = its weight; rij = its root.
  • Base: Cii = 0, Wii = qi; a single node has Wi,i+1 = qi + qi+1 + pi+1 and Ci,i+1 = Wi,i+1.
  • Wij = Wi,j−1 + pj + qj.
Cij = mini < k ≤ j { Ci,k−1 + Ck,j } + Wij
rij = k that gives the minimum

The cost formula comes from C(T0n) = C(L) + C(R) + W, where W = p1 + … + pn + q0 + … + qn.

Algorithm OBST (book §3.7.1)

Algorithm OBST(p, q, n)
{
    for i = 0 to n do
    {
        C[i][i] = 0;
        r[i][i] = 0;
        W[i][i] = q[i];
    }

    for i = 0 to n−1 do
    {
        W[i][i+1] = q[i] + q[i+1] + p[i+1];
        C[i][i+1] = W[i][i+1];
        r[i][i+1] = i+1;
    }

    for m = 2 to n do
        for i = 0 to n−m do
        {
            j = i + m;
            W[i][j] = W[i][j−1] + p[j] + q[j];
            C[i][j] = min over i < k ≤ j of { C[i][k−1] + C[k][j] } + W[i][j];
            r[i][j] = k giving the minimum;
        }
    return C[0][n], r;
}

Time O(n³), space O(n²). The book notes that Knuth's range restriction improves it to O(n²).

3.8 0/1 Knapsack using dynamic programming ★★ 2×

Q1Find the optimal solution of the 0/1 knapsack problem using dynamic programming.
Items (weight, profit): (2,12), (1,10), (3,20), (2,15). Capacity = 5.

9 marks★★ 2×

Asked in: 2023 Nov Q1(b) [9] · 2025 May Q2(b) [10 — capacity 7, items (1,1),(3,4),(4,5),(5,7)]

Problem and recurrence (book §3.8)

Given n objects, object i has weight wi and profit pi; the knapsack capacity is W. Choose xi ∈ {0,1} to maximise Σpixi subject to Σwixi ≤ W.

table[i, j] = max{ table[i−1, j],   pi + table[i−1, j−wi] }   if j ≥ wi
table[i, j] = table[i−1, j]   if j < wi
table[0, j] = 0,   table[i, 0] = 0

table[i, j] = best profit using the first i objects with capacity j. The answer is table[n, W]. To recover the items, compare table[i, k] with table[i−1, k]: if different, take item i and set k = k − wi; otherwise skip item i and set i = i − 1.

Algorithm Knapsack01 (book's table method)

Knapsack01(w[], p[], n, W)
{
    for j = 0 to W do table[0][j] = 0;
    for i = 0 to n do table[i][0] = 0;

    for i = 1 to n do
        for j = 0 to W do
        {
            if (w[i] > j) then
                table[i][j] = table[i−1][j];
            else
                table[i][j] = max(table[i−1][j],
                                  p[i] + table[i−1][j−w[i]]);
        }
    return table[n][W];
}

Time O(nW), space O(nW).

3.9 Binomial coefficients using DP

Q1Find the binomial coefficients of (x + y)5 using the dynamic programming approach.

10 marks★ 1×

Asked in: 2025 Nov Q2(b) [10]

Definition (book §3.6)

Computing a binomial coefficient is a typical example of dynamic programming. In the expansion of (a + b)n, the coefficient of a term is denoted by C(n, k) or nCk, where 0 ≤ k ≤ n.

Recurrence (Pascal's identity)

C(n, k) = C(n−1, k−1) + C(n−1, k)    for n > k > 0
C(n, 0) = 1,   C(n, n) = 1

Direct recursion is exponential because C(n−1,k−1) and C(n−1,k) overlap. DP fills Pascal's triangle row by row, so every value is computed once.

Algorithm Binomial (book §3.6)

Algorithm Binomial(n, k)
{
    for i = 0 to n do
        for j = 0 to min(i, k) do     // book: k is taken as min(i, k)
        {
            if (j = 0 or i = j) then
                C[i][j] = 1;
            else
                C[i][j] = C[i−1][j−1] + C[i−1][j];
        }
    return C[n][k];
}

Analysis: the basic operation is one addition. The book counts A(n,k) = nk additions, so the time complexity is Θ(nk); space is O(nk), which can be reduced to O(k) by keeping only the previous row.

One-line memory hooks

  • Greedy = local best, one pass, never undo.
  • DP = overlapping subproblems + optimal substructure + table.
  • Fractional knapsack → ratio p/w; 0/1 → DP.
  • Job sequencing → highest profit first, latest free slot.
  • Activity selection → earliest finish first.
  • MCM → try every split k, add pi−1pkpj.
  • OBST → root r minimises left + right + weight(i,j).
  • Knapsack DP → max(skip, take + value).
  • Pascal → add the two numbers above.
