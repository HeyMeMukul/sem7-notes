3.1 Greedy strategy

Syllabus: Principle, control abstraction, time analysis of control abstraction, knapsack problem, job scheduling, activity selection.

Q1Explain Greedy strategy: Principle, control abstraction, time analysis of control abstraction with suitable example.

8 marks★★ 2×

Asked in: 2022 Nov Q1(b) [8] · 2024 May Q1(a) [6 — control abstraction + complexity]

1. Principle (definition)

A greedy algorithm builds the solution one component at a time. At every step it picks the component that looks best at that moment (locally optimal), without worrying about future consequences, and never changes a decision once made.

  • Feasible solution — satisfies all constraints (e.g. total weight ≤ capacity).
  • Optimal solution — feasible solution with best objective value.
  • Greedy is correct only if the problem has the greedy-choice property (a globally optimal solution can be reached by local greedy choices) and optimal substructure.

2. Control abstraction

Algorithm Greedy(a, n)
// a[1..n] : list of candidates (already sorted by the greedy criterion)
// solution : set of selected candidates
{
    solution = ∅;
    for i = 1 to n do
    {
        x = Select(a);                  // pick the "best" remaining candidate
        if Feasible(solution, x) then   // does it keep the solution valid?
            solution = Union(solution, x);
    }
    return solution;
}

The three functions that change from problem to problem are Select, Feasible and Union. The loop runs exactly n times, so greedy is usually very fast.

3. Time analysis of the control abstraction

T(n) = Tsort + n · ( TSelect + TFeasible + TUnion )
  • If candidates are pre-sorted by the greedy criterion: O(n log n).
  • Select becomes O(1) after sorting; Feasible/Union are usually O(1) or O(n).
  • Therefore total = O(n log n) when feasibility is O(1), and O(n²) when each feasibility check costs O(n).
  • Space = O(n) for the candidate array and solution set.

4. Suitable example — fractional knapsack

Capacity m = 20, items: (w,p) = (10,60), (10,100), (10,120). Greedy by profit/weight: 12, 10, 6 → take item 3 (120), item 2 (100), then half of item 1 (30). Total profit = 250, which is optimal. (Full solution in §3.2.)

Write this for 8 marks: principle (2–3 lines) + control abstraction (6–8 lines) + time analysis (3 bullets) + one example. That is exactly what the paper asks for — do not add unrelated theory.

Q3Comment on the statement: "Greedy method always provides the optimal solution."

3 marks★ 1×

Asked in: 2025 Nov Q1(c) [3]

The statement is false. A greedy algorithm gives an optimal solution only when the problem satisfies the greedy-choice property and optimal substructure. Otherwise it gives a feasible but possibly sub-optimal answer.

Counter-example — 0/1 knapsack: capacity 10, items (w,p) = (6,30), (5,25), (5,25). Greedy by profit/weight picks 6 kg (30) and cannot take the others → profit 30. Optimal is 5+5 kg → profit 50.

Where it works: fractional knapsack, activity selection, job sequencing with deadlines, Huffman coding, Prim/Kruskal MST.

3.2 Fractional knapsack & greedy knapsack

Q1Give a mathematical formulation for: (i) Fractional Knapsack problem (ii) 0/1 Knapsack problem.

8 marks★ 1×

Asked in: 2025 May Q1(a) [8]

Common given data

n items; item i has weight wi > 0 and profit pi > 0; knapsack capacity m; xi = fraction of item i chosen.

(i) Fractional knapsack

Maximize  Z = Σi=1..n pi xi
Subject to  Σi=1..n wi xi ≤ m
and  0 ≤ xi ≤ 1    for all i = 1..n

Here items are divisible, so a fraction of an item may be taken.

(ii) 0/1 knapsack

Maximize  Z = Σi=1..n pi xi
Subject to  Σi=1..n wi xi ≤ m
and  xi ∈ {0, 1}    for all i = 1..n

Here an item is either taken completely (xi=1) or rejected (xi=0). Because of this integrality constraint the greedy ratio rule fails, and dynamic programming / branch & bound is required.

Why fractional is greedy-solvable: the feasible region is continuous, so the objective is maximised at an extreme point obtained by taking items in decreasing pi/wi order. In 0/1, the gaps between integer points break this property.

3.3 Job sequencing with deadlines ★★★★ 4×

This is the single most repeated Unit-3 question. Learn the algorithm and the three solved instances below.

Q1What is job scheduling algorithm? How can it be solved using the greedy approach? Explain with respect to principle, control abstraction and time analysis, for the given instance.
Jobs J1–J5, Deadline 2,1,3,2,1, Profit 60,100,20,40,20

12 marks★★★ 3×

Asked in: 2023 Nov Q2(a) [12] · related: 2023 Nov Q2(b) [6 — steps] · 2023 Nov Q1(a) [9] · 2025 Nov Q1(b) [8]

Problem statement

We are given n jobs. Job i needs one unit of time, has deadline di and gives profit pi only if completed by its deadline. Only one job runs at a time. We must choose a subset and an order that maximises total profit.

Greedy principle

  • Select: the job with the highest profit among unselected jobs.
  • Feasible: it can be placed in some free time slot r ≤ di.
  • Union: assign it to the latest free slot before its deadline (this keeps earlier slots free for jobs with tight deadlines).

Control abstraction

Algorithm JobSequencing(J, d, p, n)
{
    Sort jobs in decreasing order of profit p;
    for i = 1 to n do slot[i] = free;
    totalProfit = 0;

    for i = 1 to n do
    {
        // find latest free slot r with 1 <= r <= d[i]
        for r = d[i] down to 1 do
        {
            if slot[r] == free then
            {
                slot[r] = i;               // assign job i to slot r
                totalProfit += p[i];
                break;
            }
        }
    }
    return slot, totalProfit;
}

Time analysis

  • Sorting: O(n log n).
  • For each job we scan at most dmax slots → O(n · dmax), worst case O(n²).
  • Using a disjoint-set "next free slot" structure this improves to O(n α(n)) ≈ O(n).
  • Space: O(n + dmax).

3.5 Dynamic programming — principle & control abstraction

Q1Explain the dynamic programming approach. Write the control abstraction and comment on its time complexity.

8 marks★★★ 3×

Asked in: 2022 Nov Q2(b) [8] · 2024 May Q2(a) [8] · 2025 Nov Q2(a) [7]

Principle

Dynamic programming solves a problem by breaking it into overlapping subproblems, solving each subproblem only once, storing its answer in a table, and then combining the stored answers to build the final solution.

Two properties must hold:

  1. Optimal substructure — an optimal solution is made of optimal solutions to subproblems.
  2. Overlapping subproblems — the same subproblem is needed many times (otherwise plain divide & conquer is enough).

Two implementation styles: top-down memoisation (recursion + cache) and bottom-up tabulation (fill a table in increasing order of subproblem size).

Control abstraction (bottom-up)

Algorithm DynamicProgramming(n)
{
    // table[] stores the optimal value of every subproblem
    table[0] = base case;

    for i = 1 to n do                     // increasing subproblem size
    {
        table[i] = −∞;                    // or +∞ for minimisation
        for each choice c of subproblem i do
        {
            value = cost(i, c) + table[sub(i, c)];
            if value is better than table[i] then
                table[i] = value;
                decision[i] = c;          // remember the choice
        }
    }

    return table[n];                      // optimal value of full problem
}

Time analysis

T(n) = (number of distinct states) × (choices per state) × (time per choice)
  • 0/1 knapsack: O(nW) — n items × W capacities.
  • Matrix chain multiplication: O(n³) — O(n²) subproblems × O(n) splits.
  • Optimal BST: O(n³); binomial coefficients: O(nk).
  • Space is the size of the table: O(nW), O(n²), etc.
  • This is pseudo-polynomial for knapsack (depends on W, not just on input length).

Example — Fibonacci

Plain recursion takes O(2ⁿ) because F(n−1) and F(n−2) are recomputed. DP fills F[0..n] once: O(n) time, O(n) space (or O(1) with two variables).

Q2With respect to dynamic programming, what is the principle of optimality? Give a mathematical representation.

7 marks★★ 2×

Asked in: 2025 May Q2(a) [7] · related: 2024 May Q1(c) [4]

Statement

The principle of optimality states: whatever the initial state and initial decision are, the remaining decisions must constitute an optimal policy with regard to the state resulting from the first decision. In simpler words — every subsequence of an optimal solution is itself optimal for its subproblem.

Mathematical representation

Let OPT(i, j) be the optimal cost for subproblem (i, j), and let the first decision split it at k. Then:

OPT(i, j) = mini ≤ k < j { OPT(i, k) + OPT(k+1, j) + cost(i, k, j) }

For a shortest path from s to t through an intermediate vertex v:

d(s, t) = d(s, v) + d(v, t)

i.e. the sub-paths of a shortest path are themselves shortest paths. This is exactly the recurrence used by Floyd–Warshall, matrix chain and OBST.

When it fails

Longest simple path in a graph has no optimal substructure: the longest path from A to D via B does not necessarily contain the longest path from A to B, because that sub-path may already use a vertex needed later. Hence DP does not solve it (it is NP-hard).

Q3Comment on the statement: "A problem which does not satisfy the principle of optimality cannot be solved by dynamic programming."

4 marks★ 1×

Asked in: 2024 May Q1(c) [4]

The statement is true. DP constructs the global optimum by combining optimal solutions of subproblems. If optimal substructure is absent, an optimal sub-solution may lead to a dead end or a worse global answer, so the recurrence OPT(i,j) = combine(OPT of parts) is invalid.

Example: shortest path satisfies optimality (DP works — Floyd–Warshall). Longest simple path does not (a longest sub-path may repeat a vertex), and no DP recurrence gives the correct answer; the problem is NP-hard.

Note for full marks: DP may still be applied and produce a feasible answer, but it cannot guarantee optimality without the principle.

3.6 Matrix chain multiplication ★★ 2×

Q1Solve the matrix chain multiplication for the 6-matrix problem using dynamic programming.
Dimensions: A1 10×20, A2 20×5, A3 5×15, A4 15×50, A5 50×10, A6 10×15

10 marks★★ 2×

Asked in: 2022 Nov Q1(a) [10] · same pattern: 2024 May Q2(b) [10]

Idea

Matrix multiplication is associative, so A1A2…A6 can be parenthesised in many ways. The cost of multiplying a p×q matrix by a q×r matrix is p·q·r scalar multiplications. We must find the parenthesisation with minimum cost.

Let m[i][j] = minimum cost to multiply Ai…Aj, and s[i][j] = the split point k that achieves it.

m[i][i] = 0
m[i][j] = mini ≤ k < j { m[i][k] + m[k+1][j] + pi−1 · pk · pj }

Dimension array: p = [10, 20, 5, 15, 50, 10, 15] (6 matrices → 7 dimensions).

Algorithm

MatrixChainOrder(p, n)
{
    for i = 1 to n do m[i][i] = 0;

    for L = 2 to n do                     // chain length
        for i = 1 to n − L + 1 do
        {
            j = i + L − 1;
            m[i][j] = ∞;
            for k = i to j − 1 do
            {
                q = m[i][k] + m[k+1][j] + p[i−1]*p[k]*p[j];
                if q < m[i][j] then
                {
                    m[i][j] = q;
                    s[i][j] = k;
                }
            }
        }
    return m and s;
}

3.7 Optimal binary search tree (OBST)

Q1Write a dynamic programming algorithm for creating an optimal binary search tree for n keys, and construct the OBST for the 4 given keys.
Keys A, B, C, D with probabilities 0.1, 0.2, 0.4, 0.3

10 marks★ 1×

Asked in: 2022 Nov Q2(a) [10]

Idea

Given sorted keys k1 < k2 < … < kn with search probabilities p1 … pn, build a BST that minimises the expected search cost Σ pi (depthi + 1). Any key can be the root; trying all roots gives overlapping subproblems.

e[i][j] = mini ≤ r ≤ j { e[i][r−1] + e[r+1][j] + w(i, j) }
w(i, j) = Σt=i..j pt   (sum of probabilities in the range)

Base case: e[i][i−1] = 0. root[i][j] stores the chosen root.

Algorithm

OptimalBST(p, n)
{
    for i = 1 to n+1 do
    {
        e[i][i−1] = 0;
        w[i][i−1] = 0;
    }

    for L = 1 to n do                       // chain length
        for i = 1 to n − L + 1 do
        {
            j = i + L − 1;
            e[i][j] = ∞;
            w[i][j] = w[i][j−1] + p[j];

            for r = i to j do
            {
                t = e[i][r−1] + e[r+1][j] + w[i][j];
                if t < e[i][j] then
                {
                    e[i][j] = t;
                    root[i][j] = r;
                }
            }
        }
    return e and root;                      // e[1][n] is optimal cost
}

Complexity: O(n³) time, O(n²) space.

3.8 0/1 Knapsack using dynamic programming ★★ 2×

Q1Find the optimal solution of the 0/1 knapsack problem using dynamic programming.
Items (weight, profit): (2,12), (1,10), (3,20), (2,15). Capacity = 5.

9 marks★★ 2×

Asked in: 2023 Nov Q1(b) [9] · 2025 May Q2(b) [10 — capacity 7, items (1,1),(3,4),(4,5),(5,7)]

Recurrence

V[i][w] = V[i−1][w]    if wi > w
V[i][w] = max( V[i−1][w],   V[i−1][w − wi] + pi )    otherwise

V[i][w] = best profit using the first i items with capacity w. Time O(nW), space O(nW).

Algorithm

Knapsack01(w[], p[], n, W)
{
    for w = 0 to W do V[0][w] = 0;

    for i = 1 to n do
        for w = 0 to W do
        {
            if w[i] > w then
                V[i][w] = V[i−1][w];
            else
                V[i][w] = max(V[i−1][w], V[i−1][w−w[i]] + p[i]);
        }

    return V[n][W];
}

3.9 Binomial coefficients using DP

Q1Find the binomial coefficients of (x + y)5 using the dynamic programming approach.

10 marks★ 1×

Asked in: 2025 Nov Q2(b) [10]

Recurrence

C(n, k) = C(n−1, k−1) + C(n−1, k)    for 0 < k < n
C(n, 0) = C(n, n) = 1

This is Pascal's identity. Direct recursion is exponential because C(n−1,k−1) and C(n−1,k) overlap; DP fills Pascal's triangle once.

Algorithm

BinomialCoefficients(n)
{
    for i = 0 to n do
    {
        C[i][0] = 1;
        C[i][i] = 1;
        for k = 1 to i−1 do
            C[i][k] = C[i−1][k−1] + C[i−1][k];
    }
    return C[n][0..n];
}

Complexity: O(n²) time, O(n²) space (can be reduced to O(n) using one row).
