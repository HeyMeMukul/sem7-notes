3.1 Greedy strategy

Syllabus: Principle, control abstraction, time analysis of control abstraction, knapsack problem, job scheduling, activity selection.

Q1Explain Greedy strategy: Principle, control abstraction, time analysis of control abstraction with suitable example.

8 marks★★ 2×

Asked in: 2022 Nov Q1(b) [8] · 2024 May Q1(a) [6 — control abstraction + complexity]

In simple words: A greedy algorithm solves a problem by taking the best-looking choice right now. Then it moves on and never goes back. It is fast, but it is correct only for some problems.

Why we do this

Many problems ask for the best total result. Checking every possible combination can take too long. Greedy tries to reach the answer in one pass. At each step it picks the option that looks best at that moment.

Words you need first

  • Candidate — one possible item or choice that we may add to the answer.
  • Feasible — allowed by the problem's rules (for example, the item still fits in the bag).
  • Optimal — the best possible answer overall, not just a good one.
  • Locally optimal — the best choice right now, looking only at this step.
  • Irrevocable — once chosen, the choice is fixed and is never undone.
  • Control abstraction — a general skeleton of the algorithm. The skeleton stays the same; three helper functions change from problem to problem.
  • Greedy-choice property — a set of best-now choices can lead to the overall best answer.
  • Optimal substructure — the overall best answer is built from the best answers to smaller parts.
  • O(...) — big-O notation. It describes how the running time grows when the input size n grows. O(n) grows in a straight line. O(n²) grows with n × n. O(n log n) is a little more than linear and is typical of sorting.
Real-life analogy: in a sale, you pick the item with the biggest discount first. You do not plan the whole shopping trip. That is greedy: best now, no looking back.

1. Principle (book §3.1.1)

A greedy algorithm builds the answer one step at a time. It starts with an empty answer and keeps adding one candidate. At every step the chosen candidate must be three things:

  • Feasible — it satisfies the problem's constraints.
  • Locally optimal — among all allowed candidates, it is the best at this moment.
  • Irrevocable — once added, it is never removed or changed.

So there must be a “greed” for the best answer. The book adds two conditions for correctness: the greedy-choice property and optimal substructure (both defined above).

2. Control abstraction (book §3.1.2)

Think of this as a recipe card. It is the same for every greedy problem. Only Select, Feasible and Union change.

Algorithm Greedy(D, n)
// D is the domain of candidates, |D| = n
{
    Solution = ∅;
    for i = 1 to n do
    {
        s = Select(D);                     // pick the best remaining candidate
        if Feasible(Solution, s) then      // check the constraints
            Solution = Union(Solution, s); // add it permanently
    }
    return Solution;
}
  1. Start empty. Solution = ∅. Nothing has been chosen yet.
  2. Pick the best candidate. s = Select(D) returns the best remaining item. Why: this is the greedy step.
  3. Check the rules. Feasible(Solution, s) asks “can we add this without breaking a constraint?” Why: a fast answer that breaks the rules is useless.
  4. Add it permanently. Union puts s into the answer. Why: greedy never takes a choice back.
  5. Repeat n times — once for each candidate.
  6. Return the answer.

Select, Feasible and Union are the three problem-dependent functions. The book lists the applications as knapsack, job sequencing with deadlines, minimum spanning tree, single-source shortest path and Huffman tree. These are other problems that greedy can solve; you do not need them for this question.

3. Time analysis of the control abstraction

We count how many times each line runs. The loop runs n times — once per candidate.

T(n) = Tsort + n × ( TSelect + TFeasible + TUnion )

What this means: total time = sorting time + n × (cost of one selection + one feasibility check + one union).

  • The loop runs exactly n times — one candidate per round.
  • If candidates are already sorted and the three helpers take O(1): O(n). The book's Knapsack_Greedy is of this type — the basic operation lies inside the loop, so time = O(n).
  • If we must sort first: O(n log n).
  • If each feasibility check scans the answer so far: O(n²).
  • Space = O(n) for the candidate array and the answer set.
Why O(n log n) is common: sorting n items costs O(n log n), and it is usually the slowest part. The single greedy pass after sorting is only O(n).

4. Suitable example — fractional knapsack (book Example 3.2.2)

n = 5, capacity m = 100, profits (10, 20, 30, 40, 50), weights (20, 30, 66, 40, 60). The greedy rule is “take the item with the largest profit per unit weight first”.

  1. Compute profit/weight: 10/20 = 0.5, 20/30 = 0.67, 30/66 = 0.45, 40/40 = 1, 50/60 = 0.83. Why: this measures value for each kg.
  2. Sort by ratio: item 4 (1), item 5 (0.83), item 2 (0.67), item 1 (0.5), item 3 (0.45).
  3. Take item 4. Weight 40, profit 40. Remaining capacity = 60. Why: it gives the best value per kg.
  4. Take item 5. Weight 60, profit 50. Remaining capacity = 0.
  5. Stop. The bag is full, so items 2, 1 and 3 are skipped.
x = (0, 0, 0, 1, 1),   weight = 100,   maximum profit = 40 + 50 = 90

What this means: we take all 40 kg of item 4 and all 60 kg of item 5. The capacity is exactly full, and the total profit is 90.

Common confusion: “Greedy” does not mean “pick any item”. It means “pick the best item by the rule”. The rule differs by problem: ratio for knapsack, finish time for activities, profit for jobs. Also, a greedy answer is not always the overall best answer.
For 8 marks: principle (3 conditions) + control abstraction + time analysis + one example. Add the two correctness conditions — the examiner looks for “greedy-choice property” and “optimal substructure”.

Q2Compare greedy algorithmic strategy and dynamic programming strategy.

4–6 marks★ 1×

Asked in: 2025 Nov Q1(a)

In simple words: Greedy takes the best choice now and never changes it. Dynamic programming (DP) tries many choices, saves every small answer in a table, and reuses those answers. Greedy is faster. DP is safer.

Why we do this

Exams ask you to pick the right tool for a problem. If a safe greedy rule exists, greedy gives a fast answer. If one bad early choice can spoil the result, DP is needed.

Words you need first

  • Feasible solution — an answer that obeys all the rules of the problem.
  • Local choice — the best option at this moment, ignoring future effects.
  • Subproblem — a smaller version of the same problem.
  • Overlapping subproblems — the same smaller problem appears again and again.
  • Table — stored answers for smaller problems, so we do not calculate them twice.
  • Principle of optimality — the best overall answer is made of best answers to its parts. The book also calls the related property optimal substructure.
  • Top-down — start from the full problem and break it into smaller parts.
  • Bottom-up — start from the smallest parts and build up to the full problem.
  • Polynomial time — running time grows as a power of n, such as n² or n³. It is considered manageable, unlike exponential time.
Real-life analogy: greedy is grabbing the first taxi you see. DP is checking a map app, writing the best route to each landmark in a notebook, and reusing those notes. The notebook takes effort, but no route is worked out twice.

What this means: read the table row by row. Greedy commits to one path. DP keeps answers for many smaller paths, then chooses the best full path. In O(nW), W is the knapsack capacity. MST (minimum spanning tree), Huffman coding and LCS (longest common subsequence) are other standard algorithms; here they are only examples.

How to choose in the exam (3 steps)

  1. Ask if a local rule is provably safe. Does taking the best item now ever block a better overall answer? If no, greedy is enough. Why: greedy is simpler and faster.
  2. Ask if the same subproblem repeats. If yes, store its answer once. Why: repeated work is what makes plain recursion slow.
  3. Check the principle of optimality. If the best full answer must contain best parts, DP can build it. Why: the DP formula depends on this.
One-line answer: greedy looks only one step ahead, so it is fast but can be wrong. DP examines all choices for each state, so it is slower but gives the optimum when the principle of optimality holds.
Common confusion: DP is not “try every order by brute force”. It stores each state once and reuses it. Also, greedy is not a special case of DP; they are two different strategies.

Q3Comment on the statement: "Greedy method always provides the optimal solution."

3 marks★ 1×

Asked in: 2025 Nov Q1(c) [3]

In simple words: The statement is false. Greedy is fast, but it can miss the best answer. It works only when taking the best choice now is safe for the overall answer, and when the best whole is built from best parts.

Why we do this

“Comment on” questions need a clear verdict, a reason, and one small example. A counterexample proves that “always” is too strong a word.

Words you need first

  • Greedy-choice property — taking the best option now can still lead to the overall best answer.
  • Optimal substructure — the best overall answer contains the best answers to its smaller parts.
  • Counterexample — one case where the statement fails. One is enough to disprove “always”.

Verdict: the statement is false. The book says plainly that in the greedy method there is no guarantee of getting the optimum solution (§3.5.5). A greedy algorithm is optimal only when the problem satisfies:

  • Greedy-choice property — a globally optimal solution can be reached by making locally optimal choices;
  • Optimal substructure — an optimal solution contains optimal solutions of its subproblems.

Counterexample, step by step — 0/1 knapsack (take whole items only)

Capacity 10. Items (weight, profit) = (6, 30), (5, 25), (5, 25).

  1. Compute each ratio: 30/6 = 5, 25/5 = 5, 25/5 = 5. Why: the greedy rule uses value per kg.
  2. All ratios tie at 5. Greedy takes the first item, the 6 kg one. Why: it is “best” by the rule, and there is no tie-break rule that looks ahead.
  3. Profit is now 30. Remaining capacity is 10 − 6 = 4. Why: each chosen item uses space.
  4. The next items weigh 5 kg each. Neither fits in 4 kg, so greedy stops at profit 30.
  5. The optimum is both 5 kg items. Weight 10, profit 25 + 25 = 50. So greedy loses by 20.

Why it fails here: the 0/1 restriction means an item cannot be split. A choice that looks best now can leave space that is too small for anything else. The book's Example 3.2.8 shows the same limitation — after selecting by p/w ratio, object 5 cannot be taken because it does not fit, and no fraction is allowed.

Where it does work: fractional knapsack, job sequencing with deadlines, activity selection, minimum spanning tree, single-source shortest path and Huffman tree (the book's list of greedy applications).

Real-life analogy: a traveller with a 10 kg bag grabs one 6 kg item because it has the best value per kg. Later, two 5 kg items would have given more total value, but they no longer fit. Greedy never gets to undo the first grab.
Common confusion: do not say “greedy failed because it picked the heaviest item”. It picked by ratio; all ratios were equal. The failure comes from the all-or-nothing rule plus a tie that greedy cannot resolve by looking ahead. Also, one counterexample is enough — you do not need to prove every case fails.

3.2 Fractional knapsack & greedy knapsack

Q1Give a mathematical formulation for: (i) Fractional Knapsack problem (ii) 0/1 Knapsack problem.

8 marks★ 1×

Asked in: 2025 May Q1(a) [8]

In simple words: Both problems ask “which items should go into a bag of limited capacity to earn the most profit?”. In fractional knapsack you may cut an item and take a part. In 0/1 knapsack you must take the whole item or leave it.

Why we do this

A formula removes confusion. It states exactly what we maximise, what limits us, and what values the variables may take. Once the formula is clear, the correct algorithm choice becomes obvious.

Words you need first

  • Objective function — the quantity we want to make as large as possible. Here it is total profit.
  • Constraint — a rule the answer must obey. Here it is the weight limit.
  • Feasible solution — any selection that obeys every constraint.
  • Optimal solution — the feasible selection with the best objective value (book §3.1.1).
  • Divisible — an item can be split into parts, like sugar.
Real-life analogy: fractional knapsack is buying sugar by weight — 2.5 kg is fine. 0/1 knapsack is buying a sealed 5 kg packet — you take the whole packet or none.

Let there be n items. Item i has weight wi > 0 and profit pi > 0. The capacity is m (the book uses W). xi is the fraction of item i selected.

How to write the formulation (4 steps)

  1. Name the decision variable. xi says how much of item i we take. Why: the answer must be written as numbers we can choose.
  2. Write the objective. Maximise Z = Σ pixi. Why: profit grows with the amount taken.
  3. Write the capacity constraint. Σ wixi ≤ m. Why: the bag cannot hold more than its capacity.
  4. Write the allowed values. 0 ≤ xi ≤ 1 for fractional, xi = 0 or 1 for 0/1. Why: this one line is the only real difference between the two problems.

(i) Fractional knapsack (book §3.2)

Maximize  Z = Σi=1..n pi xi
Subject to  Σi=1..n wi xi ≤ m
and  0 ≤ xi ≤ 1    for i = 1, 2, …, n

What this means: “Maximise” sets the goal. “Subject to” lists the limits. The last line allows a fraction, so the bag can be filled exactly.

Items are divisible: a fraction of an item may be placed in the knapsack. The greedy algorithm sorts by pi/wi and takes items in that order, taking a fraction of the last item if needed.

(ii) 0/1 knapsack (book §3.8)

Maximize  Z = Σi=1..n pi xi
Subject to  Σi=1..n wi xi ≤ W
and  xi = 0 or 1    for i = 1, 2, …, n

What this means: xi = 1 means “take the whole item”; xi = 0 means “leave it”. There is no middle value.

Each item is either taken completely or rejected. The book states that the objective is the maximum profit earned; because of the 0/1 restriction the ratio rule can fail, so dynamic programming is used.

Key difference: in fractional knapsack the last item may be split (0 ≤ xi ≤ 1); in 0/1 knapsack only 0 or 1 is allowed. That single change is why fractional knapsack is greedy-solvable and 0/1 knapsack needs DP.
Common confusion: students write xi ≤ 1 for 0/1 knapsack, or allow fractions in the 0/1 formula. Match the allowed values to the problem. Also, ≤ m is correct — the bag does not have to be filled exactly.

Q2Find an optimal solution for the knapsack instance using greedy method. n = 5, capacity m = 100.
Objects 01–05, Weight 20/30/66/40/60, Profit 10/20/30/40/50

8 marks★ 1×

Asked in: 2024 May Q1(b) [8]

In simple words: Put the items with the best profit per kg into the bag first. Keep going until the bag is full. If the next item is too big, take only the part that fits.

Why we do this

The bag has a fixed capacity, so every kg must earn as much as possible. Profit per kg lets us compare a light costly item with a heavy cheap one in a fair way.

Words you need first

  • Capacity — the maximum total weight the bag can hold.
  • Profit/weight ratio — profit earned by one unit of weight, p/w.
  • Fraction — a part of an item, such as half of it. Only allowed in fractional knapsack.
Real-life analogy: you fill a jar with the most valuable grain first. If the jar has a little space left, you pour in part of the next grain. You do not waste space.

Step-by-step method

  1. Compute p/w for every item. Why: this compares items fairly, no matter how heavy they are.
  2. Sort from largest ratio to smallest. Why: the best value per kg should get the first chance at the space.
  3. Take items in that order while they fit. Why: each full item uses capacity and adds its full profit.
  4. If the next item is too big, take only the fraction that fills the bag. Why: fractional knapsack allows part of an item, so no space is wasted.
  5. Stop when the bag is full. Why: no more weight can be added.

3.3 Job sequencing with deadlines ★★★★ 4×

This is the single most repeated Unit-3 question. Learn the algorithm and the three solved instances below.

Q1What is job scheduling algorithm? How can it be solved using the greedy approach? Explain with respect to principle, control abstraction and time analysis, for the given instance.
Jobs J1–J5, Deadline 2,1,3,2,1, Profit 60,100,20,40,20

12 marks★★★★ 4×

Asked in: 2023 Nov Q2(a) [12] · related: 2023 Nov Q2(b) [6 — steps] · 2023 Nov Q1(a) [9] · 2025 Nov Q1(b) [8]

In simple words: Each job takes one hour, has a deadline, and pays a profit. Do the highest-profit jobs first. Place each job in the latest free hour before its deadline. If no such hour is free, drop the job.

Why we do this

We have more jobs than time. Doing every job is impossible. We want the set of jobs that earns the most money while every chosen job still finishes by its deadline.

Words you need first

  • Job — one task. Here every job takes exactly one unit of time (one hour).
  • Deadline di — the last hour in which job i may finish. A deadline of 3 means the job can run in hour 1, 2 or 3.
  • Profit pi — money earned only if the job finishes by its deadline.
  • Slot — one free hour in the schedule. Slot 1 is the first hour, slot 2 the second, and so on.
  • Feasible sequence — an order of jobs in which every job finishes by its deadline.
  • Discard — leave a job out because no allowed slot is free.
  • Optimal sequence — the feasible order with the highest total profit.
  • J array — the timetable. J[r] stores the job placed in slot r.
Real-life analogy: a clinic books patients into hourly slots. The most valuable patients are booked first. Each is placed in the latest slot they can accept, so earlier slots stay free for patients who can only come early. If no slot fits, that patient is not booked.

Problem statement (book §3.3)

There are n jobs to be executed. Each job takes one unit of time, has deadline di and gives profit pi only if it is completed within its deadline. At any time only one job runs. We must obtain a feasible sequence that maximises the total profit.

The book's rules: a job started before or at its deadline earns profit, otherwise no profit; consider all schedules and choose the one with maximum profit. A feasible sequence is one in which every job finishes by its deadline.

Greedy strategy (book's 4 steps, §3.3)

  1. Arrange the jobs in descending order of profit. Why: a high-profit job should get a slot before a low-profit one takes it.
  2. Create a job array J[1..n] and keep all slots free. Why: we need a place to record which job runs in which hour.
  3. For each job in that order, try the slot equal to its deadline. If that slot is occupied, search an earlier free slot (< di). If no free slot exists, discard the job. Why latest slot: using the latest possible hour keeps early hours free for jobs with tight deadlines.
  4. Read the filled array from left to right — that is the optimal sequence. Why: slot 1 runs first, slot 2 next, and so on.

Algorithm Job_seq (book §3.3)

Algorithm Job_seq(p, d, n)
{
    Sort jobs so that p[1] ≥ p[2] ≥ … ≥ p[n];
    for r = 1 to n do J[r] = free;
    count = 0;

    for i = 1 to n do
    {
        r = d[i];                       // try the deadline slot
        while (r ≥ 1 and J[r] ≠ free) do
            r = r − 1;                  // search an earlier slot
        if (r ≥ 1) then
        {
            J[r] = i;                   // insert job i
            count = count + 1;
        }
        // if r = 0, no slot ≤ d[i] is free → discard job i
    }
    return J, count;
}

How to read the code: the outer for visits jobs from highest profit to lowest. The inner while walks left from the deadline until it finds a free slot. If r reaches 0, no slot at or before the deadline is free, so the job is dropped.

Time: the book states O(n²). For each job we may scan up to n slots, so n jobs × n slots. Sorting adds O(n log n). Space is O(n) for J.

In simple words: Pick the activity that finishes earliest. Then pick the next activity that starts after the chosen one ends. Repeat. This fits the largest number of activities into one room.

Why we do this

We have one resource, such as a lecture hall or a CPU. Two activities cannot run at the same time. Finishing early frees the resource sooner, so more activities can follow.

Words you need first

  • Activity — one task with a start time Si and a finish time Fi.
  • Compatible — two activities do not overlap. The next one may start exactly when the previous one ends.
  • Maximum-size subset — the largest possible number of activities, not the largest total duration.
Real-life analogy: you manage one meeting room. You accept the meeting that ends soonest, so the room becomes free for the next group. A long meeting that blocks the whole morning is a bad first choice, even if it is important.

Definition (book §3.4)

Given a resource such as a CPU or a lecture hall and n activities, activity i has start time Si and finish time Fi. The activity-selection problem is to find a maximum-size subset of mutually compatible activities — that is, maximise the number of lectures in the hall or tasks assigned to the CPU.

Greedy rule

Sort the activities by finish time in non-decreasing order. Select the first activity. Then repeatedly select the next activity whose Si ≥ Flast. Choosing the earliest finish leaves the maximum room for the remaining activities.

Algorithm Greedy_Act_sel (book §3.4)

Algorithm Greedy_Act_sel(S, F)
{
    n = length[S];

        }
    }

3.5 Dynamic programming — principle & control abstraction

Q1Explain the dynamic programming approach. Write the control abstraction and comment on its time complexity.

8 marks★★★ 3×

Asked in: 2022 Nov Q2(b) [8] · 2024 May Q2(a) [8] · 2025 Nov Q2(a) [7]

In simple words: Dynamic programming (DP) solves a big problem by solving small parts once. It writes each small answer in a table. Then it builds bigger answers from those stored answers, so no part is calculated twice.

Why we do this

Some problems repeat the same smaller problem many times. Plain recursion solves it again and again, which is slow. A table turns repeated work into one lookup.

Words you need first

  • Subproblem — a smaller version of the main problem, such as “best profit using the first 2 items”.
  • State — the set of numbers that describes one subproblem, such as (item number, capacity).
  • Overlapping subproblems — the same state appears through more than one path, so it would be solved many times without a table.
  • Optimal substructure — the best overall answer is built from best answers to smaller parts.
  • Control abstraction — a general algorithm skeleton with the problem-specific details left as blanks.
  • Bottom-up — solve the smallest states first, then larger ones, filling the table in order.
Real-life analogy: you write answers to practice sums in a notebook. When a later sum needs an earlier answer, you copy it from the notebook instead of solving it again. DP is that notebook, kept in a fixed order.

What is dynamic programming? (book §3.5)

Dynamic programming was invented by Richard Bellman in 1950. It is a technique for solving problems that have overlapping subproblems. Each subproblem is solved only once, and its result is recorded in a table; the final solution is then obtained from that table. It is typically applied to optimization problems, where we want the minimum or maximum value among many possible solutions.

Steps of dynamic programming (book §3.5.1) — and why each step exists

  1. Characterise the structure of an optimal solution. Write down what a solution looks like and what its parts are. Why: you cannot store an answer until you know what defines it.
  2. Recursively define the value of an optimal solution. Write a formula that gets a big answer from smaller answers. Why: this formula is the engine of DP.
  3. Compute the value bottom-up. Fill the table from small states to large states. Why: when a state needs smaller states, they are already in the table.
  4. Compute an optimal solution from the stored information. Use the stored choices to rebuild the actual answer, not just its value. Why: the exam usually asks which items, which order, or which root.

Control abstraction (bottom-up table filling)

This skeleton has four jobs: set the base cases, visit states from small to large, try every choice for each state, and keep the best. Only the meaning of “state” and “choice” changes per problem.

Algorithm DynamicProgramming(n)
{
    // table[] stores the optimum value of every subproblem
    for each base subproblem do
        table[base] = base value;

    for each subproblem in increasing order of size do
    {
        table[state] = worst value;              // +∞ for min, −∞ for max
        for each choice c of that subproblem do
        {
            value = cost(c) + table[smaller state(c)];
            if value is better than table[state] then
            {
                table[state] = value;
                decision[state] = c;             // remember the choice
            }
        }
    }
    return table[full problem];
}

How to read the code:

  1. Fill the base cases. These are the smallest states, whose answers are known directly. Why: every larger state eventually depends on them.
  2. Visit states in increasing size. Why: a state can then read smaller states that are already filled.
  3. Start with the worst value (+∞ for a minimum problem, −∞ for a maximum problem). Why: the first real choice must beat this placeholder.
  4. Try each choice. Add the cost of this choice to the stored answer of the smaller state it leads to. Why: this tests one complete way to build the state.
  5. Keep the best value and remember the choice. Why: the value answers “how good”, the choice answers “how”.
  6. Return the full problem's cell. Why: the largest state is the answer.

A tiny example — Fibonacci numbers

Fibonacci numbers start 0, 1, 1, 2, 3, 5, …; each one is the sum of the previous two. To get F(5) we need F(4) and F(3). To get F(4) we need F(3) again. Plain recursion computes F(3) twice. DP computes F(0), F(1), F(2), F(3), F(4), F(5) once each, in that order. That is the whole idea: store, then reuse.

Elements (book §3.5.3)

  • Optimal substructure — the optimal solution contains optimal solutions of its subproblems.
  • Overlapping subproblems — the same subproblem is solved many times, so storing its result avoids repeated work.

Time analysis

T(n) = (number of distinct states) × (choices per state) × (cost per choice)

What this means: count the number of table cells, multiply by the number of choices tried in each cell, then multiply by the work per choice.

  • 0/1 knapsack: table of (n + 1) × (W + 1) entries → O(nW).
  • Matrix chain multiplication: O(n²) states × O(n) splits → O(n³).
  • Optimal BST: O(n³) (the book notes Knuth's improvement to O(n²)).
  • Binomial coefficients: A(n,k) = nk additions → Θ(nk). This means the work grows in proportion to n × k.
  • Space equals the table size: O(nW), O(n²), etc.

The book lists the main applications as multistage graph, travelling salesman, matrix multiplication, longest common subsequence, maximum flow and all-pairs shortest path.

Common confusion: DP is not “recursion only”. Plain recursion without stored answers is still slow. DP is also not divide and conquer: divide-and-conquer parts are independent, while DP parts overlap. And “dynamic” does not mean the program changes while running; it is just the historical name.

Q2With respect to dynamic programming, what is the principle of optimality? Give a mathematical representation.

7 marks★★ 2×

Asked in: 2025 May Q2(a) [7] · related: 2024 May Q1(c) [4]

In simple words: If a full answer is the best possible, then every piece of it must also be the best way to solve that piece. This lets us build a big best answer from small best answers.

Why we do this

DP works by combining answers to smaller parts. That is only safe if a best full answer never contains a badly solved part. The principle of optimality is the promise that makes this safe.

Words you need first

  • Optimal — the best possible answer under the problem's rules.
  • Subsequence of decisions — the later decisions that remain after the first decision is fixed.
  • Subproblem — the smaller problem that remains after one decision.
  • Principle of optimality — in a best sequence of choices, every later part must also be best for the problem it faces.
Real-life analogy: the fastest route from Delhi to Pune goes through Mumbai. Then the Delhi-to-Mumbai part must itself be the fastest Delhi-to-Mumbai route. If a faster one existed, swapping it in would make the whole trip faster — a contradiction.

Statement (book §3.5.2)

The principle of optimality states: “In an optimal sequence of decisions or choices, each subsequence must also be optimal.” In other words, whatever the first decision is, the remaining decisions must form an optimal solution for the subproblem that results from that first decision.

The book adds: a DP algorithm obtains its solution using this principle, and when the principle cannot be applied it is almost impossible to obtain the solution by dynamic programming.

Mathematical representation

Let OPT(i, j) be the optimum cost for the subproblem from i to j, and let the first decision split it at k. Then the optimum is built from optimum subsolutions:

OPT(i, j) = mini ≤ k < j { OPT(i, k) + OPT(k+1, j) + cost(i, k, j) }

What this means: “min over k” means try every possible first split. For each split, add the best cost of the left part, the best cost of the right part, and the cost of joining them. Keep the smallest total.

For matrix chain multiplication the book writes this as:

m[i, j] = mini ≤ k < j { m[i, k] + m[k+1, j] + Pi−1 Pk Pj },    m[i, i] = 0

What this means: m[i, j] is the cheapest way to multiply matrices i to j. The last multiplication joins a left chain and a right chain, and that join costs Pi−1 · Pk · Pj.

For a shortest path from s to t through v, the same idea gives:

d(s, t) = d(s, v) + d(v, t)

That is, every sub-path of a shortest path is itself a shortest path — the book's example of the principle of optimality.

Book's proof for OBST (Example 3.7.1), step by step

  1. Assume the left subtree L of the optimal tree is not optimal. Why: this is a proof by contradiction — we suppose the opposite of what we want to prove.
  2. Then a cheaper left subtree L′ exists. Replace L with L′ and keep the same root and right subtree. Why: the tree's sorted order is unchanged, so it is still a valid search tree.
  3. The new cost is C(L′) + C(R) + W. Since C(L′) < C(L), the new cost is smaller than the old cost. Why: the root and right part did not change, so only the left cost went down.
  4. This contradicts the claim that the old tree was optimal. Therefore L must be optimal. The same argument shows R must be optimal. Why: an optimal tree cannot contain a part that can be improved.

When it fails

Longest simple path has no optimal substructure. A longest path from A to D through B need not contain the longest path from A to B, because that sub-path may already use a vertex needed later. DP cannot be applied to such a problem.

Common confusion: the principle of optimality is not the same as the greedy-choice property. Greedy needs “best now is safe”. DP needs “best whole contains best parts”. Also, the principle does not say every sub-path of any path is optimal; it says the sub-parts of an optimal solution must be optimal for their own subproblem.

Q3Comment on the statement: "A problem which does not satisfy the principle of optimality cannot be solved by dynamic programming."

4 marks★ 1×

Asked in: 2024 May Q1(c) [4]

In simple words: The statement is true in the sense the book uses. Dynamic programming (DP) builds a big best answer out of small best answers. If a best part can lead to a bad whole, that building method cannot be trusted.

Why we do this

This is a short “comment” question. You must state a verdict, explain the DP assumption, and give one example where the assumption holds and one where it fails.

Words you need first

  • Principle of optimality — a best full answer is made of best answers to its parts.
  • Recurrence — a formula that computes a big answer from smaller answers.
  • Feasible — allowed by the rules, even if not the best.
  • NP-hard — a problem for which no known fast exact algorithm exists; the running time grows too quickly as the input grows.

Verdict: the statement is true in the sense used by the book. Dynamic programming builds the global optimum from optimal solutions of subproblems — it “makes use of the principle of optimality to find the optimal solution from subproblems” (book §3.5.3).

Step-by-step argument

  1. DP's formula assumes a best whole is made of best parts. For example, OPT(i,j) = combine(OPT of parts). Why: the formula only stores one best value per part.
  2. If the principle fails, a best-looking part may be a bad choice for the whole. Why: the part was optimised for itself, not for the larger problem.
  3. Then the stored value can lead to a worse or invalid full answer. Why: DP has thrown away the other candidate parts, so it cannot recover.
  4. Therefore DP cannot guarantee the correct optimum. Why: a guarantee needs a proof that the formula is valid for every input.

The book states: “When it is not possible to apply the principle of optimality it is almost impossible to obtain the solution using the dynamic programming approach.”

Example where it holds: shortest path — every sub-path of a shortest path is a shortest path, so Floyd–Warshall and the MCM recurrence work.

Example where it fails: longest simple path — the longest path from A to D through B may not contain the longest A–B path, because that sub-path can use a vertex needed later. No DP recurrence gives the correct answer; the problem is NP-hard.

Real-life analogy: a relay team's best total time is not always made of the four fastest runners. A runner who is fast alone may refuse the baton change. The “best part” depends on the whole team, so you cannot pick each leg independently.
Common confusion: “cannot be solved by DP” does not mean “no program can ever solve it”. It means DP cannot guarantee the optimum. DP may still run and return a feasible answer, but without the principle that answer may not be the best. Write this distinction for the 4th mark.

3.6 Matrix chain multiplication ★★ 2×

Q1Solve the matrix chain multiplication for the 6-matrix problem using dynamic programming.
Dimensions: A1 10×20, A2 20×5, A3 5×15, A4 15×50, A5 50×10, A6 10×15

10 marks★★ 2×

Asked in: 2022 Nov Q1(a) [10] · same pattern: 2024 May Q2(b) [10]

In simple words: Multiplying matrices is expensive. The order in which we multiply them changes the cost a lot. Dynamic programming (DP) compares every possible place to split the chain, saves the cheapest result for each part, and builds the cheapest full order.

Why we do this

The final product is the same for every order, because matrix multiplication is associative. Associative means (AB)C = A(BC): changing the brackets does not change the product. Only the number of scalar multiplications changes. A smart order can save a huge amount of work, so we let DP find it.

Words you need first

  • Matrix — a grid of numbers. A matrix with p rows and q columns is called p×q.
  • Scalar multiplication — one number-times-number multiplication inside matrix multiplication. We count these.
  • Chain — matrices written side by side, such as A1A2A3.
  • Parenthesisation — the order of multiplication, shown by brackets. (A1A2)A3 and A1(A2A3) are different parenthesizations.
  • m[i][j] — the minimum cost to multiply matrices i through j.
  • s[i][j] — the split point k that gives that minimum. It is used to rebuild the brackets.
Real-life analogy: you must combine four parcels into one. Combining two small parcels is cheap; combining two huge parcels is expensive. The cheapest order of combining depends on the sizes, so you plan the order before you start.

Problem (book §3.9)

Given n matrices A1, A2, …, An with dimensions P1×P2, P2×P3, …, Pn×Pn+1, compute the product A1A2…An using the minimum number of scalar multiplications.

Multiplying a p×q matrix by a q×r matrix costs p·q·r scalar multiplications. The book's 3-matrix example: (5×4)(4×6)(6×2) costs 180 as (A1A2)A3 but only 88 as A1(A2A3). Same matrices, different cost — that is why order matters.

Recurrence (book Step 2)

m[i, i] = 0
m[i, j] = mini ≤ k < j { m[i, k] + m[k+1, j] + Pi−1 · Pk · Pj }

What this means: m[i][i] = 0 because one matrix needs no multiplication. For a chain i…j, try every split k. The left part i…k and right part k+1…j are already solved. The final join costs Pi−1 · Pk · Pj.

Here m[i][j] = minimum cost for Ai…Aj; s[i][j] = the split k that gives it.

Algorithm Matrix_chain (book §3.9.1)

Matrix_chain(P[0..n])
{
    for i = 1 to n do m[i, i] = 0;

    for len = 2 to n do
        for i = 1 to (n − len + 1) do
        {
            j = i + len − 1;
            m[i, j] = ∞;
            for k = i to j − 1 do
            {
                q = m[i, k] + m[k+1, j] + P[i−1]*P[k]*P[j];
                if (q < m[i, j]) then
                {
                    m[i, j] = q;
                    s[i, j] = k;
                }
            }
        }
    return m[1, n];
}

How to read the code: the outer loop fixes the chain length. The middle loop fixes the start i. The inner loop tries every split k. q is the cost of one split, and the smallest q is stored with its split.

3.7 Optimal binary search tree (OBST)

Q1Write a dynamic programming algorithm for creating an optimal binary search tree for n keys, and construct the OBST for the 4 given keys.
Keys A, B, C, D with probabilities 0.1, 0.2, 0.4, 0.3

10 marks★ 1×

Asked in: 2022 Nov Q2(a) [10]

In simple words: Put the words you search most often near the top of the tree. Then most searches finish after a few comparisons. Dynamic programming (DP) finds the arrangement with the smallest average search cost.

Why we do this

In a binary search tree, a key at depth d needs d + 1 comparisons. Common keys should sit shallow. Rare keys can sit deep. The best shape depends on the probabilities, so we calculate it instead of guessing.

Words you need first

  • Binary search tree (BST) — a tree where every left key is smaller than the root and every right key is larger.
  • Root — the top node of the tree. Child — a node directly below another node.
  • Depth — the number of edges from the root down to a node. The root has depth 0.
  • Key — the value we search for, such as A, B, C or D.
  • Probability p(i) — the chance that key i is searched. A larger value means the key is more common.
  • Successful search — the key is found. Unsuccessful search — the key is absent.
  • Expected cost — the average number of comparisons, weighted by how often each search happens.
  • Wij — the total probability weight of the keys in the range i…j.
  • Cij — the minimum cost for that range.
  • rij — the root chosen for that range.
Real-life analogy: your contacts app shows favourite people at the top. You reach them with one tap; rarely messaged people take more scrolling. OBST arranges keys the same way, with the most-searched key easiest to reach.

Problem (book §3.7)

When we search words in a dictionary, frequently used words should be placed near the root so that the average search time is small. Such a tree — arranged to minimise the search cost — is an optimal binary search tree (OBST).

Given identifiers a1 < a2 < … < an, let p(i) be the probability of a successful search for ai and q(i) the probability of an unsuccessful search between ai and ai+1. We want a tree with minimum cost Σp(i) + Σq(i).

Notation and recurrence (book Steps 1–3)

  • Tij = OBST for keys ai+1 … aj; Cij = its cost; Wij = its weight; rij = its root.
  • Base: Cii = 0, Wii = qi; a single node has Wi,i+1 = qi + qi+1 + pi+1 and Ci,i+1 = Wi,i+1.
  • Wij = Wi,j−1 + pj + qj.
Cij = mini < k ≤ j { Ci,k−1 + Ck,j } + Wij
rij = k that gives the minimum

What this means: try each key k as the root. The left range and right range are solved separately. Add their costs, then add Wij once.

The cost formula comes from C(T0n) = C(L) + C(R) + W, where W = p1 + … + pn + q0 + … + qn.

Why add W once: when a subtree is attached under a new root, every node in it gains one extra comparison. Adding W adds one comparison for every key in the range, weighted by its probability.

Algorithm OBST (book §3.7.1)

Algorithm OBST(p, q, n)
{
    for i = 0 to n do
    {
        C[i][i] = 0;
        r[i][i] = 0;
        W[i][i] = q[i];
    }

    for i = 0 to n−1 do
    {
        W[i][i+1] = q[i] + q[i+1] + p[i+1];
        C[i][i+1] = W[i][i+1];
        r[i][i+1] = i+1;
    }

    for m = 2 to n do
        for i = 0 to n−m do
        {
            j = i + m;
            W[i][j] = W[i][j−1] + p[j] + q[j];
            C[i][j] = min over i < k ≤ j of { C[i][k−1] + C[k][j] } + W[i][j];
            r[i][j] = k giving the minimum;
        }
    return C[0][n], r;
}

How to read the code: first fill the empty ranges and single-key ranges. Then grow the range length m from 2 to n. For each range, try every key k as root, keep the cheapest, and store that k in r.

Time O(n³), space O(n²). There are O(n²) ranges, and each tries O(n) roots. The book notes that Knuth's range restriction improves it to O(n²).

Step-by-step method

  1. Set the base cases. C[i][i] = 0 and W[i][i] = qi. Why: an empty range costs nothing.
  2. Fill every one-key range. Its cost equals its weight. Why: one comparison finds the only key.
  3. Grow the range length from 2 to n. For each range, try every key k as the root. Why: every possible root must be tested before choosing.
  4. Add left cost + right cost + W. Keep the smallest total and store its root. Why: this is the recurrence in action.
  5. Read the root of the full range. Split left and right, then repeat on each part. Why: the stored roots rebuild the tree.

3.8 0/1 Knapsack using dynamic programming ★★ 2×

Q1Find the optimal solution of the 0/1 knapsack problem using dynamic programming.
Items (weight, profit): (2,12), (1,10), (3,20), (2,15). Capacity = 5.

9 marks★★ 2×

Asked in: 2023 Nov Q1(b) [9] · 2025 May Q2(b) [10 — capacity 7, items (1,1),(3,4),(4,5),(5,7)]

In simple words: For each item, you have two choices: take it or skip it. Dynamic programming (DP) records the best profit for every item count and every capacity. Then it reads the table backwards to find which items were taken.

Why we do this

Greedy can fail here because a heavy high-value item may block two lighter items that together earn more. DP avoids that mistake by comparing “take” and “skip” for every capacity.

Words you need first

  • State — one table cell, described by two numbers: which items are allowed and how much capacity is left.
  • table[i][j] — the best profit using the first i items with capacity j.
  • Skip — do not take item i. The answer is the best profit without it.
  • Take — include item i. It adds pi profit and uses wi capacity.
  • Backtracking — walking back through the table to list the chosen items.
Real-life analogy: you keep a notebook with one page per number of items and one column per remaining bag space. Each cell says “best profit so far”. For a new item you compare the old best with “take it plus the best using the space left”.

Problem and recurrence (book §3.8)

Given n objects, object i has weight wi and profit pi; the knapsack capacity is W. Choose xi ∈ {0,1} to maximise Σpixi subject to Σwixi ≤ W.

table[i, j] = max{ table[i−1, j],   pi + table[i−1, j−wi] }   if j ≥ wi
table[i, j] = table[i−1, j]   if j < wi
table[0, j] = 0,   table[i, 0] = 0

What this means: for each cell, take the better of two options. Option 1 is skip: copy the row above. Option 2 is take: add this item's profit to the best answer for the remaining capacity, using only earlier items. If the item is heavier than the current capacity, only skip is possible.

table[i, j] = best profit using the first i objects with capacity j. The answer is table[n, W]. To recover the items, compare table[i, k] with table[i−1, k]: if different, take item i and set k = k − wi; otherwise skip item i and set i = i − 1.

Algorithm Knapsack01 (book's table method)

Knapsack01(w[], p[], n, W)
{
    for j = 0 to W do table[0][j] = 0;
    for i = 0 to n do table[i][0] = 0;

    for i = 1 to n do
        for j = 0 to W do
        {
            if (w[i] > j) then
                table[i][j] = table[i−1][j];
            else
                table[i][j] = max(table[i−1][j],
                                  p[i] + table[i−1][j−w[i]]);
        }
    return table[n][W];
}

How to read the code: row 0 means “no items”, so every profit is 0. Column 0 means “no capacity”, so every profit is 0. For each item and each capacity, the code chooses the better of skip and take.

Time O(nW), space O(nW). There are n rows and W + 1 columns, and each cell does constant work.

Step-by-step method

  1. Make row 0 and column 0 zero. Why: no items means no profit; no capacity means no item fits.
  2. Visit items one by one, from item 1 to item n. Why: each row builds on the row above.
  3. For each capacity j, check whether the item fits. If wi > j, it cannot be taken. Why: the bag is too small.
  4. If it fits, compare skip and take. Skip copies the cell above. Take adds pi to the cell at j − wi. Why: these are the only two choices.
  5. Store the larger value. Why: we want the best profit, not just any profit.
  6. Read table[n][W] for the answer. Then backtrack to list the chosen items. Why: the value alone does not say which items were taken.

3.9 Binomial coefficients using DP

Q1Find the binomial coefficients of (x + y)5 using the dynamic programming approach.

10 marks★ 1×

Asked in: 2025 Nov Q2(b) [10]

In simple words: The coefficients of (x + y)5 are row 5 of Pascal's triangle (the sixth row, counting row 0). Each number is the sum of the two numbers above it. Dynamic programming (DP) builds the rows one by one and reuses the previous row.

Why we do this

The direct formula uses large factorials (products like 1 × 2 × … × n), and plain recursion computes the same smaller values again and again. Building rows from top to bottom computes every value once. It is easy to do by hand and easy to code.

Words you need first

  • Binomial coefficient C(n, k) — the number of ways to choose k items from n items. In the expansion, it is the coefficient of the term with k copies of y.
  • Pascal's identity — C(n, k) = C(n−1, k−1) + C(n−1, k). Each entry is the sum of the two entries above it.
  • Row — all coefficients for one power n. Row n has n + 1 entries, for k = 0 to n.
  • Pascal's triangle — the triangle formed by writing all rows one below another, with 1s at the edges.
Real-life analogy: Pascal's triangle is a wall of bricks. Each brick rests on the two bricks above it, and its value is their sum. You build the wall from the top down, one row at a time.

Definition (book §3.6)

Computing a binomial coefficient is a typical example of dynamic programming. In the expansion of (a + b)n, the coefficient of a term is denoted by C(n, k) or nCk, where 0 ≤ k ≤ n.

Recurrence (Pascal's identity)

C(n, k) = C(n−1, k−1) + C(n−1, k)    for n > k > 0
C(n, 0) = 1,   C(n, n) = 1

What this means: the two edge values are always 1. Every inside value is the sum of the two values directly above it in the previous row. Direct recursion is exponential because C(n−1,k−1) and C(n−1,k) overlap. DP fills Pascal's triangle row by row, so every value is computed once.

Algorithm Binomial (book §3.6)

Algorithm Binomial(n, k)
{
    for i = 0 to n do
        for j = 0 to min(i, k) do     // book: k is taken as min(i, k)
        {
            if (j = 0 or i = j) then
                C[i][j] = 1;
            else
                C[i][j] = C[i−1][j−1] + C[i−1][j];
        }
    return C[n][k];
}

How to read the code: i is the current row, j is the position in that row. The edges (j = 0 or i = j) are set to 1. Every other cell adds the two cells above it.

Analysis: the basic operation is one addition. The book counts A(n,k) = nk additions, so the time complexity is Θ(nk); space is O(nk), which can be reduced to O(k) by keeping only the previous row.

Step-by-step for n = 5

  1. Write row 0 as just 1. Why: (x + y)0 = 1, so there is one coefficient.
  2. Start each new row with 1. Why: the first term always has coefficient 1.
  3. Add the two numbers above to get each inside value. Why: this is Pascal's identity.
  4. End each new row with 1. Why: the last term always has coefficient 1.
  5. Repeat until row 5. Why: the question asks for the power 5.
  6. Read row 5 left to right. Why: these six numbers are the coefficients of the six terms.

Expansion

(x + y)5 = 1x5 + 5x4y + 10x3y2 + 10x2y3 + 5xy4 + 1y5

What this means: the powers of x count down from 5 to 0, and the powers of y count up from 0 to 5. The coefficients are row n = 5: 1, 5, 10, 10, 5, 1.

Book's example: C(4, 2) = C(3,1) + C(3,2) = 3 + 3 = 6; the book's C program prints The Binomial Coefficient C(4,2)=6. The same row-by-row method gives the n = 5 row above.
