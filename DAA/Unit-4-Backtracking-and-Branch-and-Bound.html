4.1 Backtracking — principle, control abstraction, time analysis

Q1Explain with a suitable example: Backtracking — principle, control abstraction, time analysis of control abstraction.

8 marks★★ 2×

Asked in: 2022 Nov Q3(b) [8] · 2023 Nov Q3(b) [8]

1. Principle (book §4.1)

Backtracking is a systematic trial-and-error method. The desired solution is an n-tuple (x1, x2, …, xn), where each xi is chosen from a finite set Si. The solution must maximise, minimise or satisfy a criterion function C(x1, …, xn).

  • The problem may be a decision problem (is there a feasible solution?), an optimisation problem (what is the best solution?) or an enumeration problem (list all feasible solutions).
  • The vector is built one component at a time. At every step the algorithm tests whether the partial vector has any chance of success. If it cannot lead to a solution, that partial vector is abandoned by the bounding function.
  • Backtracking is a depth-first search with bounding. It is better than brute force because whole subtrees are never generated.
  • Explicit constraints restrict each xi to its allowed set Si (for 8-queens, xi ∈ {1,…,8}). Implicit constraints decide which tuples satisfy the criterion (no two queens in the same row, column or diagonal; no repeated element in sum of subsets; the chosen weights must add to M).

Applications (book §4.3): 8-queens, sum of subsets, graph colouring, Hamiltonian cycle and knapsack.

2. State-space tree terms (book §4.1.1)

  • Problem state — every node of the tree.
  • Solution state / solution space — a path from the root that defines a tuple in the solution space.
  • Answer state — a leaf that satisfies the implicit constraints.
  • Live node — generated but its children are not yet fully generated. E-node — the live node whose children are being expanded. Dead node — a node not to be expanded further.
  • Bounding function Bk — kills live nodes without generating all their children, but care is taken that at least one answer node is produced.

3. Control abstraction (book §4.2, recursive)

Algorithm Backtrack(k)
// a[1..k] is a solution vector. On entering, k-1 values are fixed.
// T(a1,...,a_{k-1}) = set of all values for a_k such that
// (a1,...,a_k) is a path to a problem state.
// B_k is the bounding function.
{
    for (each a_k that belongs to T(a1, a2, ..., a_{k-1})) do
    {
        if (B_k(a1, a2, ..., a_k) = true) then      // feasible sequence
        {
            if ((a1, a2, ..., a_k) is a path to an answer node) then
                print(a[1], a[2], ..., a[k]);
            if (k < n) then
                Backtrack(k + 1);                   // find the next set
        }
    }
}

How to read it: T gives the legal values for the next component, and Bk rejects a partial vector early. If the partial vector is already an answer, it is printed; if not, the algorithm goes one level deeper. When no value remains, the recursion returns — this return is the backtrack.

The book also gives the iterative form Non_Rec_Backtrack(): it keeps k, tries the next untried value of a[k], prints the solution if it is an answer node, increments k on success, and executes k := k − 1 to backtrack when no value is left.

4. Time analysis (book §4.2)

The efficiency depends on four factors:

  1. time to generate a[k];
  2. number of a[k] values that satisfy the explicit constraints;
  3. time taken by the bounding function Bk to generate a feasible sequence;
  4. number of a[k] values that satisfy Bk for all k.

The first three factors are independent of the instance and take polynomial time. The fourth varies with the instance. If n! nodes satisfy the bounding function, then

T(n) = O(P(n) · n!)

where P(n) is the polynomial time of the first three factors. For particular problems: n-queens O(n!), sum of subsets O(2n), graph colouring O(n·mn). Space is O(n) for the solution vector and recursion stack.

5. Suitable example — 4-queens

Place queens row by row. The book's 4-queen state-space tree (Fig. 4.4.1) first tries a placement that reaches a dead end, backtracks, and finally gives the answer tuple (2, 4, 1, 3): queen 1 in column 2, queen 2 in column 4, queen 3 in column 1, queen 4 in column 3. No two queens share a row, column or diagonal. The book's 8-queens solution is the tuple (4, 6, 8, 2, 7, 1, 3, 5).

Key idea: brute force generates all mn vectors and tests them at the end; backtracking tests at every level, so a bad partial vector is killed immediately.

4.2 Sum of subsets ★★★★★ 5×

Q1State the sum of subsets problem. Write an algorithm using backtracking and comment on its time complexity.

8 marks★★★ 3×

Asked in: 2025 May Q4(a) [8] · algorithm also asked in 2024 May, 2023 Nov

Problem statement (book §4.6)

Let S = {s1, s2, …, sn} be a set of n positive integers and d a given positive integer. Find a subset of S whose sum is exactly d. It is convenient to sort the elements in ascending order: s1 ≤ s2 ≤ … ≤ sn.

Represent the choice by xi ∈ {0,1}: xi = 1 means si is selected, 0 means it is not. The constraint is

Σi=1..n sixi = d,   xi ∈ {0,1}

Backtracking algorithm (book's 6 steps)

  1. Start with an empty subset; sum = 0.
  2. Add the next element from the sorted list to the subset.
  3. If the subset sum is d, stop — this subset is a solution.
  4. If the subset is not feasible (sum exceeds d) or the end of the list is reached, backtrack through the subset until a suitable value is found.
  5. If the subset is feasible, repeat step 2.
  6. If all elements are visited and no suitable subset is found, and backtracking is no longer possible, stop without a solution.

The same procedure is written recursively below. Here s is the current sum, k is the next index, and r is the sum of the weights from k to n.

Algorithm SumOfSubsets(s, k, r)
{
    if (s = d) then
    {
        print the chosen subset;
        return;
    }
    if (k > n) then return;

    if (s + w[k] ≤ d) then          // include w[k]
        SumOfSubsets(s + w[k], k + 1, r − w[k]);

    if (s + r − w[k] ≥ d) then      // exclude w[k]
        SumOfSubsets(s, k + 1, r − w[k]);
}

The book's Example 4.6.2 starts with SumOfSubsets(0, 1, 55) for W = {7, 11, 13, 24} and m = 31. Its recursion tree (Fig. 4.6.2) produces the two solutions {7, 11, 13} and {7, 24}.

The search space is a binary state-space tree: at level i, the left edge means “include si” and the right edge means “exclude si”. The bounding function kills a node when its sum exceeds d, or when the remaining elements cannot possibly take the sum up to d.

Time complexity

In the worst case the tree is a full binary tree of depth n, so it has 2n leaves and the algorithm takes O(2n) time. Sorting costs O(n log n). The recursion stack and solution vector need O(n) space.

Why sort ascending? The book shows that a non-decreasing order finds solutions early and prunes more branches. A decreasing or unsorted list may examine every element for every subset and makes the computing time worst.

Q4Prove that the full state-space tree for finding a sum of subsets of n elements using backtracking has (excluding the leaf nodes) 2n − 1 nodes.

4 marks★ 1×

Asked in: 2025 May Q3(b) [4]

Proof

  1. Each element of the set has exactly two choices — include it (1) or exclude it (0). Therefore the state-space tree is a full binary tree of height n.
  2. A complete decision is made only at a leaf, so the number of leaves is 2n.
  3. In any full binary tree, the number of internal nodes is one less than the number of leaves: internal = leaves − 1.
  4. Hence the number of nodes excluding the leaves is 2n − 1.
Leaves = 2n  |  Internal nodes (excluding leaves) = 2n − 1
Total nodes = 2n+1 − 1

The book's Fig. 4.6.4 for S = {3, 4, 5, 6} shows this full binary tree: n = 4, so it has 16 leaves, 15 internal nodes and 31 nodes in total. Only the leaves that sum to d = 13 become answer states; the rest are pruned or dead.

Marks tip: state the two choices (include/exclude), then use the standard full-binary-tree result. One line of algebra and the n = 4 example are enough for 4 marks.

4.3 Graph colouring ★★★★ 4×

Q1Explain backtracking with the graph colouring problem. Write the recursive algorithm and give its time complexity.

8–9 marks★★★ 3×

Asked in: 2024 May Q3(a) [9] · 2025 Nov Q4(b) [8] · 2022 Nov Q4(b) [8 — with numerical]

Problem (book §4.5)

Given an undirected graph G = (V, E) and m colours, colour every vertex so that no two adjacent vertices have the same colour. This is the m-colouring problem. If the maximum degree of the graph is d, then d + 1 colours are always enough. The smallest number of colours needed is the chromatic number.

The book's Fig. 4.5.1 graph has chromatic number 3; one valid colouring is A = 1 (Red), B = 2 (Green), C = 3 (Blue), D = 1, E = 2, F = 3.

Backtracking formulation

  • The solution is a tuple x[1..n], where x[k] ∈ {1, 2, …, m} is the colour of vertex k.
  • The state-space tree has one level per vertex and m branches per level.
  • Bounding function: colour c is rejected for vertex k if any already-coloured neighbour j < k has G[k][j] = 1 and x[j] = c.
  • When no colour is left, x[k] = 0; the algorithm returns and the previous vertex tries its next colour — this is the backtrack.

Recursive algorithm (book §4.5.1)

Algorithm Gr_color(k)
// G[1:n, 1:n] is the adjacency matrix.
// x[k] is the legal colour assigned to vertex k.
{
    repeat
    {
        Gen_Col_Value(k);              // produce the next possible colour
        if (x[k] = 0) then
            return;                    // no new colour is possible
        if (k = n) then
            write(x[1..n]);            // all vertices are coloured
        else
            Gr_color(k + 1);           // choose the next vertex
    } until (false);
}

Algorithm Gen_Col_Value(k)
// x[k] = 0 if no legal colour exists.
{
    repeat
    {
        x[k] ← (x[k] + 1) mod (m + 1); // next colour index
        if (x[k] = 0) then
            return;                    // all m colours have been tried
        for j ← 1 to n do
        {
            if (G[k][j] = 1 and x[k] = x[j]) then
                break;                 // same colour as an adjacent vertex
        }
        if (j = n + 1) then
            return;                    // no conflict: colour is legal
    } until (false);
}

Time analysis (book §4.5.2)

At level 1 there are m choices, at level 2 up to m2, and so on. The total number of nodes generated is

Σi=0..n−1 mi = 1 + m + m2 + … + mn−1

Each colour check scans n vertices, so the total computing time is O(n · mn). Space is O(n) for x[] and the recursion stack.

Book's 4-step strategy

  1. Choose a colour c and apply it to some vertex v.
  2. Choose different colours from the available list for each successive vertex; after applying a colour, check whether it is the same as an adjacent colour.
  3. If the colour is not the same, go to the next adjacent vertex; otherwise try another colour from the list or change an already-assigned colour.
  4. Repeat for all vertices.
Bounding in action: in the book's Fig. 4.5.1 example, the search reaches a vertex where colours 1, 2 and 3 all conflict with neighbours. That node is a dead end, so the algorithm backtracks and changes an earlier vertex. The final colouring uses only 3 colours, which proves the chromatic number is 3.

4.4 Branch and Bound — fundamentals

Q1What is the Branch and Bound method? Write the control abstraction for Least-Cost search.

9 marks★★ 2×

Asked in: 2022 Nov Q4(a) [9] · control abstraction + applications: 2025 Nov Q3(b) [8]

What is Branch and Bound? (book §4.7)

Branch and Bound (BnB) is a general algorithm for finding optimal solutions of optimisation problems. It is used where greedy and dynamic programming fail, but it is slower; in the worst case it takes exponential time, although with good bounding it can run reasonably fast on average.

  • Branch — partition the problem at a node into smaller subproblems (generate its children).
  • Bound — compute a lower bound c^(x) and an upper bound u(x) for every child. If a child cannot contain a better answer than the best known, it is killed (pruned).
  • BnB builds the state-space tree and generates all children of the E-node before any other live node can become an E-node.
  • It may use BFS (FIFO queue) or DFS (LIFO stack). FIFO BnB is breadth-first; LIFO BnB is depth-first.

Three search strategies (book §4.9)

StrategyLive-node listE-node chosenSearch
FIFOQueueOldest live nodeBreadth-first
LIFOStackNewest live nodeDepth-first
LCHeap (priority queue)Smallest c^(x)Best-cost first

LC (Least Cost) uses a ranking function. Let g^(x) be an estimate of the extra effort needed to reach an answer node from x, and h(x) the cost of reaching x from the root. Define

c^(x) = f(h(x)) + g^(x)
  • If g^(x) = 0 and f(h(x)) = level of x, the search is BFS.
  • If f(h(x)) = 0 and g^(x) ≤ g^(y) whenever y is a child of x, the search is D-search (DFS).
  • LC search with a bounding function is called LC Branch and Bound (LCBB).

Control abstraction — general BnB (book §4.8)

Algorithm Branch_Bound()
{
    E ← new(node);          // root / dummy start node
    // H is the heap of all live nodes
    // min-heap for minimisation, max-heap for maximisation
    while (true)
    {
        if (E is a final leaf) then
        {
            write(path from E to the root);   // optimal solution
            return;
        }
        Expand(E);
        if (H is empty) then
        {
            write("there is no solution");
            return;
        }
        E ← delete_top(H);
    }
}

Algorithm Expand(E)
{
    Generate all children of E;
    Compute the approximate cost value of each child;
    Insert each child into the heap H;
}

Control abstraction — Least-Cost search (book §4.9)

Algorithm LC_search()
// tr is the state-space tree; x is a node; E is the E-node
{
    if (tr is an answer node) then
    {
        write(tr);
        return;
    }
    E ← tr;                              // set the E-node
    repeat
    {
        for (each child x of E) do
        {
            if (x is an answer node) then
            {
                output the path from x to the root;
                return;
            }
            Add_Node(x);                 // add x to the live-node list
            x.parent ← E;                // path from x to the root
        }
        if (no more live nodes) then
        {
            write("Can not have answer node!!");
            return;
        }
        E ← Least_cost();                // next E-node with least cost
    } until (false);
}

Each node gets a bounding value; the node with the optimum bound becomes the E-node, and children that cannot beat the current best are killed. The numbers outside the nodes show the order of evaluation.

Q2What are the major drawbacks of the branch and bound method?

4 marks★ 1×

Asked in: 2025 May Q3(c) [4]

Major drawbacks (from the book's discussion)

  • Slower than greedy and DP; exponential worst case. The book states that BnB applies where greedy and dynamic programming fail, but it is much slower. If the bound is weak, most children survive, no pruning happens, and the method degenerates to exhaustive search — O(2n) for knapsack/subsets or O(n!) for TSP.
  • Blind FIFO/LIFO selection; costly LC. The book says selecting the E-node using FIFO or LIFO is “very complicated and somewhat blind”. LC is better but needs a ranking/cost value c^(x) at every node; computing a tight bound (for example, fractional knapsack at every node) itself costs time.
  • Large live-node list. FIFO/LIFO/LC must store all live nodes in a queue, stack or heap; in the worst case this is exponential, unlike backtracking's O(n) stack.
  • Problem-specific bounds. A correct bounding function and branching rule need insight. The book warns that care must be taken while killing live nodes so that at least one answer node is still produced; a bad bound can remove the optimum.
  • No guaranteed early stop. Finding one complete solution is not enough; the search must continue until the bound proves that no unexplored node can beat it.
Exam-safe one-liner: BnB is exact but can be slow and memory-heavy; its speed depends entirely on how tight the bound is.

4.5 0/1 Knapsack using Branch and Bound

Q1Explain the branch and bound approach. Write a BnB algorithm for 0/1 knapsack and solve: capacity 15 kg, items A(9 kg, Rs.18), B(4 kg, Rs.10), C(6 kg, Rs.12), D(2 kg, Rs.10).

9 marks★★ 2×

Asked in: 2022 Nov Q3(a) [9] · 2023 Nov Q4(a) [9 — identical instance]

0/1 knapsack — book's formulation (book §4.12)

There are n objects and a knapsack of capacity m. Object i has weight wi and profit pi. Choose xi ∈ {0,1} to

maximise   Σ pixi   subject to   Σ wixi ≤ m

The book writes the same problem as minimise −Σpixi. It uses the fixed tuple size formulation: level i decides xi = 1 (include) or xi = 0 (exclude). For every node x,

c^(x) ≤ c(x) ≤ u(x)

where c^(x) is the lower bound (approximate least cost) and u(x) is the upper bound. A node is killed when its bound cannot lead to a better answer than the best solution already found.

BnB algorithm for 0/1 knapsack

Algorithm Knapsack_BB()
{
    sort items by p[i]/w[i] in decreasing order;
    best ← 0;  bestSet ← ∅;
    PQ ← empty max-heap;
    insert root with ub = C_Bound(0, 0, 0);
    while (PQ is not empty) do
    {
        node ← delete-max(PQ);          // highest upper bound
        if (node.ub ≤ best) then
            continue;                   // bound cannot beat best
        if (node.level = n) then
        {
            if (node.profit > best) then
            {
                best ← node.profit;
                bestSet ← node.set;
            }
        }
        else
        {
            // left child: include item level+1
            if (node.weight + w[node.level+1] ≤ m) then
                insert left child with ub = C_Bound(...);
            // right child: exclude item level+1
            insert right child with ub = C_Bound(...);
        }
    }
    return best, bestSet;
}

Algorithm C_Bound(total_profit, total_wt, k)
// optimistic bound: remaining items are taken fractionally
{
    pt ← total_profit;
    wt ← total_wt;
    for (i ← k+1 to n) do
    {
        wt ← wt + w[i];
        if (wt < m) then
            pt ← pt + p[i];
        else
            return (pt + (1 − (wt − m)/w[i]) * p[i]);
    }
    return pt;
}

The book also defines U_Bound, which adds only the items that fit completely. In the book's minimisation form the bounds are stored with a minus sign; for the PYQ we use the equivalent positive profit upper bound: ub = profit so far + fractional profit of the remaining items. A node is pruned if ub ≤ best.

LC branch and bound (book §4.9, §4.12)

LC (Least Cost) BnB keeps all live nodes in a heap and always expands the node with the smallest cost estimate c^(x). For maximisation we store c^ = −ub, so the node with the largest upper bound is expanded first. A node is pruned when its bound cannot beat the best solution found. The book demonstrates the same rule on job sequencing in §4.10.3: expand the least-cost live node and update the upper bound whenever a cheaper answer node is reached.

best ← 0
insert root into min-heap with key c^ = −ub(root)
while heap is not empty do
{
    x ← delete-min(heap)
    if (−x.c^) ≤ best then continue        // bound cannot beat best
    if x is a complete solution then
        best ← max(best, x.profit)
    else
        generate include-child and exclude-child
        compute ub for each child by fractional knapsack
        insert each child with key c^ = −ub
}

LC vs FIFO: LC expands the best-bound node, so it reaches the optimal leaf fastest. The book calls LC search with a bounding function LCBB; FIFO uses a queue (breadth-first), LIFO uses a stack (depth-first).

4.6 Travelling Salesman Problem using BnB

Q1Solve the TSP using branch and bound for 4 cities 0,1,2,3 with edges 0–1 = 10, 0–2 = 15, 0–3 = 20, 1–2 = 35, 1–3 = 25, 2–3 = 30.

9 marks★★ 2×

Asked in: 2023 Nov Q3(a) [9] · method also asked in 2025 Nov Q4(a)

TSP — book's method (book §4.11)

Given n cities and the cost of travelling from any city to any other, find the cheapest round trip that visits every city exactly once and returns to the starting city. The problem is represented by a weighted graph / cost matrix.

The state-space tree has the root at level 1, one level per city, and (n−1)! leaves when the starting city is fixed. A node at level k represents a partial tour of k cities. The bound is obtained by reducing the cost matrix.

Reduction rules (book §4.11.1 – 4.11.3)

  • Row reduction: subtract the minimum of each row from that row; add all row minima to get the row-reduction cost.
  • Column reduction: subtract the minimum of each column from that column; add all column minima.
  • Fully reduced matrix: every row and every column has at least one zero. The total reduction cost is a lower bound on every tour.

Dynamic reduction (book §4.11.4)

  1. Draw the state-space tree with the optimum (reduced) cost at the root.
  2. For path i → j, make row i and column j infinite; also set M[j][i] = ∞ so the tour cannot return early.
  3. Cost of the child = optimum cost of the parent + reduced cost of the new matrix + M[i][j].
  4. Choose the node with the minimum cost as the next E-node and generate its children; repeat.

Book's solved example (Example 4.11.3) — one line

For the 4-city graph of Fig. 4.11.18 (edges 1–2 = 2, 1–3 = 4, 1–4 = 7, 2–3 = 8, 2–4 = 3, 3–4 = 1), the row reduction gives 6 and the column reduction gives 0, so the root bound is 6. The BnB tree finds the tour 1 → 3 → 4 → 2 → 1 with cost 10.

4.7 Backtracking vs Branch and Bound

Q1Compare backtracking with branch and bound with respect to: search technique, exploration of the state-space tree, and kind of problems that can be solved.

8 marks★ 1×

Asked in: 2024 May Q4(a) [8]

Comparison (book §4.13)

PointBacktrackingBranch and Bound
Search techniqueDepth-first search of the state-space tree, usually by recursion or an explicit stack.May use BFS (FIFO queue), DFS (LIFO stack) or best-cost search (LC priority queue); DFS is not compulsory.
Exploration of the state-space treeFollows one path as far as possible; when a partial solution violates a constraint, it backtracks and tries the next value. The tree is searched only until the required solution is obtained.Builds the tree and generates all children of the E-node before any other live node. It keeps a list of live nodes and may have to search the whole tree, because the optimum may be anywhere.
Kind of problemsDecision / constraint-satisfaction problems: m-colouring, 8-queens, sum of subsets, Hamiltonian cycle.Optimisation problems: job sequencing with deadlines, travelling salesman, 0/1 knapsack, assignment.
Pruning criterionFeasibility — a partial solution that violates an explicit or implicit constraint is rejected.Optimality bound — a subtree whose lower/upper bound cannot beat the best known solution is rejected.
Bad choicesBad choices can be made while finding the solution; they are undone by backtracking.It proceeds on better solutions, so a bad complete solution cannot be accepted as the answer.
When a solution is foundStops at the first feasible solution (unless all solutions are asked).Must continue until the bound proves optimality; finding one solution is not enough.
MemoryO(n) — only the current path and solution vector.Stores all live nodes in a queue/stack/heap; can be exponential in the worst case.
One-line answer: backtracking asks “can this partial solution ever become valid?”; branch and bound asks “can this partial solution ever beat my best answer?”
