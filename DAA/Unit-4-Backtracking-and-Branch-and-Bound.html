4.2 Sum of subsets ★★★★★ 5×

Q1State the sum of subsets problem. Write an algorithm using backtracking and comment on its time complexity.

8 marks★★★ 3×

Asked in: 2025 May Q4(a) [8] · algorithm also asked in 2024 May, 2023 Nov

In simple words: We have a list of numbers and a target d. We want some of those numbers to add up to exactly d. We try each number as “take it” or “leave it”, and undo a choice as soon as the sum goes too high.

Why we do this

With n numbers there are 2n possible subsets — every number is either in or out. Checking all of them is slow. Backtracking stops a branch the moment its sum passes d or can no longer reach d.

Problem statement (book §4.6)

Let S = {s1, s2, …, sn} be a set of n positive integers and d a given positive integer. Find a subset — a selection of some of the numbers — whose sum is exactly d.

It helps to sort the numbers in ascending order: s1 ≤ s2 ≤ … ≤ sn. Small numbers first let us find solutions early and prune more branches.

Represent each choice by xi ∈ {0,1}. Here xi = 1 means “take si” and xi = 0 means “leave it”. The constraint is

Σi=1..n sixi = d,   xi ∈ {0,1}
What this means: multiply each number by 0 or 1, add the results, and the total must equal d. That is all the formula says.

Backtracking algorithm (book’s 6 steps)

  1. Start with an empty subset; sum = 0.
  2. Add the next element from the sorted list to the subset.
  3. If the subset sum is d, stop — this subset is a solution. If the question wants all solutions, record it and keep going.
  4. If the subset is not feasible (sum exceeds d) or the end of the list is reached, backtrack through the subset until a suitable value is found.
  5. If the subset is feasible, repeat step 2.
  6. If all elements are visited and no suitable subset is found, and backtracking is no longer possible, stop without a solution.

Here feasible means “still able to reach d”. A sum above d is infeasible because all numbers are positive — adding more only makes it worse. A pruned branch is a branch we cut off early because it cannot lead to a solution.

The same procedure is written recursively below. Here s is the current sum, k is the next index, and r is the sum of the weights from k to n.

Algorithm SumOfSubsets(s, k, r)
{
    if (s = d) then
    {
        print the chosen subset;
        return;
    }
    if (k > n) then return;

    if (s + w[k] ≤ d) then          // include w[k]
        SumOfSubsets(s + w[k], k + 1, r − w[k]);

    if (s + r − w[k] ≥ d) then      // exclude w[k]
        SumOfSubsets(s, k + 1, r − w[k]);
}
What this means, line by line: (1) If the sum already equals d, print and return. (2) If we ran out of numbers, return. (3) Include branch: take w[k] only if the new sum stays ≤ d. (4) Exclude branch: skip w[k] only if the remaining numbers can still push the sum up to d.

Why the exclude test s + r − w[k] ≥ d? After skipping w[k], the largest sum we could still build is s + (r − w[k]). If even that is below d, skipping is hopeless, so we do not go there.

One code detail: this book version returns as soon as it finds one solution. For “find all” questions, record the solution and keep exploring. The PYQ trees below do exactly that.

The book’s Example 4.6.2 starts with SumOfSubsets(0, 1, 55) for W = {7, 11, 13, 24} and m = 31 (the book calls the target m; it is the same as d). Its recursion tree (Fig. 4.6.2) produces the two solutions {7, 11, 13} and {7, 24}.

The search space is a binary state-space tree: at level i, the left edge means “include si” and the right edge means “exclude si”. “Binary” means two choices per level. The bounding function kills a node when its sum exceeds d, or when the remaining elements cannot possibly take the sum up to d.

What this means: each level is one number from the list. A path of n choices is one full subset. Backtracking walks this tree depth-first and never enters a branch that is already too big or too small to finish.

Time complexity

In the worst case the tree is a full binary tree of depth n, so it has 2n leaves and the algorithm takes O(2n) time. Sorting costs O(n log n). The recursion stack and solution vector need O(n) space.

Why sort ascending? The book shows that a non-decreasing order finds solutions early and prunes more branches. A decreasing or unsorted list may examine every element for every subset and makes the computing time worst.
Real-life analogy: you want to pay exactly ₹30 using coins from your pocket. You pick a coin, then another. If the total crosses ₹30, you put the last coin back and try a different one. You never keep adding coins to an amount that is already too large.
Common confusion: r includes w[k] itself. So when you exclude w[k], the remaining best sum is r − w[k], not r. Also, a “subset” ignores order: {7, 11, 13} and {11, 7, 13} are the same answer and are printed once.

Q4Prove that the full state-space tree for finding a sum of subsets of n elements using backtracking has (excluding the leaf nodes) 2n − 1 nodes.

4 marks★ 1×

Asked in: 2025 May Q3(b) [4]

In simple words: Every number has 2 choices — take it or leave it. So a full decision tree has 2n leaves. In a tree where every internal node has exactly 2 children, the internal nodes are always one fewer than the leaves. That gives 2n − 1.

Why we do this

This proof explains the O(2n) time of sum of subsets. If you can count the tree nodes, you can count the work.

Step-by-step proof

  1. Each element has exactly two choices. Include it (1) or exclude it (0). Therefore the state-space tree is a full binary tree — every internal node has exactly two children.
  2. The tree has height n. Each level decides one element. A complete decision is made only at a leaf, so the number of leaves is 2n.
  3. Use the full-binary-tree rule. In any full binary tree, the number of internal nodes is one less than the number of leaves: internal = leaves − 1.
  4. Substitute. Internal nodes = 2n − 1. These are exactly the nodes excluding the leaves.

Real-life analogy: a knockout tournament with 16 players has 15 matches. In general, a tournament with 2n players needs 2n − 1 matches. The players are leaves; the matches are internal nodes.
Common confusion: “excluding the leaf nodes” means internal nodes only, not “all nodes minus one”. Also, a leaf is a complete decision, but it is not always a valid answer. Only leaves that satisfy the constraints are answer states.

4.3 Graph colouring ★★★★ 4×

Q1Explain backtracking with the graph colouring problem. Write the recursive algorithm and give its time complexity.

8–9 marks★★★ 3×

Asked in: 2024 May Q3(a) [9] · 2025 Nov Q4(b) [8] · 2022 Nov Q4(b) [8 — with numerical]

In simple words: A graph is a set of dots joined by lines. We must give every dot a colour so that two joined dots never share a colour. We colour one dot at a time. If no colour fits a dot, we undo the previous dot and try another colour.

Why we do this

Many real tasks are “keep conflicting things apart”: exam timetables, radio frequencies, map regions, and seating guests. Graph colouring is the clean model for all of them. Backtracking finds a valid colouring without testing every possible colouring.

Problem and words you need first (book §4.5)

  • Graph G = (V, E): a set of vertices (dots) V and edges (lines) E.
  • Adjacent: two vertices joined by an edge. They are neighbours.
  • m-colouring: a colouring that uses at most m colours and gives neighbours different colours.
  • Chromatic number: the smallest number of colours needed for a valid colouring.
  • Degree of a vertex: how many edges touch it.
  • Adjacency matrix G[i][j]: a table where 1 means “i and j are joined” and 0 means “not joined”.

Given an undirected graph G = (V, E) and m colours, colour every vertex so that no two adjacent vertices have the same colour. This is the m-colouring problem. If the maximum degree of the graph is d, then d + 1 colours are always enough.

The book’s Fig. 4.5.1 graph has chromatic number 3; one valid colouring is A = 1 (Red), B = 2 (Green), C = 3 (Blue), D = 1, E = 2, F = 3.

Backtracking formulation — step by step

  1. Number the vertices 1 to n. We colour in this fixed order.
  2. Keep an array x[1..n]. x[k] is the colour of vertex k. Value 0 means “not coloured yet”.
  3. Pick the next vertex k. Try colours 1, 2, …, m in order.
  4. Check every earlier neighbour j < k. If G[k][j] = 1 and x[j] = c, then colour c is illegal for k.
  5. Take the first legal colour. Move on to vertex k + 1.
  6. If no colour is legal, set x[k] = 0. Return to vertex k − 1 and try its next colour. This is the backtrack.
  7. When every vertex is coloured, print the colour array. That is one valid colouring.

The bounding function is the neighbour check in step 4. It kills a colour choice before the whole graph is coloured. Without it, we would colour everything and only then discover a clash.

Recursive algorithm (book §4.5.1)

Algorithm Gr_color(k)
// G[1:n, 1:n] is the adjacency matrix.
// x[k] is the legal colour assigned to vertex k.
{
    repeat
    {
        Gen_Col_Value(k);              // produce the next possible colour
        if (x[k] = 0) then
            return;                    // no new colour is possible
        if (k = n) then
            write(x[1..n]);            // all vertices are coloured
        else
            Gr_color(k + 1);           // choose the next vertex
    } until (false);
}

Algorithm Gen_Col_Value(k)
// x[k] = 0 if no legal colour exists.
{
    repeat
    {
        x[k] ← (x[k] + 1) mod (m + 1); // next colour index
        if (x[k] = 0) then
            return;                    // all m colours have been tried
        for j ← 1 to n do
        {
            if (G[k][j] = 1 and x[k] = x[j]) then
                break;                 // same colour as an adjacent vertex
        }
        if (j = n + 1) then
            return;                    // no conflict: colour is legal
    } until (false);
}
What this means, line by line: Gen_Col_Value(k) finds the next legal colour for vertex k. The line (x[k] + 1) mod (m + 1) counts 1, 2, …, m, then 0. A result of 0 means “all colours tried, none worked”. The inner for loop checks every neighbour. If the loop finishes without a clash, j becomes n + 1, which signals “colour is legal”.

Time analysis (book §4.5.2)

At level 1 there are m choices, at level 2 up to m2, and so on. The total number of nodes generated is

Σi=0..n−1 mi = 1 + m + m2 + … + mn−1

This is a geometric sum. It is dominated by its largest term, mn−1. Each colour check scans n vertices, so the total computing time is O(n · mn). Space is O(n) for x[] and the recursion stack.

What this means: the n is the cost of checking neighbours. The mn is the number of possible colour assignments. Backtracking cuts many of them, but the worst case still grows exponentially.

Book’s 4-step strategy

  1. Choose a colour c and apply it to some vertex v.
  2. Choose different colours from the available list for each successive vertex; after applying a colour, check whether it is the same as an adjacent colour.
  3. If the colour is not the same, go to the next adjacent vertex; otherwise try another colour from the list or change an already-assigned colour.
  4. Repeat for all vertices.
Bounding in action: in the book’s Fig. 4.5.1 example, the search reaches a vertex where colours 1, 2 and 3 all conflict with neighbours. That node is a dead end, so the algorithm backtracks and changes an earlier vertex. The final colouring uses only 3 colours, which proves the chromatic number is 3.
Real-life analogy: you are seating guests at coloured tables. Some guests refuse to sit with each other. You seat one guest at a time. If every allowed table already has an enemy, you move the previous guest to a different table and try again.
Common confusion: having m colours does not mean you must use all m. The chromatic number is the minimum, not the number you were given. Also, three mutually connected vertices (a triangle) always need 3 colours — two colours can never work.

Q2Find a colouring solution for the given graph (adjacency matrix of C1…C5).

8 marks★ 1×

Asked in: 2022 Nov Q4(b) [8]

In simple words: Five vertices C1 to C5 must get colours so that every edge joins two different colours. The vertices C3, C4 and C5 form a triangle, so 3 colours are compulsory. We colour in order C1 to C5 and check neighbours each time. The answer is 1, 2, 1, 2, 3.

Why we do this

The triangle gives a quick lower bound: 2 colours are impossible. Knowing that, we start with m = 3 and avoid wasting time on a search that cannot succeed.

Read the graph from the matrix

The question paper prints a 5×5 matrix. We only need its 1-entries. The matrix is symmetric, so the edges are: C1–C2, C1–C4, C2–C3, C3–C4, C3–C5, C4–C5. Vertices C3, C4, C5 form a triangle (C3–C4, C4–C5, C5–C3), so at least 3 colours are necessary. We try m = 3 with colours 1, 2, 3.

What this means: a triangle is three vertices that are all joined to each other. All three need different colours. No trick can avoid that, so 3 is a hard minimum.

Step-by-step colouring (book’s Gen_Col_Value)

  1. Take the next uncoloured vertex in the order C1 to C5.
  2. Try colour 1, then 2, then 3.
  3. Check only coloured neighbours. If one has the same colour, reject it.
  4. Assign the first legal colour and move to the next vertex.
  5. If all colours fail, set this vertex to 0 and backtrack.

4.5 0/1 Knapsack using Branch and Bound

Q1Explain the branch and bound approach. Write a BnB algorithm for 0/1 knapsack and solve: capacity 15 kg, items A(9 kg, Rs.18), B(4 kg, Rs.10), C(6 kg, Rs.12), D(2 kg, Rs.10).

9 marks★★ 2×

Asked in: 2022 Nov Q3(a) [9] · 2023 Nov Q4(a) [9 — identical instance]

In simple words: We have a bag that can hold 15 kg. Each item is taken whole or left behind. We want the largest total profit. BnB tries “take it” and “leave it” for each item. For every branch it calculates the best profit still possible. If that best is not better than what we already have, the branch is dropped.

Why we do this

Greedy by profit-to-weight ratio is fast but can miss the best 0/1 answer. BnB is exact: it checks only the branches that can still win. That is why it is used for real packing and budgeting problems.

Words you need first

  • 0/1 knapsack: each item is either fully taken (1) or fully left (0). No cutting.
  • Capacity m: the maximum total weight the bag can hold.
  • Profit pi: the value of item i. Weight wi: how heavy it is.
  • Ratio pi/wi: profit per kilogram. A high ratio means “good value for weight”.
  • Upper bound ub: the best profit a branch could possibly reach. It is optimistic, so it is never below the true best.
  • Fractional relaxation: pretend we may cut items and take part of one. This gives an easy optimistic bound.
  • Prune: drop a branch because its bound cannot beat the best answer found.

0/1 knapsack — book’s formulation (book §4.12)

There are n objects and a knapsack of capacity m. Object i has weight wi and profit pi. Choose xi ∈ {0,1} to

maximise   Σ pixi   subject to   Σ wixi ≤ m
What this means: add the profits of the items you take. Add their weights too. The profit must be as large as possible, and the weight must not exceed the capacity.

The book writes the same problem as minimise −Σpixi. It uses the fixed tuple size formulation — a fixed order where level i decides item i, so the tree shape never changes. At level i, choose xi = 1 (include) or xi = 0 (exclude). For every node x,

c^(x) ≤ c(x) ≤ u(x)

where c^(x) is the lower bound (approximate least cost) and u(x) is the upper bound. A node is killed when its bound cannot lead to a better answer than the best solution already found.

How the algorithm works — step by step

  1. Compute p/w for every item. Sort the items from highest ratio to lowest. This order gives the tightest easy bound.
  2. Start at the root with weight 0, profit 0.
  3. Compute the root upper bound. Take items in ratio order. Take a whole item if it fits. At the first item that does not fit, take the fraction that fits and stop.
  4. Branch on the next item. Left child = include it. Right child = exclude it.
  5. Never include an item that overflows the bag. That child is infeasible.
  6. Bound every child with the same fractional method.
  7. Prune a child if ub ≤ best. It cannot beat the best complete answer found so far.
  8. When all items are decided, compare the profit with best and update best.
  9. Stop when no live node remains. The stored best is optimal.

BnB algorithm for 0/1 knapsack

Algorithm Knapsack_BB()
{
    sort items by p[i]/w[i] in decreasing order;
    best ← 0;  bestSet ← ∅;
    PQ ← empty max-heap;
    insert root with ub = C_Bound(0, 0, 0);
    while (PQ is not empty) do
    {
        node ← delete-max(PQ);          // highest upper bound
        if (node.ub ≤ best) then
            continue;                   // bound cannot beat best
        if (node.level = n) then
        {
            if (node.profit > best) then
            {
                best ← node.profit;
                bestSet ← node.set;
            }
        }
        else
        {
            // left child: include item level+1
            if (node.weight + w[node.level+1] ≤ m) then
                insert left child with ub = C_Bound(...);
            // right child: exclude item level+1
            insert right child with ub = C_Bound(...);
        }
    }
    return best, bestSet;
}

Algorithm C_Bound(total_profit, total_wt, k)
// optimistic bound: remaining items are taken fractionally
{
    pt ← total_profit;
    wt ← total_wt;
    for (i ← k+1 to n) do
    {
        wt ← wt + w[i];
        if (wt < m) then
            pt ← pt + p[i];
        else
            return (pt + (1 − (wt − m)/w[i]) * p[i]);
    }
    return pt;
}
What this means: C_Bound is the “best possible” calculator. It adds whole items while they fit. At the first item that overflows, it takes only the fraction that fits. That fraction is (m − used weight) / w[i], written in the code as 1 − (wt − m)/w[i]. The result is an optimistic profit, so the real 0/1 profit can only be equal or lower.

The book also defines U_Bound, which adds only the items that fit completely. In the book’s minimisation form the bounds are stored with a minus sign; for the PYQ we use the equivalent positive profit upper bound: ub = profit so far + fractional profit of the remaining items. A node is pruned if ub ≤ best.

Why we do this

Plain BnB may expand many nodes before it reaches a good answer. LC (least cost) uses the bound to pick the most promising node first. That usually reaches the optimal leaf faster.

LC branch and bound (book §4.9, §4.12)

LC (Least Cost) BnB keeps all live nodes in a heap — a priority queue that always gives the smallest key. It always expands the node with the smallest cost estimate c^(x). For maximisation we store c^ = −ub, so the node with the largest upper bound is expanded first.

What this means: a min-heap of negative bounds behaves like a max-heap of positive bounds. The most negative key is the largest profit. This is only a storage trick; the pruning rule stays “drop if ub ≤ best”.

A node is pruned when its bound cannot beat the best solution found. The book demonstrates the same rule on job sequencing in §4.10.3: expand the least-cost live node and update the upper bound whenever a cheaper answer node is reached.

Step-by-step LC search

  1. Sort by v/w. Higher value per kg comes first.
  2. Compute the root bound with fractional knapsack.
  3. Put the root in the heap with key −ub.
  4. Remove the smallest key. That is the largest upper bound — the most promising node.
  5. If its bound ≤ best, discard it. It cannot win.
  6. If it is a complete solution, update best.
  7. Otherwise branch into include and exclude children.
  8. Bound each child and push it with key −ub.
  9. Repeat until the heap is empty.

4.4 Branch and Bound — fundamentals

Q1What is the Branch and Bound method? Write the control abstraction for Least-Cost search.

9 marks★★ 2×

Asked in: 2022 Nov Q4(a) [9] · control abstraction + applications: 2025 Nov Q3(b) [8]

In simple words: Branch and Bound finds the best answer, not just any answer. It splits the choices into branches. For each branch it calculates the best score that branch could possibly reach. If that score cannot beat the best answer already found, the whole branch is thrown away.

Why we do this

For optimisation problems, a valid answer is not enough — we need the cheapest or most profitable one. Trying every complete answer is too slow. BnB uses a bound to skip large groups of answers that cannot win.

Words you need first

  • Optimisation problem: a problem where we want the minimum cost or maximum profit.
  • Feasible: obeys all the rules. Optimal: the best feasible answer.
  • Branch: split one partial answer into smaller choices — generate its children.
  • Bound: an estimate of the best score a branch can still achieve.
  • Lower bound c^(x): the smallest cost this branch could possibly have. Used for minimisation.
  • Upper bound u(x): the largest profit this branch could possibly have. Used for maximisation.
  • Live node: a node that is waiting to be explored. E-node: the live node being expanded now.
  • Queue: a line — first in, first out. Stack: a pile — last in, first out.
  • FIFO: use a queue. LIFO: use a stack.
  • BFS: breadth-first search — explore level by level. DFS: depth-first search — go deep first.
  • LC: least cost — always expand the live node with the smallest cost estimate.
  • Heap (priority queue): a list that always gives the smallest (or largest) key quickly.

What is Branch and Bound? (book §4.7)

Branch and Bound (BnB) is a general algorithm for finding optimal solutions of optimisation problems. It is used where greedy and dynamic programming fail, but it is slower; in the worst case it takes exponential time, although with good bounding it can run reasonably fast on average.

The two words describe the two actions:

  • Branch — partition the problem at a node into smaller subproblems (generate its children).
  • Bound — compute a lower bound c^(x) and an upper bound u(x) for every child. If a child cannot contain a better answer than the best known, it is killed (pruned).

BnB builds the state-space tree and generates all children of the E-node before any other live node can become an E-node. It may use BFS (FIFO queue) or DFS (LIFO stack). FIFO BnB is breadth-first; LIFO BnB is depth-first.

General BnB — step by step

  1. Put the root in the live list. The root means “no choice made yet”.
  2. Choose an E-node using FIFO, LIFO or LC.
  3. Check for an answer. If this node is a complete final leaf, its path is the answer.
  4. Branch. Generate all children of the E-node.
  5. Bound each child. Estimate the best score it can still reach.
  6. Kill hopeless children. Drop any child whose bound cannot beat the best answer found so far.
  7. Add the survivors to the live list.
  8. Repeat until the live list is empty or optimality is proven.

What this means: FIFO explores level by level. LIFO goes deep like backtracking. LC always opens the most promising node first. All three use the same bounding idea; only the order of choosing the next node changes.

LC (Least Cost) uses a ranking function. Let g^(x) be an estimate of the extra effort needed to reach an answer node from x, and h(x) the cost of reaching x from the root. Define

c^(x) = f(h(x)) + g^(x)

Here f is a function that turns the path cost into a ranking number; in most examples f(h) = h.

  • If g^(x) = 0 and f(h(x)) = level of x, the search is BFS.
  • If f(h(x)) = 0 and g^(x) ≤ g^(y) whenever y is a child of x, the search is D-search (DFS).
  • LC search with a bounding function is called LC Branch and Bound (LCBB).
What this means: c^(x) is a total estimate: cost so far plus expected cost remaining. A small c^ means “promising”. LC expands the smallest c^ first. The two special cases show that BFS and DFS are just different ways of defining this estimate.

Q2What are the major drawbacks of the branch and bound method?

4 marks★ 1×

Asked in: 2025 May Q3(c) [4]

In simple words: Branch and Bound is designed to give the correct best answer, but it can be very slow. It can also use a lot of memory. Its speed depends completely on how tight the bound is. A weak bound turns it into brute force with extra bookkeeping.

Why we do this

Examiners ask this to check that you know BnB is not a magic fast algorithm. You should be able to say when it struggles, not just how it works.

Major drawbacks (from the book’s discussion)

  1. Slower than greedy and DP; exponential worst case. The book states that BnB applies where greedy and dynamic programming fail, but it is much slower. If the bound is weak, most children survive, no pruning happens, and the method degenerates to exhaustive search — O(2n) for knapsack/subsets or O(n!) for TSP.
  2. Blind FIFO/LIFO selection; costly LC. The book says selecting the E-node using FIFO or LIFO is “very complicated and somewhat blind”. LC is better but needs a ranking/cost value c^(x) at every node; computing a tight bound (for example, fractional knapsack at every node) itself costs time.
  3. Large live-node list. FIFO/LIFO/LC must store all live nodes in a queue, stack or heap; in the worst case this is exponential, unlike backtracking’s O(n) stack.
  4. Problem-specific bounds. A correct bounding function and branching rule need insight. The book warns that care must be taken while killing live nodes so that at least one answer node is still produced; a bad bound can remove the optimum.
  5. No guaranteed early stop. Finding one complete solution is not enough; the search must continue until the bound proves that no unexplored node can beat it.
What this means: points 1 and 3 are about time and memory. Points 2 and 4 are about design effort. Point 5 is about correctness: a single good answer does not prove it is the best one.
Exam-safe one-liner: BnB is exact but can be slow and memory-heavy; its speed depends entirely on how tight the bound is.
Real-life analogy: you are planning a trip and pin every possible route on a noticeboard. The board fills the whole wall. If your “minimum possible cost” estimate is vague, you cannot remove any route, so you end up checking them all.
Common confusion: “exponential worst case” does not mean BnB is useless. On many inputs a tight bound prunes almost everything. The drawback is that there is no guarantee of fast running time.

4.6 Travelling Salesman Problem using BnB

Q1Solve the TSP using branch and bound for 4 cities 0,1,2,3 with edges 0–1 = 10, 0–2 = 15, 0–3 = 20, 1–2 = 35, 1–3 = 25, 2–3 = 30.

9 marks★★ 2×

Asked in: 2023 Nov Q3(a) [9] · method also asked in 2025 Nov Q4(a)

In simple words: A salesman must visit four cities and return home. We want the cheapest round trip, with no city visited twice. BnB calculates a minimum possible cost for each partial route. If that minimum is already 80 or more, and we already have an 80 tour, the route is dropped.

Why we do this

There are (n−1)! round trips for n cities. For 10 cities that is 362,880 routes; for 15 it is huge. A good lower bound lets us ignore most routes without ever building them.

Words you need first

  • Tour (also called a cycle): a route that visits every city once and returns to the start.
  • Cost matrix M[i][j]: the cost of going from city i to city j.
  • ∞ in the matrix: “this move is forbidden”. It blocks self-loops such as 0→0 and early returns.
  • Row reduction: subtract the smallest value in each row. The sum of what you subtract is a cost you cannot avoid.
  • Column reduction: the same idea on columns.
  • Reduced matrix: a matrix where every row and every column has at least one zero.
  • Lower bound: the smallest possible cost of any tour in this branch. It is optimistic, so it never overestimates.

TSP — book’s method (book §4.11)

Given n cities and the cost of travelling from any city to any other, find the cheapest round trip that visits every city exactly once and returns to the starting city. The problem is represented by a weighted graph / cost matrix.

The state-space tree has the root at level 1, one level per city, and (n−1)! leaves when the starting city is fixed. A node at level k represents a partial tour of k cities. The bound is obtained by reducing the cost matrix.

Reduction rules (book §4.11.1 – 4.11.3)

  • Row reduction: subtract the minimum of each row from that row; add all row minima to get the row-reduction cost.
  • Column reduction: subtract the minimum of each column from that column; add all column minima.
  • Fully reduced matrix: every row and every column has at least one zero. The total reduction cost is a lower bound on every tour.
What this means: every tour must leave each city once and enter each city once. So it must pay at least the cheapest exit from every row. Subtracting those minima records that unavoidable cost. The same logic applies to columns.

Step-by-step: reduce the root matrix

  1. Write the cost matrix. Put ∞ on the diagonal, because a city cannot travel to itself.
  2. Find each row minimum. Subtract it from every entry in that row. Add the minima: 55.
  3. Find each column minimum in the new matrix. Subtract it. Add the minima: 15.
  4. Add both totals. 55 + 15 = 70. No tour can cost less than 70.

Dynamic reduction (book §4.11.4)

4.1 Backtracking — principle, control abstraction, time analysis

Q1Explain with a suitable example: Backtracking — principle, control abstraction, time analysis of control abstraction.

8 marks★★ 2×

Asked in: 2022 Nov Q3(b) [8] · 2023 Nov Q3(b) [8]

In simple words: Backtracking builds an answer one small choice at a time. After every choice it asks, “Can this still work?” If the answer is no, it undoes that choice and tries the next one. So it never wastes time on a path that is already broken.

Why we do this

Many problems have a huge number of possible answers. Checking every complete answer is too slow. Backtracking stops a bad partial answer immediately. That saves most of the work.

1. Principle (book §4.1) — step by step

  1. Write the answer as n slots. The answer is an n-tuple (x1, x2, …, xn). That is just n positions in a row.
  2. List the allowed values for each slot. Slot xi may take values only from its set Si. These limits are the explicit constraints — the rules written directly in the problem.
  3. Fill one slot at a time, left to right. Never jump ahead.
  4. Test the partial answer. A bounding function Bk checks the implicit constraints — the real rules, such as “no two queens attack each other”.
  5. Go deeper only if it can still work. A partial answer that passes is called feasible (still able to become a full answer).
  6. Record a full valid answer. If all n slots are filled and valid, print the tuple.
  7. Undo and retry when stuck. If no value works in a slot, step back one slot and try that slot’s next value. This undo step is the backtrack.
  8. Stop when every option has been tried. Stop early only if the question asks for one answer and you found it.

Depending on the question, the problem may be a decision problem (does any answer exist?), an optimisation problem (which answer is best?), or an enumeration problem (list every answer).

Depth-first search (DFS) means “go as deep as possible before trying a sibling”. Backtracking is DFS with a bounding function. It is much better than brute force (generate every full answer, then test it), because whole subtrees are never generated.

Applications (book §4.3): 8-queens, sum of subsets, graph colouring, Hamiltonian cycle (a cycle that visits every vertex once) and knapsack.

2. State-space tree terms (book §4.1.1)

A state-space tree is a drawing of every partial choice. The root is the empty choice. Each edge adds one choice. Each level is one slot of the answer.

TermPlain meaning
Problem stateAny node in the tree — one partial choice.
Solution state / solution spaceA path from the root that builds one full tuple.
Answer stateA leaf that satisfies all implicit constraints.
Live nodeA node that is generated, but whose children are not all generated yet.
E-nodeThe live node whose children are being generated right now. “E” means expanding.
Dead nodeA node we will never expand again — it failed a test or cannot help.
Bounding function BkA quick test that kills hopeless nodes. It must never kill a node that could still lead to an answer.
What this means: the tree is not the answer. It is the map of all choices. Backtracking walks this map and cuts dead branches early.

3. Control abstraction (book §4.2, recursive)

An abstraction hides problem details and shows only the common skeleton. A control abstraction is the shared skeleton of an algorithm, written with placeholders for the problem-specific parts. The same skeleton works for queens, colouring and subsets.

Algorithm Backtrack(k)
// a[1..k] is a solution vector. On entering, k-1 values are fixed.
// T(a1,...,a_{k-1}) = set of all values for a_k such that
// (a1,...,a_k) is a path to a problem state.
// B_k is the bounding function.
{
    for (each a_k that belongs to T(a1, a2, ..., a_{k-1})) do
    {
        if (B_k(a1, a2, ..., a_k) = true) then      // feasible sequence
        {
            if ((a1, a2, ..., a_k) is a path to an answer node) then
                print(a[1], a[2], ..., a[k]);
            if (k < n) then
                Backtrack(k + 1);                   // find the next set
        }
    }
}
What this means, line by line: (1) Backtrack(k) means “fill slot k”. (2) T gives the legal values for that slot. (3) Bk rejects a partial answer early. (4) If the partial answer is already complete, print it. (5) If slots remain, go one level deeper. (6) When the loop ends, the function returns — that return is the backtrack.

The book also gives an iterative form, Non_Rec_Backtrack(). It keeps k, tries the next untried value of a[k], prints a solution if the node is an answer, increases k on success, and does k := k − 1 to backtrack when no value is left.

4. Time analysis (book §4.2)

The running time depends on four things:

  1. time to generate a[k] — picking the next value;
  2. number of a[k] values that satisfy the explicit constraints — how many legal choices exist;
  3. time taken by the bounding function Bk — the cost of one pruning test;
  4. number of a[k] values that satisfy Bk for all k — how many nodes survive pruning.

The first three are independent of the data and take polynomial time — time like n, n2 or n3, not 2n. The fourth depends on the instance. If n! nodes survive the bounding function, then

T(n) = O(P(n) · n!)

Here P(n) is the polynomial cost of the first three factors, and n! is the number of surviving nodes. The symbol n! means n × (n−1) × … × 1. The O notation means “grows no faster than”.

What this means: the bound P(n) is cheap. The explosion comes from the number of surviving nodes. A stronger bounding function reduces that number.

For specific problems: n-queens O(n!), sum of subsets O(2n), graph colouring O(n·mn). Space is O(n) for the solution vector and the recursion stack.

5. Suitable example — 4-queens

The 4-queens problem asks for 4 queens on a 4×4 chessboard so that no two share a row, column or diagonal. We place one queen per row. So the answer is a tuple of 4 column numbers.

  1. Row 1: try a column.
  2. Row 2: try a column that does not attack row 1.
  3. Check after every placement. Two queens attack if they share a column, or if their row distance equals their column distance (a diagonal).
  4. Dead end? Undo the last queen and try her next column.
  5. All 4 placed? Record the tuple.

The book’s 4-queen state-space tree (Fig. 4.4.1) first tries a placement that reaches a dead end, backtracks, and finally gives the answer tuple (2, 4, 1, 3). Read it as: queen in row 1 goes to column 2, row 2 to column 4, row 3 to column 1, row 4 to column 3. No two queens share a row, column or diagonal. The book’s 8-queens solution is the tuple (4, 6, 8, 2, 7, 1, 3, 5).

What this means: brute force generates all mn vectors and tests them at the end. Backtracking tests at every level, so a bad partial vector is killed immediately.
Real-life analogy: you are in a maze. You walk down one corridor. If it ends at a wall, you walk back to the last junction and take a different turn. You do not restart the maze from the entrance.
Common confusion: backtracking is not random trial and error, and it is not brute force. It is organised DFS. Also, the “backtrack” is just the function returning one level — you do not throw away the whole answer and start again.

4.7 Backtracking vs Branch and Bound

Q1Compare backtracking with branch and bound with respect to: search technique, exploration of the state-space tree, and kind of problems that can be solved.

8 marks★ 1×

Asked in: 2024 May Q4(a) [8]

In simple words: Backtracking asks, “Can this partial answer ever become valid?” Branch and bound asks, “Can this partial answer ever beat my best answer?” Backtracking is usually depth-first and stops at the first valid answer. BnB may use a queue, stack or heap and must keep going until it proves the answer is the best.

Why we do this

The two methods look similar because both build a state-space tree and both prune. The exam wants the difference in goal and pruning rule. Backtracking is used for decision and constraint-satisfaction problems — questions where any valid answer is enough. Once you see that, the whole table becomes easy to remember.

One-line answer: backtracking asks “can this partial solution ever become valid?”; branch and bound asks “can this partial solution ever beat my best answer?”

How to remember it in the exam

  1. Goal first. Backtracking = any valid answer. BnB = the best answer.
  2. Pruning second. Backtracking kills on constraint violation. BnB kills on bound cannot win.
  3. Search order third. Backtracking is normally DFS. BnB can be FIFO, LIFO or LC.
  4. Memory last. Backtracking keeps one path, so O(n). BnB keeps many live nodes, so it can be exponential.
Real-life analogy: you are hiring for one post. Backtracking checks, “Is this candidate eligible?” and hires the first eligible person. BnB checks, “Can this candidate be better than the best one so far?” and keeps interviewing until no one can beat the current best.
Common confusion: both methods use a state-space tree and both prune, so they are not “opposites”. The difference is the question they ask before pruning. Also, BnB can use DFS — it is not always breadth-first.
