4.1 Backtracking — principle, control abstraction, time analysis

Q1Explain with a suitable example: Backtracking — principle, control abstraction, time analysis of control abstraction.

8 marks★★ 2×

Asked in: 2022 Nov Q3(b) [8] · 2023 Nov Q3(b) [8]

Principle

Backtracking is a systematic trial-and-error method. It builds a solution vector x[1..n] one component at a time. At each level it tries all legal values of that component; if a partial vector cannot be extended to a complete solution (detected by a bounding function), it abandons that branch and backs up to the previous level to try the next value.

  • The search space is a state-space tree: root = empty solution, level k = choice for x[k].
  • Bounding / pruning function B(k) rejects a partial solution early — this is what makes backtracking better than brute force.
  • It is a depth-first search with pruning.

Control abstraction

Algorithm Backtrack(k)
// x[1..k−1] is a partial solution; tries to extend it
{
    if (x[1..k−1] is a complete solution) then
        output x[1..k−1];

    else
    {
        for each value v in S(k) do        // S(k) = allowed values at level k
        {
            if ( B(k, v) is true ) then     // bounding function
            {
                x[k] = v;
                Backtrack(k + 1);
            }
        }
    }
}

For n-queens, S(k) = {1..n} (column of queen k) and B(k) checks no two queens share a column or diagonal. For sum of subsets, S(k) = {0,1} and B checks s + w[k] ≤ target ≤ s + remaining.

Time analysis

Worst case: T(n) = O(mn)  — n levels, m choices per level
With effective bounding: T(n) = O(number of nodes actually generated)
  • n-queens: worst O(n!), with pruning about O(n!).
  • Sum of subsets: O(2n) worst (each element in/out); tree has 2n leaves.
  • Graph colouring: O(mn) worst.
  • Space: O(n) for the recursion stack + solution vector.

Example — 4-queens (one line)

Place Q1 in column 1, Q2 in column 3, Q3 in column 5 → conflict? If a partial placement attacks, backtrack to the previous queen and shift it. The first valid 4-queens arrangement is (2,4,1,3).

Difference from brute force: brute force generates all mn vectors and tests them at the end. Backtracking tests as it builds, so entire subtrees are never generated.

4.2 Sum of subsets ★★★★★ 5×

Q1State the sum of subsets problem. Write an algorithm using backtracking and comment on its time complexity.

8 marks★★★ 3×

Asked in: 2025 May Q4(a) [8] · algorithm also asked in 2024 May, 2023 Nov

Problem statement

Given a set W = {w1, w2, …, wn} of positive weights and a target sum M, find all subsets of W whose elements add up to exactly M.

Find xi ∈ {0, 1} such that   Σi=1..n wi xi = M

Each xi = 1 means wi is included. The state-space tree is binary: include (left) or exclude (right).

Algorithm

// w[1..n] sorted ascending, x[] is the solution vector
// s = current sum, k = current index, r = sum of remaining weights
Algorithm SumOfSubsets(s, k, r)
{
    x[k] = 1;                                  // try including w[k]
    if (s + w[k] == M) then
        output x[1..k];                        // solution found
    else if (s + w[k] + w[k+1] <= M) then
        SumOfSubsets(s + w[k], k+1, r − w[k]);

    x[k] = 0;                                  // try excluding w[k]
    if ((s + r − w[k] >= M) and (s + w[k+1] <= M)) then
        SumOfSubsets(s, k+1, r − w[k]);
}

Bounding conditions used

  • If s + w[k] > M, including w[k] is useless → prune left branch.
  • If s + r − w[k] < M, even taking all remaining weights cannot reach M → prune right branch.
  • If s + w[k] + w[k+1] > M, no further inclusion can complete a solution.

Time complexity

Worst case the tree is a full binary tree of depth n → O(2n) nodes. Sorting takes O(n log n). Space is O(n) for the recursion stack. With pruning, far fewer nodes are generated in practice.

Q4Prove that the full state-space tree for finding a sum of subsets of n elements using backtracking has (excluding the leaf nodes) 2n − 1 nodes.

4 marks★ 1×

Asked in: 2025 May Q3(b) [4]

Proof

  1. Each element has exactly two choices — include (1) or exclude (0). So the state-space tree is a full binary tree of height n.
  2. The number of leaves (complete decisions) is 2n.
  3. In any full binary tree, the number of internal nodes = number of leaves − 1.
  4. Therefore internal nodes = 2n − 1.
Total nodes = 2n+1 − 1   |   Leaves = 2n   |   Excluding leaves = 2n − 1 ∎

Example n = 3: leaves = 8, internal nodes = 7, total = 15. ✓

4.3 Graph colouring ★★★★ 4×

Q1Explain backtracking with the graph colouring problem. Write the recursive algorithm and give its time complexity.

8–9 marks★★★ 3×

Asked in: 2024 May Q3(a) [9] · 2025 Nov Q4(b) [8] · 2022 Nov Q4(b) [8 — with numerical]

Problem

Given an undirected graph G = (V, E) and m colours, assign a colour to every vertex so that no two adjacent vertices share a colour. This is the m-colourability problem; the smallest m for which it works is the chromatic number.

Algorithm

// G[1..n][1..n] adjacency matrix, x[1..n] colour of each vertex
Algorithm mColoring(k)
{
    do
    {
        NextValue(k);              // assign the next valid colour to x[k]
        if (x[k] == 0) return;     // no colour left → backtrack
        if (k == n) then
            output x[1..n];        // all vertices coloured
        else
            mColoring(k + 1);
    } while (true);
}

Algorithm NextValue(k)
{
    do
    {
        x[k] = (x[k] + 1) mod (m + 1);
        if (x[k] == 0) return;     // all m colours tried
        for j = 1 to k−1 do
        {
            if (G[k][j] == 1 and x[k] == x[j]) then
                break;             // conflict with an adjacent vertex
        }
    } while (j != k);              // repeat until a non-conflicting colour
}

Time complexity

Worst case m choices at each of n levels → O(mn). The adjacency check at each node costs O(n), so the bound is O(n·mn). Space = O(n) for x[] and recursion.

Bounding function: a partial colouring is abandoned as soon as a vertex has no colour that differs from all its already-coloured neighbours. This pruning removes whole subtrees.

4.4 Branch and Bound — fundamentals

Q1What is the Branch and Bound method? Write the control abstraction for Least-Cost search.

9 marks★★ 2×

Asked in: 2022 Nov Q4(a) [9] · control abstraction + applications: 2025 Nov Q3(b) [8]

Definition

Branch and Bound (BnB) is an optimisation technique for combinatorial problems. It explores the state-space tree but uses a bound at every node:

  • Branch — split a node into its children (include / exclude a decision).
  • Bound — compute the best value that any solution in that subtree can possibly achieve.
  • If the bound cannot beat the best solution found so far (best), prune the subtree. Otherwise expand it.

Unlike backtracking (depth-first, feasibility-based pruning), BnB prunes using an objective-value bound and can use different search orders.

Three strategies

StrategyData structureOrderUse
FIFOQueueBreadth-firstSimple, more memory
LIFOStackDepth-firstLow memory
LC (Least Cost)Min-heap (priority queue)Best-bound firstFewest nodes, best for optimisation

Control abstraction — Least-Cost search

Algorithm LCBB(root)
{
    PQ = empty min-heap;              // key = estimated cost / bound
    best = +∞;                        // for minimisation
    insert(PQ, root);

    while (PQ is not empty) do
    {
        node = delete-min(PQ);        // node with smallest bound

        if (node is a complete solution) then
        {
            if (cost(node) < best) best = cost(node);
        }
        else
        {
            for each child c of node do
            {
                compute bound(c);
                if (bound(c) < best) then   // pruning test
                    insert(PQ, c);
            }
        }
    }
    return best;
}

For maximisation, replace < by > and use a max-heap / upper bound.

Applications (asked in 2025 Nov)

  • 0/1 knapsack problem
  • Travelling salesman problem (TSP)
  • Job scheduling / assignment problem
  • Integer linear programming
  • Facility location, network design

Q2What are the major drawbacks of the branch and bound method?

4 marks★ 1×

Asked in: 2025 May Q3(c) [4]

  • Exponential worst case — if bounds are weak, the tree is not pruned and the method degenerates to brute force, O(2n) or O(n!).
  • Memory heavy — FIFO/LC must store many live nodes in the queue/heap.
  • Bound computation cost — a tight bound (e.g. solving a fractional knapsack at every node) is itself expensive.
  • No guarantee of early solution — the first complete solution found may not be optimal; the whole tree may still need exploration.
  • Problem-specific — designing a correct bound and branching rule needs insight; a wrong bound can prune the optimal solution.

4.5 0/1 Knapsack using Branch and Bound

Q1Explain the branch and bound approach. Write a BnB algorithm for 0/1 knapsack and solve: capacity 15 kg, items A(9 kg, Rs.18), B(4 kg, Rs.10), C(6 kg, Rs.12), D(2 kg, Rs.10).

9 marks★★ 2×

Asked in: 2022 Nov Q3(a) [9] · 2023 Nov Q4(a) [9 — identical instance]

Algorithm

Algorithm KnapsackBB(w[], p[], n, M)
{
    sort items by p[i]/w[i] in decreasing order;
    best = 0;  bestSet = ∅;
    PQ = empty max-heap;  insert(root with ub = fractionalBound(0, M));

    while (PQ not empty) do
    {
        node = delete-max(PQ);            // highest upper bound
        if (node.ub <= best) continue;    // prune

        if (node.level == n) then
        {
            if (node.profit > best) { best = node.profit; bestSet = node.set; }
        }
        else
        {
            // left child: include item level+1
            if (node.weight + w[node.level+1] <= M) then
                insert(child with profit + p, weight + w, ub = bound());

            // right child: exclude item
            insert(child with same profit/weight, ub = bound());
        }
    }
    return best, bestSet;
}

// bound = current profit + profit of remaining items taken fractionally
fractionalBound(node)
{
    ub = node.profit;  rem = M − node.weight;
    for i = node.level+1 to n do
    {
        if w[i] <= rem then { ub += p[i]; rem −= w[i]; }
        else { ub += p[i] * rem / w[i]; break; }
    }
    return ub;
}

Step 2 — state-space tree with bounds

Root upper bound = take D + B + A fully = 2+4+9 = 15 kg, profit 10+10+18 = 38.

root w=0, p=0 ub=38 ┌────────┴────────┐ +D │ │ −D w=2,p=10 w=0,p=0 ub=38 ub=32 ✂ prune (<38) ┌────┴────┐ +B │ │ −B w=6,p=20 w=2,p=10 ub=38 ub=36 ✂ prune (<38) ┌───┴───┐ +A │ │ −A w=15,p=38 w=6,p=20 ub=38 ub=32 ✂ prune (<38) ✅

Bound calculations:

  • −D branch: best is B + A = 13 kg, 28, plus 2 kg of C (ratio 2) = 4 → ub = 32.
  • −B branch (D taken): A = 9 kg, 18 → total 28 at 11 kg, plus 4/6 of C = 8 → ub = 36.
  • −A branch (D+B taken): 6 kg, 20; remaining 9 kg can take C (6 kg, 12) + part of nothing → ub = 32.
Optimal set = {A, B, D}  |  weight = 9 + 4 + 2 = 15 kg  |  profit = 18 + 10 + 10 = Rs. 38
Why BnB beats plain DP here: DP would build a 4×15 table; BnB reaches the answer after exploring only 4–5 nodes because the bound proves the other branches cannot beat 38.

4.7 Backtracking vs Branch and Bound

Q1Compare backtracking with branch and bound with respect to: search technique, exploration of the state-space tree, and kind of problems that can be solved.

8 marks★ 1×

Asked in: 2024 May Q4(a) [8]

PointBacktrackingBranch and Bound
Search techniqueDepth-first search of the state-space tree (implicitly via recursion/stack)Can be BFS (FIFO queue), DFS (LIFO stack) or best-first (LC priority queue)
Pruning criterionFeasibility — a partial solution violating constraints is rejectedOptimality bound — a subtree whose bound cannot beat the best known solution is rejected
ExplorationExplores one path fully before trying the next; backtracks on failureMaintains a list of live nodes; expands the most promising node (LC) or in queue/stack order
Type of problemDecision / constraint-satisfaction problems — n-queens, graph colouring, sum of subsets, Hamiltonian cycleOptimisation problems — 0/1 knapsack, TSP, assignment, job scheduling
MemoryO(n) — only the current pathO(2n) in the worst case — stores live nodes
When a solution is foundStops at the first feasible solutionMust continue until the bound proves optimality (unless a good incumbent is known)
SpeedFast when constraints are tightFast when bounds are tight; can be exponential otherwise
One-line answer: Backtracking asks "can this partial solution ever become valid?"; BnB asks "can this partial solution ever beat my best answer?"
